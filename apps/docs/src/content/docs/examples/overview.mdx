# Examples

An example is a recipe: one use case, written as files you can copy into an app and run. Each recipe page shows every file word for word, and a test runs the same files, so a snippet cannot drift from the code that works.

## What a recipe holds

- **The files.** Each is a module that imports only packages and its sibling files (`./engine`). It never imports the docs app, so it runs where you paste it.
- **The page.** It states the install line, then shows every file under its name. A recipe that renders UI has a live demo, and a forms recipe shows its React and Radiant files in tabs side by side.
- **The test.** It runs the files, including the failure paths, in the docs unit or browser project. A recipe that is not tested, or whose page differs from its files, fails the docs tests.

## Copy a recipe

1. Run the install line at the top of the recipe's page.
2. Create one folder and copy every file of the page into it under the name above the code. The files import each other as `./name`, so they keep working side by side.
3. Run the entry the page names, or render the component it exports.

### Forms

Each forms recipe has React and Radiant tabs and the same two install lines, one for each renderer:

- React: `pnpm add @schema-engine/forms @schema-engine/forms-react @schema-engine/layout react react-dom zod`
- Radiant: `pnpm add @schema-engine/forms @schema-engine/forms-radiant @schema-engine/layout @ecopages/radiant-ui @ecopages/radiant @ecopages/jsx @ecopages/signals zod`

| Recipe                                                         | Shows                                                                                               |
| -------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| [Contact form](/docs/examples/contact-form)                    | Rules with messages, a field shown only for a support request, a JSON submit and a 422 on its field |
| [Registration wizard](/docs/examples/registration-wizard)      | Two steps, Next that validates the step it leaves, and a taken email that sends the visitor back    |
| [Branching survey](/docs/examples/branching-survey)            | A step skipped unless the answer was poor, validated on Next and left out of what is sent           |
| [Submit, notify and reset](/docs/examples/submit-notify-reset) | Actions in the config: send, tell the visitor, clear the form, and report a failure                 |
