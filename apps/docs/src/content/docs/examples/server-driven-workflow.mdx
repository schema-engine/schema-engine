# A server-driven workflow

The server decides what happens when a customer changes the cart or submits it, and the client runs it. The workflow is JSON from an endpoint, so changing the checkout means changing the response, not shipping a client. The client does not trust the answer: it checks every entry against the actions it has, and runs only what passed. Each entry names the moment it answers through `triggers`, so one workflow holds the steps of `change` and of `submit`.

It uses the actions of [A checkout workflow](/docs/examples/checkout-workflow), which run the same way here: `actions.ts` below is that file, unchanged.

## Install

```bash
pnpm add @schema-engine/actions zod
```

## The endpoint

`GET` is the route handler of `/cart/workflow`. Any runtime that speaks `Request` and `Response` runs it. The workflow it answers with has one entry for `change` and the checkout for `submit`. `?next` returns the workflow of a later release, which this client cannot run: it names an action the client does not have and sends a quantity as text. That is how you see what the client does with a workflow it must refuse.

```ts title="endpoint.ts"
/**
 * What the server runs on each moment of the cart page.
 *
 * @remarks
 * `track-cart` answers `change` and everything else answers `submit`, through each entry's own `triggers`.
 */
const cartWorkflow = [
	{ id: 'track-cart', $type: 'trackPurchase', event: 'cart_changed', triggers: ['change'] },
	{ id: 'reserve', $type: 'reserveStock', sku: 'tee-black-m', quantity: 2, triggers: ['submit'] },
	[
		{ id: 'charge', $type: 'chargeCard', amount: 120, triggers: ['submit'] },
		{ id: 'warehouse', $type: 'notifyWarehouse', triggers: ['submit'] },
		{ id: 'track', $type: 'trackPurchase', event: 'purchase', triggers: ['submit'] },
	],
	{ id: 'receipt', $type: 'sendReceipt', to: 'ada@example.com', triggers: ['submit'] },
];

/**
 * The workflow of the next release, which a client that has not updated cannot run: it fraud-checks the order
 * with an action the client does not have, and sends a quantity as text.
 */
const nextWorkflow = [
	{ id: 'score', $type: 'scoreRisk', threshold: 0.8, triggers: ['submit'] },
	{ id: 'reserve', $type: 'reserveStock', sku: 'tee-black-m', quantity: '2', triggers: ['submit'] },
];

/** The route handler of `/cart/workflow`: it answers with the workflow as JSON. `?next` asks for the next release's. */
export function GET(request: Request): Response {
	return Response.json(new URL(request.url).searchParams.has('next') ? nextWorkflow : cartWorkflow);
}
```

## The client

`loadWorkflow` fetches the workflow and checks it with `parseActions`. The result is the parsed sequence, the only thing the dispatcher accepts, or the issues: the server could not be reached, it answered with an error status, its body is not JSON, or an entry fails its schema, with the path of the entry. `runWorkflow` dispatches the parsed sequence on one trigger.

```ts title="client.ts"
import {
	ActionDispatcher,
	parseActions,
	type ActionDispatchResult,
	type ParsedActionSequence,
} from '@schema-engine/actions';
import { registry, type CheckoutContext, type CheckoutTrigger } from './actions';

export type Loaded = { success: true; actions: ParsedActionSequence } | { success: false; issues: string[] };

const where = (path: ReadonlyArray<PropertyKey | { key: PropertyKey }> = []) =>
	path.map((segment) => (typeof segment === 'object' ? String(segment.key) : String(segment))).join('.');

/**
 * Fetches a workflow and checks it against the registered actions.
 *
 * @remarks
 * The result is the parsed sequence, which is the only thing the dispatcher accepts, or the issues that explain
 * why the workflow cannot run: the server could not be reached, it answered with an error status or with text
 * that is not JSON, or an entry fails its schema, with the entry's path.
 */
export async function loadWorkflow(url: string, request: typeof fetch = fetch): Promise<Loaded> {
	let response: Response;
	try {
		response = await request(url, { headers: { Accept: 'application/json' } });
	} catch {
		return { success: false, issues: ['The server could not be reached.'] };
	}
	if (!response.ok) return { success: false, issues: [`The server answered ${response.status}.`] };
	let input: unknown;
	try {
		input = await response.json();
	} catch {
		return { success: false, issues: ['The answer is not JSON.'] };
	}
	const parsed = parseActions(registry, input);
	if (parsed.success) return { success: true, actions: parsed.data };
	return { success: false, issues: parsed.issues.map((issue) => `${where(issue.path)}: ${issue.message}`) };
}

/** Runs the entries of a parsed workflow that answer `trigger`. */
export function runWorkflow(
	actions: ParsedActionSequence,
	trigger: CheckoutTrigger,
	context: CheckoutContext,
): Promise<ActionDispatchResult[]> {
	return new ActionDispatcher(registry).dispatch({ actions, trigger, context });
}
```

## The actions

The registrations of [A checkout workflow](/docs/examples/checkout-workflow), unchanged. The workflow refers to them by `$type`, and their schemas are what `parseActions` checks each entry against.

```ts title="actions.ts"
import * as z from 'zod/mini';
import { ActionRegistry, defineAction, type ActionConfigBase } from '@schema-engine/actions';

z.config(z.locales.en());

/** What the actions of a checkout read and change. A test, or another runtime, passes its own. */
export interface CheckoutContext {
	stock: Record<string, number>;
	cardLimit: number;
	/** What left the shop, in order: the warehouse, the analytics and the mailer. */
	sent: string[];
}

export type CheckoutTrigger = 'change' | 'submit';

/** Waits `ms`, and rejects as soon as `signal` aborts, so a cancelled action stops waiting. */
function delay(ms: number, signal: AbortSignal): Promise<void> {
	return new Promise((resolve, reject) => {
		const timer = setTimeout(resolve, ms);
		signal.addEventListener(
			'abort',
			() => {
				clearTimeout(timer);
				reject(new DOMException('The operation was aborted.', 'AbortError'));
			},
			{ once: true },
		);
	});
}

const define = defineAction<CheckoutContext, CheckoutTrigger>();

interface ReserveStockConfig extends ActionConfigBase<'reserveStock'> {
	sku: string;
	quantity: number;
}

const reserveStock = define<ReserveStockConfig>({
	$type: 'reserveStock',
	schema: z.object({
		sku: z.string(),
		quantity: z.number().check(z.int(), z.positive()),
	}),
	metadata: { name: 'Reserve stock', defaultTriggers: ['submit'] },
	execute: async ({ config, stock }) => {
		const left = stock[config.sku] ?? 0;
		if (left < config.quantity) {
			return { success: false, error: `Only ${left} of ${config.sku} left`, shouldContinue: false };
		}
		stock[config.sku] = left - config.quantity;
		return { success: true, message: `Reserved ${config.quantity} of ${config.sku}` };
	},
});

interface ChargeCardConfig extends ActionConfigBase<'chargeCard'> {
	amount: number;
}

const chargeCard = define<ChargeCardConfig>({
	$type: 'chargeCard',
	schema: z.object({ amount: z.number().check(z.positive()) }),
	metadata: { name: 'Charge the card', defaultTriggers: ['submit'] },
	execute: async ({ config, cardLimit, signal }) => {
		await delay(10, signal);
		if (config.amount > cardLimit) {
			return { success: false, error: 'The card was declined', shouldContinue: false };
		}
		return { success: true, message: `Charged ${config.amount}` };
	},
});

type NotifyWarehouseConfig = ActionConfigBase<'notifyWarehouse'>;

const notifyWarehouse = define<NotifyWarehouseConfig>({
	$type: 'notifyWarehouse',
	schema: z.object({}),
	metadata: { name: 'Notify the warehouse', defaultTriggers: ['submit'] },
	execute: async ({ sent, signal }) => {
		await delay(50, signal);
		sent.push('warehouse');
		return { success: true, message: 'Warehouse notified' };
	},
});

interface TrackPurchaseConfig extends ActionConfigBase<'trackPurchase'> {
	event: string;
}

const trackPurchase = define<TrackPurchaseConfig>({
	$type: 'trackPurchase',
	schema: z.object({ event: z.string() }),
	metadata: { name: 'Track the purchase', defaultTriggers: ['change', 'submit'] },
	execute: async ({ config, sent, signal }) => {
		await delay(50, signal);
		sent.push(`analytics:${config.event}`);
		return { success: true, message: `Tracked ${config.event}` };
	},
});

interface SendReceiptConfig extends ActionConfigBase<'sendReceipt'> {
	to: string;
}

const sendReceipt = define<SendReceiptConfig>({
	$type: 'sendReceipt',
	schema: z.object({ to: z.email() }),
	metadata: { name: 'Send the receipt', defaultTriggers: ['submit'] },
	execute: async ({ config, sent }) => {
		sent.push(`receipt:${config.to}`);
		return { success: true, message: `Receipt sent to ${config.to}` };
	},
});

export const registry = new ActionRegistry<CheckoutContext, CheckoutTrigger>([
	reserveStock,
	chargeCard,
	notifyWarehouse,
	trackPurchase,
	sendReceipt,
]);
```

## Run it

`main.ts` talks to the route handler without a network. It loads the workflow, runs the `change` trigger, then the `submit` trigger, then asks for the workflow of the next release.

```ts title="main.ts"
import type { CheckoutContext } from './actions';
import { loadWorkflow, runWorkflow } from './client';
import { GET } from './endpoint';

/** The client talking to the route handler, without a network. */
const server: typeof fetch = async (url, init) => GET(new Request(url, init));

const context: CheckoutContext = { stock: { 'tee-black-m': 10 }, cardLimit: 500, sent: [] };

const workflow = await loadWorkflow('https://shop.example/cart/workflow', server);
if (workflow.success) {
	for (const trigger of ['change', 'submit'] as const) {
		console.log(trigger);
		for (const { actionId, status, message } of await runWorkflow(workflow.actions, trigger, context)) {
			console.log(`  ${actionId}: ${status}, ${message}`);
		}
	}
}

const next = await loadWorkflow('https://shop.example/cart/workflow?next', server);
if (!next.success) {
	console.log('next release');
	for (const issue of next.issues) console.log(`  ${issue}`);
}
```

```text
change
  track-cart: succeeded, Tracked cart_changed
submit
  reserve: succeeded, Reserved 2 of tee-black-m
  charge: succeeded, Charged 120
  warehouse: succeeded, Warehouse notified
  track: succeeded, Tracked purchase
  receipt: succeeded, Receipt sent to ada@example.com
next release
  0.$type: Unknown action type 'scoreRisk'. Register it in the action registry.
  1.quantity: Invalid input: expected number, received string
```

- **`change` runs one entry.** `track-cart` is the only entry whose `triggers` include `change`. The reservation, the card and the receipt do not run while the customer is still editing the cart.
- **`submit` runs the checkout.** Its entries run in order, and the group runs together, as in the checkout recipe.
- **The next release is refused with paths.** `0.$type` is the first entry, whose action this client does not have, and `1.quantity` is the second entry's bad value. Nothing from that workflow runs, not even the entry that is valid.
