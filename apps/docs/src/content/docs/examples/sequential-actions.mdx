# Sequential Actions

Actions are registered capabilities that run in response to lifecycle
triggers. The form configuration determines the order in which action entries
are evaluated.

## Configuration pattern

```ts
const formConfig: FormConfig = {
	id: 'action-demo',
	steps: [{
		id: 'details',
		title: 'Details',
		elements: [
			{ $type: 'input', id: 'email', name: 'email', label: 'Email', inputType: 'email' },
		],
	}],
	actions: [
		{
			id: 'submit',
			$type: 'submit',
			endpoint: '/api/submit',
			method: 'POST',
			enabled: true,
		},
		{
			id: 'notify',
			$type: 'show_notification',
			message: 'Submitted successfully',
			variant: 'success',
			triggers: ['form_submit_success'],
		},
		{
			id: 'reset',
			$type: 'reset',
			triggers: ['form_submit_success'],
			resetToDefaults: true,
		},
	],
};
```

Register the corresponding action registrations with
`createFormEngine({ actions: [...] })`. Use `form_submit_start`,
`form_submit_success`, `form_submit_error`, and `form_submit_complete` for the
submit lifecycle; step navigation uses the `step_*` triggers.

See [Actions](/docs/forms/actions) for the built-in registrations and
[How Actions Work](/docs/actions/how-it-works) for execution semantics.
