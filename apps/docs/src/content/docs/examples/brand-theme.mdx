# A brand theme with a host tone axis

The built-in axes are `size` and `surface`. A host adds its own with `defineAxis`: here `tone`, whose values set the colour roles Radiant UI (`--primary`, `--on-primary`) and shadcn (`--primary`, `--primary-foreground`) components read. The theme file builds it; every engine receives it as `layout`. The form picks `tone: 'brand'` once, on the form, and the submit button, the checkbox and the border recolor. Try `forest` after you paste it; the demo is static.

The CSS reads `--primary` and keys one rule on the `data-se-tone` attribute the renderer writes on the form element.

## Install

For React:

```bash
pnpm add @schema-engine/forms @schema-engine/forms-react @schema-engine/layout react react-dom zod
```

For Radiant:

```bash
pnpm add @schema-engine/forms @schema-engine/forms-radiant @schema-engine/layout @ecopages/radiant-ui @ecopages/radiant @ecopages/jsx @ecopages/signals zod
```

Set your app up as the getting-started page of your renderer says ([Forms Radiant](/docs/forms-radiant/getting-started) or [Forms React](/docs/forms-react/getting-started)), then copy the files below into one folder.

## The config

The config is data: it names the layout it wants, and the CSS and the theme below decide how it looks.

```ts title="config.ts"
import type { FormConfig } from '@schema-engine/forms';

/** A form that picks the host `tone` axis. */
export const brandForm: FormConfig = {
	id: 'brand-form',
	title: 'Newsletter',
	className: 'brand-form',
	appearance: { tone: 'brand' },
	view: { $type: 'card' },
	steps: [
		{
			id: 'signup',
			title: 'Stay in touch',
			elements: [
				{
					$type: 'input',
					id: 'email',
					name: 'email',
					label: 'Email',
					inputType: 'email',
					rules: [{ $type: 'email', message: 'Enter a valid email' }],
				},
				{ $type: 'checkbox', id: 'weekly', name: 'weekly', label: 'Weekly digest' },
			],
		},
	],
};
```

## The theme

```ts title="theme.ts"
import { builtInAxes, createLayoutTheme, defineAxis } from '@schema-engine/layout';

/**
 * A host axis. Each value is a set of tokens: the colour roles Radiant UI (`--primary`, `--on-primary`) and a
 * shadcn theme (`--primary`, `--primary-foreground`) read.
 */
export const tone = defineAxis({
	$type: 'tone',
	metadata: { name: 'Tone', description: 'Accent colour of a form' },
	default: 'neutral',
	values: {
		neutral: {},
		brand: {
			'--primary': '#c2410c',
			'--on-primary': '#ffffff',
			'--primary-foreground': '#ffffff',
			'--primary-container': '#ffedd5',
			'--on-primary-container': '#7c2d12',
		},
		forest: {
			'--primary': '#15803d',
			'--on-primary': '#ffffff',
			'--primary-foreground': '#ffffff',
			'--primary-container': '#dcfce7',
			'--on-primary-container': '#14532d',
		},
	},
});

/** The compiled theme: the built-in `size` and `surface` axes plus `tone`. Pass it to every engine as `layout`. */
export const brandTheme = createLayoutTheme({ appearance: [...builtInAxes, tone] });
```

## The CSS

```css title="brand-tone.css"
/*
 * The tone axis sets colour roles (--primary and friends); this rule only reads one.
 * [data-se-tone] is written by the renderer on the form element, so it can style the form itself.
 */
.brand-form {
	padding-inline-start: 1rem;
	border-inline-start: 0.25rem solid var(--primary);
}

.brand-form[data-se-tone='forest'] {
	border-inline-start-style: dashed;
}
```

## What the tests check

The test checks that the theme adds `tone` to the built-in axes, that the form is valid in an engine built on the theme and fails with `Unknown axis 'tone'` in one that is not, and that the CSS styles the class of the config and keys a rule on `data-se-tone`.
