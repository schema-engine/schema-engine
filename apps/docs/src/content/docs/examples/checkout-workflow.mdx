# A checkout workflow

A checkout is a workflow: reserve the stock, charge the card, tell the warehouse, track the purchase, send a receipt. Some steps depend on the one before, and some can run together. Some can fail, and a failure has to stop the steps that are still running. This recipe writes the five steps as actions, expresses the order of a purchase as a JSON array, and runs it. A declined card cancels the other members of its group through their `signal`.

The workflow is data, so a server can build it, a CMS can store it and a log can replay it. [A server-driven workflow](/docs/examples/server-driven-workflow) fetches it from an endpoint.

## Install

```bash
pnpm add @schema-engine/actions zod
```

## The actions

Each action is a registration: a `$type`, a schema for its entry, metadata with the triggers it answers by default, and an async `execute`. The context is what the actions read and change: the stock, the card limit and a list of what left the shop. A test, or another runtime, passes its own.

`chargeCard`, `notifyWarehouse` and `trackPurchase` wait on `signal` through `delay`. That is what makes cancellation work: the dispatcher aborts the signal of the other members of a group when one of them fails with `shouldContinue: false`, and a handler that observes it stops. A handler that ignores its signal keeps the dispatch waiting.

```ts title="actions.ts"
import * as z from 'zod/mini';
import { ActionRegistry, defineAction, type ActionConfigBase } from '@schema-engine/actions';

z.config(z.locales.en());

/** What the actions of a checkout read and change. A test, or another runtime, passes its own. */
export interface CheckoutContext {
	stock: Record<string, number>;
	cardLimit: number;
	/** What left the shop, in order: the warehouse, the analytics and the mailer. */
	sent: string[];
}

export type CheckoutTrigger = 'change' | 'submit';

/** Waits `ms`, and rejects as soon as `signal` aborts, so a cancelled action stops waiting. */
function delay(ms: number, signal: AbortSignal): Promise<void> {
	return new Promise((resolve, reject) => {
		const timer = setTimeout(resolve, ms);
		signal.addEventListener(
			'abort',
			() => {
				clearTimeout(timer);
				reject(new DOMException('The operation was aborted.', 'AbortError'));
			},
			{ once: true },
		);
	});
}

const define = defineAction<CheckoutContext, CheckoutTrigger>();

const entry = {
	id: z.string(),
	enabled: z.optional(z.boolean()),
	triggers: z.optional(z.array(z.string())),
};

interface ReserveStockConfig extends ActionConfigBase<'reserveStock'> {
	sku: string;
	quantity: number;
}

const reserveStock = define<ReserveStockConfig>({
	$type: 'reserveStock',
	schema: z.object({
		...entry,
		$type: z.literal('reserveStock'),
		sku: z.string(),
		quantity: z.number().check(z.int(), z.positive()),
	}),
	metadata: { name: 'Reserve stock', defaultTriggers: ['submit'] },
	execute: async ({ config, stock }) => {
		const left = stock[config.sku] ?? 0;
		if (left < config.quantity) {
			return { success: false, error: `Only ${left} of ${config.sku} left`, shouldContinue: false };
		}
		stock[config.sku] = left - config.quantity;
		return { success: true, message: `Reserved ${config.quantity} of ${config.sku}` };
	},
});

interface ChargeCardConfig extends ActionConfigBase<'chargeCard'> {
	amount: number;
}

const chargeCard = define<ChargeCardConfig>({
	$type: 'chargeCard',
	schema: z.object({ ...entry, $type: z.literal('chargeCard'), amount: z.number().check(z.positive()) }),
	metadata: { name: 'Charge the card', defaultTriggers: ['submit'] },
	execute: async ({ config, cardLimit, signal }) => {
		await delay(10, signal);
		if (config.amount > cardLimit) {
			return { success: false, error: 'The card was declined', shouldContinue: false };
		}
		return { success: true, message: `Charged ${config.amount}` };
	},
});

type NotifyWarehouseConfig = ActionConfigBase<'notifyWarehouse'>;

const notifyWarehouse = define<NotifyWarehouseConfig>({
	$type: 'notifyWarehouse',
	schema: z.object({ ...entry, $type: z.literal('notifyWarehouse') }),
	metadata: { name: 'Notify the warehouse', defaultTriggers: ['submit'] },
	execute: async ({ sent, signal }) => {
		await delay(50, signal);
		sent.push('warehouse');
		return { success: true, message: 'Warehouse notified' };
	},
});

interface TrackPurchaseConfig extends ActionConfigBase<'trackPurchase'> {
	event: string;
}

const trackPurchase = define<TrackPurchaseConfig>({
	$type: 'trackPurchase',
	schema: z.object({ ...entry, $type: z.literal('trackPurchase'), event: z.string() }),
	metadata: { name: 'Track the purchase', defaultTriggers: ['change', 'submit'] },
	execute: async ({ config, sent, signal }) => {
		await delay(50, signal);
		sent.push(`analytics:${config.event}`);
		return { success: true, message: `Tracked ${config.event}` };
	},
});

interface SendReceiptConfig extends ActionConfigBase<'sendReceipt'> {
	to: string;
}

const sendReceipt = define<SendReceiptConfig>({
	$type: 'sendReceipt',
	schema: z.object({ ...entry, $type: z.literal('sendReceipt'), to: z.email() }),
	metadata: { name: 'Send the receipt', defaultTriggers: ['submit'] },
	execute: async ({ config, sent }) => {
		sent.push(`receipt:${config.to}`);
		return { success: true, message: `Receipt sent to ${config.to}` };
	},
});

export const registry = new ActionRegistry<CheckoutContext, CheckoutTrigger>([
	reserveStock,
	chargeCard,
	notifyWarehouse,
	trackPurchase,
	sendReceipt,
]);
```

## The workflow

`checkoutWorkflow` returns the text a server sends. The first entry reserves stock. The inner array is a group, so the card is charged, the warehouse told and the purchase tracked together. The receipt goes out last.

```ts title="workflow.ts"
export interface Order {
	sku: string;
	quantity: number;
	amount: number;
	email: string;
}

/**
 * The checkout of an order as JSON text, the way a server or a CMS would send it.
 *
 * @remarks
 * Stock is reserved first. Then the card is charged while the warehouse is told and the purchase is tracked: the
 * inner array is a group, which runs together. The receipt goes out last.
 */
export function checkoutWorkflow({ sku, quantity, amount, email }: Order): string {
	return JSON.stringify(
		[
			{ id: 'reserve', $type: 'reserveStock', sku, quantity },
			[
				{ id: 'charge', $type: 'chargeCard', amount },
				{ id: 'warehouse', $type: 'notifyWarehouse' },
				{ id: 'track', $type: 'trackPurchase', event: 'purchase' },
			],
			{ id: 'receipt', $type: 'sendReceipt', to: email },
		],
		null,
		'\t',
	);
}
```

```json
[

		"$type": "reserveStock",
		"sku": "tee-black-m",
		"quantity": 2
	},

		{

			"$type": "chargeCard",
			"amount": 120
		},
		{
			"id": "warehouse",
			"$type": "notifyWarehouse"
		},
		{

			"event": "purchase"
		}
	],
	{

	}
]
```

## Parse and dispatch

`runCheckout` parses the text, checks every entry against the schema of its action with `parseActions`, and dispatches the parsed sequence on `submit`. An entry that does not pass is an issue with its path and nothing runs, not even the entries that are valid. The dispatcher accepts only what `parseActions` returned, so an unchecked workflow cannot reach a handler.

```ts title="checkout.ts"
import { ActionDispatcher, parseActions, type ActionDispatchResult } from '@schema-engine/actions';
import { registry, type CheckoutContext } from './actions';

export type Checkout = { success: true; results: ActionDispatchResult[] } | { success: false; issues: string[] };

const where = (path: ReadonlyArray<PropertyKey | { key: PropertyKey }> = []) =>
	path.map((segment) => (typeof segment === 'object' ? String(segment.key) : String(segment))).join('.');

/**
 * Parses a workflow and runs it on `submit`.
 *
 * @remarks
 * `parseActions` checks every entry against the schema of its action, and the dispatcher accepts only what it
 * returned. A workflow with a bad entry runs nothing, not even its valid entries.
 */
export async function runCheckout(text: string, context: CheckoutContext): Promise<Checkout> {
	let input: unknown;
	try {
		input = JSON.parse(text);
	} catch {
		return { success: false, issues: ['The workflow is not valid JSON.'] };
	}
	const parsed = parseActions(registry, input);
	if (!parsed.success) {
		return { success: false, issues: parsed.issues.map((issue) => `${where(issue.path)}: ${issue.message}`) };
	}
	const results = await new ActionDispatcher(registry).dispatch({ actions: parsed.data, trigger: 'submit', context });
	return { success: true, results };
}
```

## Run it

`main.ts` runs the workflow twice: with a card that pays, and with a card that is declined because the amount is above the limit. It prints each `ActionDispatchResult`, one per line, and what left the shop.

```ts title="main.ts"
import { runCheckout } from './checkout';
import { checkoutWorkflow } from './workflow';

/** `cause` holds the error a handler threw, which has no JSON form. */
const withoutCause = (key: string, value: unknown) => (key === 'cause' ? undefined : value);

const order = { sku: 'tee-black-m', quantity: 2, amount: 120, email: 'ada@example.com' };

for (const [name, amount] of [
	['a card that pays', 120],
	['a card that is declined', 900],
] as const) {
	console.log(name);
	const context = { stock: { 'tee-black-m': 10 }, cardLimit: 500, sent: [] };
	const checkout = await runCheckout(checkoutWorkflow({ ...order, amount }), context);
	if (!checkout.success) console.log(checkout.issues.join('\n'));
	else {
		for (const result of checkout.results) console.log(JSON.stringify(result, withoutCause));
		console.log(`sent: ${context.sent.join(', ') || 'nothing'}`);
	}
}
```

```text
a card that pays
{"success":true,"message":"Reserved 2 of tee-black-m","actionId":"reserve","sequenceIndex":0,"status":"succeeded","cancellationRequested":false}
{"success":true,"message":"Charged 120","actionId":"charge","sequenceIndex":1,"groupIndex":0,"status":"succeeded","cancellationRequested":false}
{"success":true,"message":"Warehouse notified","actionId":"warehouse","sequenceIndex":1,"groupIndex":1,"status":"succeeded","cancellationRequested":false}
{"success":true,"message":"Tracked purchase","actionId":"track","sequenceIndex":1,"groupIndex":2,"status":"succeeded","cancellationRequested":false}
{"success":true,"message":"Receipt sent to ada@example.com","actionId":"receipt","sequenceIndex":2,"status":"succeeded","cancellationRequested":false}
sent: warehouse, analytics:purchase, receipt:ada@example.com
a card that is declined
{"success":true,"message":"Reserved 2 of tee-black-m","actionId":"reserve","sequenceIndex":0,"status":"succeeded","cancellationRequested":false}
{"success":false,"error":"The card was declined","shouldContinue":false,"actionId":"charge","sequenceIndex":1,"groupIndex":0,"status":"failed","cancellationRequested":false}
{"success":false,"error":"The operation was aborted.","shouldContinue":true,"actionId":"warehouse","sequenceIndex":1,"groupIndex":1,"status":"cancelled","cancellationRequested":true}
{"success":false,"error":"The operation was aborted.","shouldContinue":true,"actionId":"track","sequenceIndex":1,"groupIndex":2,"status":"cancelled","cancellationRequested":true}
sent: nothing
```

- **A card that pays.** The five entries succeed. The three members of the group carry the same `sequenceIndex` and their `groupIndex`, and results come back in configuration order, not in the order they finished.
- **A card that is declined.** `charge` fails with `shouldContinue: false`. The dispatcher aborts the signal of `warehouse` and `track`, which stop waiting and report `cancelled` with `cancellationRequested: true`. No later entry runs, so there is no receipt, and nothing was sent.
- **The reservation stays.** Cancelling stops what is still running. It does not undo what already happened: the stock of the declined order is still reserved. A real checkout adds an action that releases it, run on a trigger the failure path answers.

The package logs a warning to the console for each failed action. The recipe's test silences it.
