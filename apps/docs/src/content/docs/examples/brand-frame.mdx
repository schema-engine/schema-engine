# A custom recipe shell

A recipe is a registration: a spec (`$type`, kind, slot schemas) bound to the components of one renderer. This one is a single-step shell that frames the fields under a label read from `view.shell.label`. The same config renders in both renderers; only the binding differs, and the CSS is shared.

## Install

For React:

```bash
pnpm add @schema-engine/forms @schema-engine/forms-react @schema-engine/layout react react-dom zod
```

For Radiant:

```bash
pnpm add @schema-engine/forms @schema-engine/forms-radiant @schema-engine/layout @ecopages/radiant-ui @ecopages/radiant @ecopages/jsx @ecopages/signals zod
```

Set your app up as the getting-started page of your renderer says ([Forms Radiant](/docs/forms-radiant/getting-started) or [Forms React](/docs/forms-react/getting-started)), then copy the files below into one folder.

## The config

The config is data: it names the layout it wants, and the CSS and the theme below decide how it looks.

```ts title="config.ts"
import type { FormConfig } from '@schema-engine/forms';

/** A custom recipe shell: `view.$type` selects it and `view.shell` configures it. */
export const brandFrameForm: FormConfig = {
	id: 'brand-frame',
	view: { $type: 'brand-frame', shell: { label: 'Newsletter' } },
	steps: [
		{
			id: 'signup',
			title: 'Sign up',
			elements: [
				{ $type: 'input', id: 'email', name: 'email', label: 'Email', inputType: 'email' },
				{ $type: 'submit', id: 'submit', name: 'submit', label: 'Subscribe' },
			],
		},
	],
};
```

## The React binding

```tsx title="brand-frame.react.tsx"
import * as z from 'zod/mini';
import { defineRecipeSpec, getSlotConfig } from '@schema-engine/forms/recipes';
import { defineRecipe, type FormShellProps } from '@schema-engine/forms-react/primitives';

const BrandFrameShellSchema = z.strictObject({
	label: z._default(z.string(), 'Schema Engine'),
});

function BrandFrameShell({ slots, viewConfig }: FormShellProps) {
	const { label } = getSlotConfig(viewConfig, 'shell', BrandFrameShellSchema);
	return (
		<section className="brand-frame">
			<p className="brand-frame__label">{label}</p>
			<div className="brand-frame__body">{slots.content}</div>
		</section>
	);
}

export const BrandFrameRecipe = defineRecipe(
	defineRecipeSpec({
		$type: 'brand-frame',
		kind: 'single-step',
		slotSchemas: { shell: BrandFrameShellSchema },
		metadata: { name: 'Brand frame', description: 'A labelled frame around the fields' },
	}),
	{ shell: BrandFrameShell, slots: {} },
);
```

## Register it

Register it when you build the engine, then select it with `view.$type`.

In React:

```ts
import { createFormEngine } from '@schema-engine/forms';
import { elements } from './registrations';
import { BrandFrameRecipe } from './brand-frame.react';

export const engine = createFormEngine({ elements, recipes: [BrandFrameRecipe] });
```

In Radiant:

```ts
import { createRadiantFormEngine, schemaFormRegistrations } from '@schema-engine/forms-radiant';
import { BrandFrameRecipe } from './brand-frame.radiant';

export const engine = createRadiantFormEngine({ elements: schemaFormRegistrations, recipes: [BrandFrameRecipe] });
```

The shell receives `slots` (`header`, `progress`, `content`, `actions`, each present only when the recipe declares it) and `viewConfig`, and reads its own slot config with `getSlotConfig` and the schema it declared. A recipe that needs `size` or `surface` on a slot declares them with `appearanceAxes: { shell: ['size', 'surface'] }`. See [View recipes](/docs/forms-react/layouts#custom-recipes).

## What the tests check

The test checks that the form is valid once the engine registers the recipe and not before, that both bindings declare the same `$type`, and that the CSS styles the classes both shells write.
