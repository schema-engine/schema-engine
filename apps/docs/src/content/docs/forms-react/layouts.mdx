# View recipes

Recipes compose a **shell** with optional **header**, **progress**, and **actions** blocks. Select one with form-level `view.$type`. `@schema-engine/forms-react` is headless: the factory does not bind default recipes. `FormRenderer` still lives in the package.

| Layer                                          | Owns                                                                 |
| ---------------------------------------------- | -------------------------------------------------------------------- |
| `@schema-engine/forms/recipes`                 | Recipe protocol: `defineRecipeSpec`, `defineFormRecipe`, view model  |
| `@schema-engine/forms/recipes/built-in`        | Built-in specs, slot schemas and their config types                  |
| `schema-engine-form-recipes` (shadcn registry) | React shells, blocks, `schemaFormRecipeRegistrations`                |
| `@schema-engine/forms-radiant`                 | Radiant shells and blocks, auto-bound by `createRadiantFormEngine()` |

## Default registry recipes

Install the default source owned by your app:

```bash
pnpm dlx shadcn@latest add andeeplus/schema-engine/schema-engine-form-recipes
```

Then add its generated recipe barrel when you construct the engine:

```typescript
import { createFormEngine } from '@schema-engine/forms';
import { schemaFormRecipeRegistrations } from '@/components/schema-engine/forms/recipes/registrations';
import { schemaFormRegistrations } from '@/components/schema-engine/forms/registrations';

const engine = createFormEngine({ elements: schemaFormRegistrations, recipes: schemaFormRecipeRegistrations });
```

| `$type`               | Kind        | Description                        |
| --------------------- | ----------- | ---------------------------------- |
| `card`                | single-step | Centered card shell                |
| `split-screen`        | single-step | Side panel plus form               |
| `hero-background`     | single-step | Hero image or video                |
| `bare-controls`       | wizard      | Previous / next / submit only      |
| `card-wizard`         | wizard      | Card shell with progress           |
| `wizard`              | wizard      | Horizontal step indicators         |
| `sidebar-wizard`      | wizard      | Step indicators in a sidebar       |
| `hero-wizard`         | wizard      | Wizard over a hero background      |
| `split-screen-wizard` | wizard      | Wizard with a marketing side panel |

Slot config is optional. The recipe fixes block identity; `view` only passes options such as `shell`, `header`, `progress`, and `actions`.

## Single-step

Single-step recipes render a submit-only actions bar below the fields (aligned with the `actions.align` slot config), so the form is submittable without wizard navigation:

```typescript
const formConfig: FormConfig = {
	id: 'contact',
	view: {
		$type: 'card',
		shell: { appearance: { size: 'comfortable', surface: 'elevated' } },
	},
	steps: [{ id: 'step-1', title: 'Contact', elements: [/* ... */] }],
};
```

## Multi-step

Recipe slots, steps, fields and the form take a named `appearance`: the engine's layout theme declares the axes (`size`: `compact | default | comfortable`, `surface`: `flat | outlined | elevated`, plus any a host adds), each element or slot declares the axes it supports, and both renderers emit the picked value as `data-se-<axis>`. The card shell's width, padding and shadow are `size` and `surface` values. Structural slot config such as `header.showDescription` is unchanged.

Wizard recipes require **at least two steps**. Set `view.$type` to a wizard recipe such as `wizard` or `card-wizard`. The live demo renders exactly the configuration below:

<ReactFormDemoEmbed config={viewRecipesDemoConfig} />

<FormConfigCode config={viewRecipesDemoConfig} />

If you omit `view.$type` on a multi-step form, `validateForm` writes the engine's default wizard recipe as `view` (`bare-controls` unless `createFormEngine({ defaultWizardRecipe })` names another wizard recipe). If that recipe is not registered, the form keeps no `view`, `validateForm` warns, and fields render without chrome.

See [Registration Flow](/docs/examples/registration-flow) for a full wizard configuration.

## Custom recipes

```typescript
import * as z from 'zod/mini';
import { createFormEngine } from '@schema-engine/forms';
import { defineRecipeSpec } from '@schema-engine/forms/recipes';
import { defineRecipe, type FormShellProps } from '@schema-engine/forms-react/primitives';

function BrandShell({ slots }: FormShellProps) {
	return (
		<div>
			{slots.header}
			{slots.content}
			{slots.actions}
		</div>
	);
}

const BrandRecipe = defineRecipe(
	defineRecipeSpec({
		$type: 'brand',
		kind: 'single-step',
		slotSchemas: { shell: z.strictObject({ accent: z.optional(z.string()) }) },
		metadata: { name: 'Brand', description: 'Branded form shell' },
	}),
	{ shell: BrandShell, slots: {} },
);

const engine = createFormEngine({ recipes: [BrandRecipe] });
```
