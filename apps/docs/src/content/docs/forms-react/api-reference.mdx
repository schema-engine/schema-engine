# API Reference

## Composer

```ts
const engine = createReactFormComposer()
	.addElements(schemaFormRegistrations)
	.addRecipes(schemaFormRecipeRegistrations)
	.addRecipe(customRecipe)
	.build();
```

`createReactFormComposer()` is headless. Register installed default recipes or
your own recipes with `addRecipe` or `addRecipes`.

## Rendering

```tsx
<FormEngineProvider engine={engine} adapter={rhfAdapter}>
	<FormRenderer config={formConfig} onSubmit={handleSubmit} />
</FormEngineProvider>
```

`FormRenderer` validates the config once at the rendering boundary. The
selected recipe receives a `ViewContext` containing form metadata, active-step
state, navigation, and the current slot configuration.

## View hooks

```ts
useViewContext();
useActiveStep();
useFormNavigation();
useViewConfig<MySlotConfig>('header');
```

Shells and slot blocks are ordinary components. Bind them to a canonical spec
with `defineFormRecipe(spec, { shell, slots })` from `@schema-engine/forms/recipes`.
Built-in specs are exported from that subpath. The package root
`@schema-engine/forms` does not re-export them.

`createReactFormComposer()` does not bind default recipes. That is not the same
as omitting `FormRenderer`, which still lives in this package.

## Form hooks

The adapter exports `useFormContext`, `useFormField`, `useWatchField`,
`useWatchForm`, and `useFieldArray`. They are adapter-neutral and can be used
inside recipe blocks as well as ordinary form elements.
