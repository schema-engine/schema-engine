# API reference

Complete API documentation for `@schema-engine/registry`.

## createRegistry

```typescript
function createRegistry<const TRegistration extends BaseRegistration>(
	kind: string,
	registrations: readonly TRegistration[] & CheckChildPaths<TRegistration>,
	options?: CreateRegistryOptions,
): ReadOnlyRegistry<TRegistration>;

interface CreateRegistryOptions {
	readonly duplicates?: 'override' | 'error';
	readonly hint?: string;
}
```

Builds a frozen, read-only registry. `options.hint` is a sentence that ends the message of a `$type` the registry does not answer, such as where to register it; it is the registry's [`hint`](#readonlyregistry), so `safeParseNode`, `safeParseTree` and `parseActions` report it. By default (`duplicates: 'override'`) a later registration with the same `$type` replaces an earlier one without a warning and keeps its first position. With `duplicates: 'error'` a repeated `$type` throws a [`RegistryError`](#registryerror) (`'duplicate-type'`) `<kind> '<$type>' is registered twice.` before any schema is checked; use it for a catalog where a repeat is always a mistake. Throws `'invalid-schema'`, `<kind> '<$type>' schema must implement Standard Schema (~standard.validate).`, when a winning registration's schema is not a Standard Schema; an overridden registration is not checked. The registry stores a frozen shallow copy of each winner and leaves the objects you passed untouched.

It also checks each winner's [`childPaths`](#childpath) as data and in the types. At run time, each entry must be an object with only `keys` and `accepts`; `keys` a non-empty list of non-empty strings; `accepts`, when present, a non-empty list of non-empty names without repeats, or it throws `'invalid-child-paths'`. Two entries with the same keys are `'duplicate-child-path'`, and a path that runs through another is `'nested-child-path'`. Paths are compared key by key, so `['a.b']` and `['a', 'b']` are two paths. No check asks whether an `accepts` name is registered: a registry is not always a document's whole vocabulary, so [`safeParseTree`](#safeparsetree) checks the names against the lookup it gets, in the types. In the types, a registration whose schema output does not declare a key of a child path is an error that names it (`Property 'childPathNotInSchema' is missing`, with the `$type` and the keys), and so is an entry with a property other than `keys` and `accepts`, such as `accept` (`childPathUnknownProperty`, with the `$type` and the property). A key that a loose schema allows only through its index signature does not count as declared, and a schema whose output type cannot be read (`unknown`, a plain `StandardSchemaV1`) is not checked. The parent schema declares every child key, so the exported JSON Schema shows the whole node.

### ReadOnlyRegistry

| Member     | Returns                      | Description                              |
| ---------- | ---------------------------- | ---------------------------------------- |
| `kind`     | `string`                     | The label used in errors                 |
| `hint`     | `string \| undefined`        | The `hint` option, when one was given    |
| `size`     | `number`                     | Count of distinct `$type` keys           |
| `get(key)` | `TRegistration \| undefined` | Gets a registration by `$type`           |
| `has(key)` | `boolean`                    | Checks if the key exists                 |
| `all()`    | `readonly TRegistration[]`   | Frozen array in first-registration order |
| `keys()`   | `readonly string[]`          | Frozen array of keys in the same order   |

## bindRegistry

```typescript
function bindRegistry<TContract extends BaseRegistration, const TBindings>(
	contracts: ReadOnlyRegistry<TContract>,
	bindings: TBindings,
): BoundRegistry<TContract, TBindings>;

type RegistryBindings<TRegistry extends ReadOnlyRegistry, TBinding extends object = object> = {
	readonly [K in TRegistry['$type']]: TBinding;
};

type BoundRegistration<TContract extends BaseRegistration, TBindings> = TContract & TBindings[TContract['$type']];

interface BoundRegistry<TContract extends BaseRegistration, TBindings> extends ReadOnlyRegistry<
	BoundRegistration<TContract, TBindings>
> {
	get<K extends TContract['$type']>(key: K): Extract<BoundRegistration<TContract, TBindings>, { $type: K }>;
	get(key: string): BoundRegistration<TContract, TBindings> | undefined;
}
```

Builds a renderer's registry from a registry of contracts and one binding per `$type`; `TBindings` is constrained to exactly one binding for each `$type` of the contracts, none of which may set a key its contract defines. A contract is a registration without the renderer's part (the `$type`, schema and metadata, plus what a domain fixes); a binding is renderer-only data such as a `render` function or a tag name, and never carries schema or metadata. The result is built with `createRegistry`, so it is frozen, keeps the order of the contracts and checks every schema again. Each registration is a shallow merge, so `schema` and every other value of a contract is shared by identity between the renderers that bind it.

For contracts typed by literal `$type` (an inline list, which `createRegistry` types that way), a missing binding, a binding for a `$type` no contract has and a binding that sets a key of its contract are compile errors, `get(key)` with a known `$type` returns that registration without `undefined`, and `RegistryBindings<typeof contracts, ReactBinding>` with `satisfies` fixes the shape every binding of one renderer takes. For contracts typed only as `BaseRegistration` the same three mistakes throw a [`RegistryError`](#registryerror) when the registry is built:

| Mistake                              | Code                           | Message                                                              |
| ------------------------------------ | ------------------------------ | -------------------------------------------------------------------- |
| A contract has no binding            | `'missing-binding'`            | `<kind> '<$type>' has no binding.`                                   |
| A binding names no contract          | `'unknown-binding'`            | `<kind> binding '<key>' names no registration.`                      |
| A binding sets a key of its contract | `'binding-overrides-contract'` | `<kind> '<$type>' binding sets '<key>', which the contract defines.` |

## RegistryError

```typescript
type RegistryErrorCode =
	| 'invalid-schema'
	| 'invalid-child-paths'
	| 'duplicate-child-path'
	| 'nested-child-path'
	| 'duplicate-type'
	| 'unknown-binding'
	| 'missing-binding'
	| 'binding-overrides-contract'
	| 'schema-changes-type'
	| 'schema-breaks-child-path'
	| 'unreachable-child-path'
	| 'unknown-accepted-type'
	| 'definition-name-clash';

declare class RegistryError extends Error {
	readonly code: RegistryErrorCode;
	/** The registry's label, for example `Widget`. Absent when a parse failed through a lookup that is no registry. */
	readonly kind?: string;
	/** The `$type` of the registration at fault, or the key of a binding that names no registration. */
	readonly $type: string;
	/**
	 * The key a binding sets that its contract defines, for `'binding-overrides-contract'`, the `$type` a child path
	 * accepts that the lookup lacks, for `'unknown-accepted-type'`, and the name of the clashing definition, for
	 * `'definition-name-clash'`.
	 */
	readonly key?: string;
	/** The keys of the child path at fault, for the child path and tree codes. */
	readonly childPath?: readonly string[];
	/** The keys of the child path that `childPath` runs through, for `'nested-child-path'`. */
	readonly outerChildPath?: readonly string[];
}
```

What `createRegistry` and `bindRegistry` throw when the registrations or bindings break a rule, what `safeParseTree` throws when a schema contradicts its registration, and what `exportTreeSchema` throws when it cannot write a slot. Branch on `code`, not on `message`: the message is written for people and may be reworded, the codes stay. Every error carries `$type`, and `kind` too unless a parse went through a lookup that is no registry (a function over several registries has no label). A code that needs more to describe the mistake sets it as well, so a tool can point at the registration, or write the message again in another language, without parsing the message.

| Code                           | Thrown when                                                                                                                                                                                          | Details besides `kind` and `$type`  |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------- |
| `'invalid-schema'`             | A registration's `schema` has no `~standard.validate` function                                                                                                                                       |                                     |
| `'invalid-child-paths'`        | `childPaths` is not a list, or an entry is not `{ keys, accepts? }`: another property, empty or non-string `keys`, an empty `accepts`, or a name that is empty or listed twice                       |                                     |
| `'duplicate-child-path'`       | A registration declares the same child path (the same keys) twice                                                                                                                                    | `childPath`                         |
| `'nested-child-path'`          | A child path runs through another child path of the same registration                                                                                                                                | `childPath`, and `outerChildPath`   |
| `'duplicate-type'`             | A `$type` is registered twice with `duplicates: 'error'`                                                                                                                                             |                                     |
| `'unknown-binding'`            | `bindRegistry` got a binding whose key is no contract's `$type`                                                                                                                                      | None; `$type` is the binding key    |
| `'missing-binding'`            | `bindRegistry` got no binding for a contract                                                                                                                                                         |                                     |
| `'binding-overrides-contract'` | A binding sets a key its contract already defines                                                                                                                                                    | `key`, the key the binding sets     |
| `'schema-changes-type'`        | `safeParseTree` parsed a node whose schema returned an output that is no plain object with the node's own `$type`                                                                                    |                                     |
| `'schema-breaks-child-path'`   | `safeParseTree` parsed a node whose schema returned an output that does not keep a child path as the document has it                                                                                 | `childPath`                         |
| `'unreachable-child-path'`     | `exportTreeSchema` found no slot for a child path in a registration's JSON Schema: not declared, behind `allOf`, a `$ref` or a union, inside an `$id` of its own, or not an object, an array or open | `childPath`                         |
| `'unknown-accepted-type'`      | `exportTreeSchema` got a lookup that lacks a `$type` a child path accepts                                                                                                                            | `childPath`, and `key`, the `$type` |
| `'definition-name-clash'`      | A definition a schema brought along takes the name of a `$type` or of another definition                                                                                                             | `key`, the name                     |

A parse throws a `RegistryError` only when a schema contradicts its registration, never for a bad document. [`assertStandardSchema`](#assertstandardschema) on its own and the other errors raised while parsing, such as a Standard Schema that validates asynchronously, are plain `Error`s, and `parseYaml` throws [`YamlDocumentError`](#yaml-subpath).

## assertStandardSchema

```typescript
function assertStandardSchema(schema: unknown, context?: string): StandardSchemaV1;
```

Throws an `Error` with the message `<context> must implement Standard Schema (~standard.validate).` unless `schema` has a `~standard.validate` function. It is a plain `Error`, not a `RegistryError`: the caller is not building a registry, so there is no `kind` or `$type` to report.

## safeParseStandardSchema

```typescript
function safeParseStandardSchema<TInput, TOutput>(
	schema: StandardSchemaV1<TInput, TOutput>,
	value: TInput,
): { success: true; data: TOutput } | { success: false; error: { issues: StandardSchemaIssue[] } };
```

Runs a registration's schema without throwing. It supports only synchronous validation and throws for a schema that validates asynchronously.

```typescript
type StandardSchemaIssue = StandardSchemaV1.Issue;

type StandardSchemaSafeParseResult<T> =
	{ success: true; data: T } | { success: false; error: { issues: StandardSchemaIssue[] } };
```

`StandardSchemaIssue` is the issue of the Standard Schema spec (`message` and an optional `path`), and `StandardSchemaSafeParseResult<T>` is what `safeParseStandardSchema` returns.

## standardSchema

```typescript
function standardSchema<TOutput>(
	validate: (value: unknown) => StandardSchemaV1.Result<TOutput>,
): StandardSchemaV1<unknown, TOutput>;
```

Builds a Standard Schema from a function, for a registration whose check is not a schema library's. `validate` returns `{ value }` for an input that passes and `{ issues }` for one that does not, and it must be synchronous. The schema reports `schema-engine` as its vendor.

## safeParseNode

```typescript
function safeParseNode<TRegistration extends Pick<BaseRegistration, 'schema'>>(
	registry: NodeLookup<TRegistration>,
	node: unknown,
	options?: ParseOptions,
): SafeParseNodeResult<TRegistration>;

interface ParseOptions<TType extends string = string> {
	readonly path?: ReadonlyArray<PropertyKey | { key: PropertyKey }>;
	readonly accepts?: readonly TType[];
}
```

Checks one node against the registration its `$type` names, without throwing. `registry` is anything whose `get(key)` returns a registration with a `schema`, so a registry of either kind and a lookup over several registries all fit. `options.path` is where the node sits in its document, and every issue's `path` starts with it. `options.accepts` is the `$type`s the node may have, as a position of a document accepts them; an empty list throws an `Error`, a caller bug like an asynchronous schema.

```typescript
interface NodeLookup<TRegistration extends Pick<BaseRegistration, 'schema'> = BaseRegistration> {
	get(key: string): TRegistration | undefined;
	kind?: string;
	hint?: string;
}
```

`NodeLookup` is the one shape for finding a registration, and `ExportLookup` (see [`exportTreeSchema`](#exporttreeschema)) the one for listing them. A function that finds a registration takes a `NodeLookup`; one that lists them takes an `ExportLookup`; a registry of either kind is both. A package that adds a domain, such as actions, declares no lookup interface of its own: its functions take a `NodeLookup`. `kind` is the label used in errors, and `hint` is a sentence that follows the message of a `$type` `get` does not answer, such as where to register it.

```typescript
type SafeParseNodeResult<TRegistration extends Pick<BaseRegistration, 'schema'> = BaseRegistration> =
	| (TRegistration extends unknown
			? {
					success: true;
					$type: TRegistration extends { $type: infer TType extends string } ? TType : string;
					registration: TRegistration;
					data: StandardSchemaV1.InferOutput<TRegistration['schema']>;
				}
			: never)
	| { success: false; issues: RegistryIssue[] };
```

The success branch has one member per registration of the registry, so a registry typed by its registrations gives `data` the schema output of the registration that `$type` names, with no cast. A registry typed as `ReadOnlyRegistry<BaseRegistration>` has no concrete schema to read, so its `data` is `unknown`. Narrow on `$type` of the result: TypeScript narrows a union only by a property of the union itself, so `result.registration.$type` alone does not narrow `data`.

```ts
import * as z from 'zod/mini';
import { createRegistry, safeParseNode } from '@schema-engine/registry';

const widgets = createRegistry('Widget', [
	{ $type: 'card', schema: z.object({ title: z.string() }), metadata: { name: 'Card' } },
	{
		$type: 'badge',
		schema: z.object({ label: z.string(), tone: z._default(z.string(), 'info') }),
		metadata: { name: 'Badge' },
	},
]);

export function describeNode(node: unknown): string {
	const parsed = safeParseNode(widgets, node);
	if (!parsed.success) return 'invalid';
	return parsed.$type === 'card' ? parsed.data.title : `${parsed.data.label} (${parsed.data.tone})`;
}
```

`createRegistry` keeps the literal `$type` of each inline registration, so the example needs no `as const`.

| Node                               | Result                                                                                                                                                          |
| ---------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Valid                              | `{ success: true, $type, registration, data }`, where `data` is what the schema returned, defaults applied                                                      |
| Not an object                      | `registry/not-an-object` at `path`: `Expected an object with a string $type.`                                                                                   |
| An object without a string `$type` | `registry/missing-type` at `[...path, '$type']`: `Expected a string $type.`                                                                                     |
| A `$type` outside `accepts`        | `registry/not-accepted` at `[...path, '$type']`: `$type 'x' is not accepted here. Expected 'a'.` or `Expected one of 'a', 'b'.`, with `expected` and `received` |
| A `$type` no registration answers  | `registry/unregistered-type` at `[...path, '$type']`: `No registration for $type '<type>'.` and the lookup's `hint`, with `received`                            |
| The schema refuses it              | The schema's issues, each with `path` in front of the path the schema reported, and nothing else added                                                          |

`accepts` is checked before the lookup, so a `$type` outside the list is not accepted whether or not it is registered, and the issue names what would fit; an accepted `$type` nothing registers stays `registry/unregistered-type`.

`hint` is optional: a sentence that follows the message of a `$type` `get` does not answer, such as where to register it. With `hint: 'Register it with defineBadge.'`, an unregistered `chip` is `No registration for $type 'chip'. Register it with defineBadge.`. `kind` is the registry's label, the one used in errors, which a registry of either kind has; `safeParseTree` names it in the `RegistryError` it throws.

`unregisteredTypeMessage(type, hint?)` writes that message, for a caller that has to throw for the same case instead of returning an issue.

An issue points at the value that is wrong, the way a schema reports a missing required key at the key, so an editor can mark it and [`parseYaml`](/docs/schema-engine/serialized-documents#yaml) finds its line. [`parseActions`](/docs/actions/api-reference#parseactions) checks each entry of a workflow with it, so an entry reports these issues at the same places.

```typescript
interface RegistryIssue extends StandardSchemaIssue {
	readonly code?: string;
	readonly expected?: readonly string[];
	readonly received?: string;
}
```

The issues the engine creates carry a namespaced `code`, so it cannot be mistaken for a schema library's own `code`, which an issue from a schema keeps untouched: `registry/not-an-object`, `registry/missing-type`, `registry/unregistered-type` (`received`), `registry/not-accepted` (`expected` the `accepts` list, `received` the `$type`), `registry/not-a-node` and `registry/contains-itself`. The messages may be reworded; the codes stay. Some schema libraries have an `expected` or `received` of their own, so check `code` before reading them.

It looks at one node; [`safeParseTree`](#safeparsetree) walks a whole tree with it. It throws, like `safeParseStandardSchema`, for a schema that validates asynchronously. The result has the `issues` shape of `parseActions`, so `(value) => safeParseNode(registry, value)` is a validator for [`parseYaml`](/docs/schema-engine/serialized-documents#yaml). A schema used with `safeParseNode` alone may omit `$type` from its output; the tree contract below is for `safeParseTree`.

## safeParseTree

```typescript
function safeParseTree<
	TAll extends TreeRegistration,
	const TOptions extends ParseOptions<TAll['$type']> = ParseOptions<TAll['$type']>,
>(
	registry: NodeLookup<TAll> & CheckLookup<TAll>,
	root: unknown,
	options?: TOptions,
): SafeParseTreeResult<TAll, RootOf<TAll, TOptions>>;

type TreeRegistration = Pick<BaseRegistration, '$type' | 'schema' | 'childPaths'>;

type SafeParseTreeResult<TAll, TRoot = TAll> =
	| { success: true; tree: ParsedNode<TAll, TRoot> }
	| { success: false; issues: RegistryIssue[]; tree?: PartialNode<TAll, TRoot> };

type ParsedNode<TAll, TRegistration = TAll> = {
	$type: TRegistration['$type'];
	registration: TRegistration;
	data: NodeData<TAll, TRegistration>;
	path: ReadonlyArray<PropertyKey | { key: PropertyKey }>;
	children: readonly { keys: readonly string[]; nodes: readonly ParsedNode<TAll>[] }[];
};

type PartialNode<TAll, TRegistration = TAll> = {
	$type: TRegistration['$type'];
	registration: TRegistration;
	output: StandardSchemaV1.InferOutput<TRegistration['schema']>;
	path: ReadonlyArray<PropertyKey | { key: PropertyKey }>;
	children: readonly { keys: readonly string[]; nodes: readonly PartialNode<TAll>[] }[];
};
```

Checks a whole document without throwing for a bad document. Every node goes through `safeParseNode` with its full `path` and the `accepts` of its position, so an issue is the one `safeParseNode` reports, at the position the document has it, and `formatIssuePath(issue.path, root)` writes it as text. `options.accepts` restricts the root and `options.path` is where the root sits in a larger document. A registration says where its children are with [`childPaths`](#childpath), each read from the node as authored.

The result is `{ success: true, tree }`, or `{ success: false, issues, tree? }` with every issue and the nodes that parsed. There is no top-level `data`: `tree.data` is the whole parsed document, and the `data` of every `ParsedNode` is that node's composed data, the same object its parent's data holds at that position. `tree.data` is each node's schema output, defaults and transforms applied, with the children's data at each child path, in document order.

On failure, `tree` is a `PartialNode`, present exactly when the root's own schema passed (absent when the root failed, was not accepted or has no registration). It holds every node whose own schema passed and whose parent was kept: a node that failed is left out and its children are not walked, and a child its slot does not accept and the repeat of a cycle are left out too. A partial node has `output`, its own schema output (what `safeParseNode` returned), and no `data`: the parsed document exists only when there are no issues, so reading `tree.data` on the failure branch is a type error. A slot of `output` holds what the document had there, so read the children from `children`, never from `output`. `children` has one `{ keys, nodes }` entry per declared child path, in declaration order, with the kept children in document order, each with its own `path`; a failed child is missing, so the issues say where it was. A child is any `PartialNode<TAll>`, narrowed by its `$type`, not by `accepts`. A `RegistryError` still throws, partial walk or not. See [Check what parsed when the document has issues](/docs/registry/resolve-a-document#check-what-parsed-when-the-document-has-issues).

`children` has one entry per child path the registration declares, in declaration order, `nodes` empty when the node holds none there. Find an entry by its `keys` (`children.find(({ keys }) => keys.join('.') === 'engine.controls')?.nodes`), never by index; code that names a position reads `data`, which is typed per path. For a registry typed by its registrations, the root narrows when `accepts` is a literal list (not when the options type only may have `accepts`, and not for `{ path }` alone), `data` types each child path by what the path accepts (a list stays a list, optional stays optional, an `unknown` slot becomes `child | child[] | undefined`, and `null` is removed from a nullable slot), and the `nodes` of each `children` entry are typed by its `accepts`. A registry typed as `BaseRegistration` keeps `data: unknown`. An `accepts` name the lookup lacks is a type error (`acceptsUnknownType: 'knob'`), and so is a registration whose schema output declares no `$type` (`schemaOutputWithoutType: 'card'`). Two registries in one lookup share one `$type` namespace: the lookup decides which wins when both answer (`a.get(type) ?? b.get(type)` prefers `a`).

| Value at the child path                                | Result                                                                                           |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| key absent, or an intermediate absent or not an object | no children; `data` keeps the schema output there (a default, say)                               |
| `undefined`                                            | no children, as absent                                                                           |
| `null`                                                 | `registry/not-a-node` at the path: `Expected a node or a list of nodes.`                         |
| another primitive                                      | the same issue                                                                                   |
| an object                                              | one child, walked                                                                                |
| an array                                               | each item walked at `[...path, index]`; an item that is not an object is `safeParseNode`'s issue |
| an empty array                                         | no children; `data` holds `[]`                                                                   |
| a key only on the prototype (`constructor`)            | absent                                                                                           |
| an own key `__proto__`                                 | read and written as an own property                                                              |

| Case                        | Result                                                                                |
| --------------------------- | ------------------------------------------------------------------------------------- |
| Every node is valid         | `{ success: true, tree }`                                                             |
| A node's own schema fails   | Its issues; the node is not walked further, but its siblings still are                |
| A node that contains itself | `registry/contains-itself` at the node reached again: `A node cannot contain itself.` |
| Any issue anywhere          | `{ success: false, issues }` with all of them, and no tree                            |

The same object under two parents (not a cycle) is parsed twice, and a registration may accept itself (a section in a section). Each child is parsed once, from the authored value, and its data is written into a copy of the node's schema output, never into the authored document: the output shares references with the input (a loose object returns the authored array), so the root and each object on a path are copied once, and two paths with a shared prefix share one copy.

### The structural contract of a tree schema

The parent schema owns, at a child path, whether the value may be missing, list or single, and list bounds. It does not own the children, whose data replaces whatever the schema returned there, so keep slots opaque (`z.array(z.unknown())`, `z.unknown()`) and restrict them with `accepts`. For each node it parses, `safeParseTree` holds the schema to this and throws a `RegistryError` when it breaks it, because that is a bug of the registration, not an issue of the document:

- `'schema-changes-type'`: the output is not a plain object whose own `$type` equals the node's.
- `'schema-breaks-child-path'` with `childPath`: where the document fills a child path, the output lacks the keys down to it as plain objects, or its cardinality differs (an array of the same length for an array, an object for an object). A key stripped, renamed or turned into something else is caught here. Where the document leaves a child path absent, the output may be absent, `undefined` or `[]`; a default that holds nodes breaks the path too, because children come only from the document, so a default can never expand forever.

A parent transform at a filled slot (a reorder, a preprocess) is discarded, not detected. It throws, as `safeParseNode` does, for a schema that validates asynchronously.

## exportTreeSchema

```typescript
function exportTreeSchema(
	lookup: ExportLookup | readonly ExportLookup[],
	options?: ExportTreeSchemaOptions,
): JSONSchemaObject;

interface ExportLookup {
	all(): readonly TreeRegistration[];
}

interface ExportTreeSchemaOptions {
	/** The `$type`s the root may have. Absent: every `$type` of the lookup. */
	readonly accepts?: readonly string[];
	/** Which shape of each schema to write. Default `'input'`, the authored shape. */
	readonly io?: 'input' | 'output';
	/** The JSON Schema dialect. Default `'draft-2020-12'`. Any other value throws before a schema is read. */
	readonly target?: 'draft-2020-12' | 'draft-07';
	/** Writes one registration's schema as JSON Schema, or returns `undefined`. Default: its `~standard.jsonSchema`. */
	readonly resolve?: (
		schema: StandardSchemaV1,
		context: { io: 'input' | 'output'; target: 'draft-2020-12' | 'draft-07' },
	) => JSONSchemaObject | undefined;
}

type JSONSchemaObject = Record<string, unknown>;
type JSONSchemaTarget = 'draft-2020-12' | 'draft-07' | 'draft-04' | 'openapi-3.0';
```

`JSONSchemaTarget` is the closed set of Standard JSON Schema names that the registry's APIs take. `exportTreeSchema` writes two of them, `'draft-2020-12'` and `'draft-07'`, and throws an `Error` for any other `target` (a misspelling, `'openapi-3.0'`, Zod's older spelling of draft-07) before it reads a schema, instead of writing a document without `$schema`.

Writes the JSON Schema of a whole tree of registrations, composed at the JSON Schema level, independent of the validator. `lookup` is a registry of either kind or a list of registries; when two list a `$type`, the first wins. The result is `{ $schema, $defs, anyOf }`: one definition per `$type` under `$defs` (`definitions` for a `'draft-07'` target), and the root as the union of `accepts`, or of every `$type`. A `$ref` writes the `$type` as a JSON Pointer token: `~` as `~0`, `/` as `~1`, and the rest percent-encoded.

Each registration's schema is written by `resolve`, by default `readStandardJSONSchema(schema)?.[io]({ target })`, so a schema library that implements Standard JSON Schema needs nothing here, and the registry depends on no validator. A schema `resolve` returns `undefined` for (Zod Mini, by default) is the open fallback: an object with its `$type` and the `properties` chain of each child path, ending in the open form of a slot.

Then each child path is replaced, and only its slot, so `required`, `minItems`, `maxItems` and the sibling keys stay as the schema wrote them:

| Slot in the registration's JSON Schema               | Becomes                                                                      |
| ---------------------------------------------------- | ---------------------------------------------------------------------------- |
| an array (`type: 'array'`, `items` or `prefixItems`) | the same array with `items: U`, and `U` at each tuple position               |
| an object                                            | `U`                                                                          |
| open (`{}`)                                          | `{ anyOf: [U, { type: 'array', items: U }] }`, a child or a list of children |

`U` is `{ anyOf: [{ $ref: '#/$defs/<$type>' }, ...] }` of the path's `accepts`, or of every `$type` without one; a slot that accepts its own `$type` refers to its own definition. A slot behind `allOf`, a `$ref` or a union, one inside a schema with an `$id` of its own (where a `$ref` resolves against that `$id`, not the document), or one the schema does not declare, throws a `RegistryError` with code `'unreachable-child-path'`, naming the `$type` and `childPath`.

A schema that was written as a document of its own is moved into the document. Its `$defs` are lifted to the top as `<$type>.<name>`, every local pointer (`#`, `#/$defs/name`) follows, and anchors are renamed under their owner (`ui/button` writes `a__ui__2f__button`, since an anchor name takes only letters, digits, `-`, `.` and `_`). A `$type` named like a lifted definition throws `'definition-name-clash'`, and an `accepts` name the lookup lacks throws `'unknown-accepted-type'`: pass every registry of the vocabulary. An empty lookup, an empty `accepts` and a root `accepts` the lookup lacks throw a plain `Error`.

A `resolve` that converts one library itself and keeps the default for the rest reads the default with [`readStandardJSONSchema`](#json-schema-subpath).

## formatIssuePath

```typescript
function formatIssuePath(path: StandardSchemaIssue['path'], source?: unknown): string;
```

Writes the `path` of an issue as text for a log or a message: keys are joined by dots, indexes are in brackets, and a missing or empty path is the empty string. A segment is a key or a Standard Schema `{ key }` object, so the `path` of any issue passes as it is.

| `path`                                    | Result                          |
| ----------------------------------------- | ------------------------------- |
| `['children', 1, 'children', 0, 'label']` | `children[1].children[0].label` |
| `[1, 0, 'amount']`                        | `[1][0].amount`                 |
| `[{ key: 'steps' }, { key: 0 }, 'id']`    | `steps[0].id`                   |
| `undefined`                               | `''`                            |

With the document as `source`, an array item that has a string `id` is followed by the id in parentheses, `steps[0] (main).elements[1] (email).id`, so a log of a large document names the node it means.

## createMutableRegistry

```typescript
function createMutableRegistry<TRegistration extends BaseRegistration = BaseRegistration>(
	kind: string,
	options?: CreateRegistryOptions,
): MutableRegistry<TRegistration>;

interface MutableRegistry<
	TRegistration extends BaseRegistration = BaseRegistration,
> extends ReadOnlyRegistry<TRegistration> {
	register<const T extends TRegistration>(registration: T & CheckChildPaths<T>): void;
	clear(): void;
}
```

Builds an empty registry for registrations that arrive at runtime, such as a plugin system's. Prefer `createRegistry` when the list is known. The type parameter is explicit, since there is no list to infer from. A `MutableRegistry` is a [`ReadOnlyRegistry`](#readonlyregistry) plus `register` and `clear`, so `safeParseNode`, `safeParseTree`, `exportTreeSchema` and any code that reads a registry take either kind.

| Member                                      | Returns                  | Description                                                                                                                 |
| ------------------------------------------- | ------------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| `register(registration)`                    | `void`                   | Checks the registration as `createRegistry` does, then stores a frozen shallow copy keyed by its `$type`                    |
| `clear()`                                   | `void`                   | Removes every registration                                                                                                  |
| `kind`, `size`, `get`, `has`, `all`, `keys` | as in `ReadOnlyRegistry` | `all()` and `keys()` return the same frozen array until the next `register` or `clear`, so you can compare them by identity |

`register` throws a [`RegistryError`](#registryerror) with the codes and messages of `createRegistry`: `'invalid-schema'` for a schema that is not a Standard Schema, and `'invalid-child-paths'`, `'duplicate-child-path'` or `'nested-child-path'` for malformed [`childPaths`](#childpath). The registry is unchanged when `register` throws. In the types, `register` reports a child path the schema does not declare as `childPathNotInSchema` and an unknown child path property as `childPathUnknownProperty`, as `createRegistry` does. An `accepts` name may be a `$type` that is not registered yet: the vocabulary is open, and `safeParseTree` reports a node it cannot find as an issue.

`createMutableRegistry` takes the same `options`: `hint` is the registry's `hint`. A repeated `$type` replaces the earlier registration without a warning and keeps its first position. With `{ duplicates: 'error' }` it throws `'duplicate-type'`, and the first registration stays. The registry logs nothing: call `has` before `register` to warn about an override. The key is always `$type`.

## Types

### BaseRegistration

```typescript
import type { StandardSchemaV1 } from '@standard-schema/spec';

interface BaseRegistration<_TConfig = unknown, TMeta extends RegistrationMetadata = ComponentMetadata> {
	$type: string;
	schema: StandardSchemaV1;
	metadata: TMeta;

}
```

Zod Mini, Zod, Valibot, and Effect Schema values implement Standard Schema and remain valid `schema` values.

### ChildPath

```typescript
interface ChildPath {
	readonly keys: readonly string[];
	readonly accepts?: readonly string[];
}
```

`childPaths` says where a node of this `$type` holds child nodes. A child path is always an object, so a registration stays plain data. `keys` is the list of keys from the node to the slot (`['engine', 'controls']` is `node.engine.controls`), relative and without indexes: it is not called `path`, which names absolute document paths with indexes. The value there is one node or an array of nodes. `accepts` is a non-empty, closed list of `$type`s allowed at the slot, so adding a leaf to `[...defaults, custom]` means overriding each container that should take it; without `accepts`, the slot puts no limit on the `$type`, so any `$type` the lookup answers is accepted. No role, tag or category decides what a slot takes, and `metadata` decides nothing. `accepts` is the only way to restrict a slot: parent schemas keep slots opaque, and the docs say not to restrict `$type` in the parent schema.

## JSON Schema subpath

`@schema-engine/registry/json-schema` holds the pieces for code that writes JSON Schema itself: a `resolve` for `exportTreeSchema` that falls back to Standard JSON Schema, or a domain package with an export of its own, as the forms export is. A registry user needs only `exportTreeSchema`.

```typescript
function readStandardJSONSchema(schema: unknown): StandardJSONSchemaV1.Converter | undefined;

function createJSONSchemaEmbedder(target: JSONSchemaTarget, placement: JSONSchemaPlacement): JSONSchemaEmbedder;

function assertJSONSchemaTarget(target: string): asserts target is JSONSchemaTarget;

function replaceChildSlot(
	definition: JSONSchemaObject,
	path: { readonly $type: string; readonly keys: readonly string[] },
	union: JSONSchemaObject,
): void;

type JSONSchemaPlacement =
	{ readonly kind: 'document' } | { readonly kind: 'collection'; readonly uri: (id: string) => string };

interface JSONSchemaEmbedder {
	/** The schema to write in place of `own`, which is not changed. */
	embed(own: JSONSchemaObject): JSONSchemaObject;
	/** Adds the definitions `embed` hoisted to the finished document or collection, in place. */
	finish(written: JSONSchemaObject): JSONSchemaObject;
}
```

`createJSONSchemaEmbedder` embeds schemas that were written as documents of their own into one JSON Schema being written: it drops `$schema`, moves a schema whose `$ref`s point into itself to where they resolve (the document's definitions under `embedded-<n>`, or a collection entry of its own at `uri(id)`) and renames each anchor under that key. A schema with an `$id` of its own resolves itself and is kept as it is. It takes any of the four `JSONSchemaTarget`s and throws an `Error` for any other string.

`assertJSONSchemaTarget` throws the same `Error` for a string that is not a `JSONSchemaTarget`, and narrows it to one otherwise. Use it for the `target` of a Standard JSON Schema converter's options, which the Standard type leaves open.

`replaceChildSlot` is the step `exportTreeSchema` takes for each child path, for code that writes a JSON Schema of its own. It replaces, in place, the slot that `path.keys` names in the JSON Schema of a registration (`definition`), and only the slot: an array gets `items: union` (and `union` at each tuple position), an object becomes `union`, and an open slot becomes `{ anyOf: [union, { type: 'array', items: union }] }`. `required`, list bounds, annotations and sibling keys stay. Each place takes its own copy of `union`, which you write with the `$ref`s of your document. A slot it cannot reach (behind `allOf`, a `$ref` or a union, inside a schema with an `$id` of its own, or not declared) throws a `RegistryError` with code `'unreachable-child-path'`. Checking that the names in `union` are registered is the caller's, as it is in `exportTreeSchema`.

### Fall back to Standard JSON Schema

`readStandardJSONSchema` returns the `~standard.jsonSchema` converter of a schema, or `undefined` when it has none, which is what the default `resolve` of `exportTreeSchema` reads. A `resolve` that converts Zod Mini itself and keeps the default for every other library:

```ts title="document-schema.ts"
import * as z from 'zod/mini';
import { createRegistry, exportTreeSchema } from '@schema-engine/registry';
import { readStandardJSONSchema } from '@schema-engine/registry/json-schema';

const blocks = createRegistry('Block', [
	{
		$type: 'stack',
		schema: z.object({ $type: z.literal('stack'), children: z.array(z.unknown()) }),
		metadata: { name: 'Stack' },
		childPaths: [{ keys: ['children'] }],
	},
]);

export const documentSchema = exportTreeSchema(blocks, {
	resolve: (schema, { io, target }) =>
		schema instanceof z.core.$ZodType
			? z.toJSONSchema(schema, { io, target })
			: readStandardJSONSchema(schema)?.[io]({ target }),
});
```

## YAML subpath

`@schema-engine/registry/yaml` parses YAML documents and validates them with any validator that reports
Standard Schema issues, then points each issue at a line and column. It needs the optional peer dependency
`yaml`; the root entry never imports it.

```typescript
parseYaml<T>(text: string, validate: YamlValidate<T>, options?: { filename?: string }): T; // throws YamlDocumentError
safeParseYaml<T>(
	text: string,
	validate: YamlValidate<T>,
	options?: { filename?: string },
): { success: true; data: T } | { success: false; issues: YamlIssue[] };
stringifyYaml(value: unknown, options?: { schemaUrl?: string }): string;

type YamlIssue = { message: string; path: PropertyKey[]; line: number; column: number; filename?: string };

type YamlValidate<T> = (
	value: unknown,
) =>
	| { success: true; data: T }
	| {
			success: false;
			issues: ReadonlyArray<{ message: string; path?: ReadonlyArray<PropertyKey | { key: PropertyKey }> }>;
	  };

class YamlDocumentError extends Error {
	issues: YamlIssue[];
}
```

`YamlValidate` is any synchronous function that returns Standard Schema issues: `engine.safeValidateForm` from
`@schema-engine/forms` fits as it is, and a Standard Schema's `~standard.validate` fits once wrapped.
`YamlDocumentError` is what `parseYaml` throws; its `message` lists one `file:line:column path: message` line per issue.

See [Serialized documents](/docs/schema-engine/serialized-documents#yaml) for recipes and the caveats, and [YAML forms](/docs/forms/yaml) for forms.
