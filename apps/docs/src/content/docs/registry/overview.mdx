# @schema-engine/registry

Base registry system for managing named resources in an extensible architecture.

## Quick Look

```typescript
import * as z from 'zod/mini';

interface Feature extends BaseRegistration {
	$type: string;
	execute: () => void;
}

class FeatureRegistry extends BaseRegistry<string, Feature> {
	get registryName() {
		return 'Feature';
	}
}

const registry = new FeatureRegistry();
registry.register({
	$type: 'dark-mode',
	schema: z.object({}),
	metadata: { name: 'Dark Mode' },
	execute: () => console.log('Dark mode active'),
});

registry.get('dark-mode')?.execute();
```

The flow is: define a registration shape, create a registry subclass, then register and consume items by `$type`.

## Overview

`@schema-engine/registry` provides the foundational classes for creating registry-based plugin systems. The actions package uses it to store action registrations. The forms package exposes optional registry helpers and builds engine Maps directly.

**Key Features:**

- **Type Safe**: Full TypeScript support with generic constraints for keys and values.
- **Extensible**: Abstract `BaseRegistry` accepts domain-specific registration types.
- **Logging**: Built-in debug logging for registration lifecycle events.
- **Standard Schema boundary**: Register schemas from Zod Mini, Zod, Valibot, Effect Schema, or another compatible provider.

## Installation

```bash
pnpm add @schema-engine/registry

# Install zod only when authoring schemas with zod/mini.
pnpm add zod
```
