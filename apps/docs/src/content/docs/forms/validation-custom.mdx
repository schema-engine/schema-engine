# Custom and async rules

The [built-in rules](/docs/forms/validation) cover formats, ranges and cross-field checks. For a business requirement they do not cover, register a rule of your own: a custom rule is a registration you pass to the engine when you create it. For a check that needs a server, use the built-in `async` rule, below.

## Registration Basics

A validation registration has the same shape as an element, recipe or action registration:

- `$type`: the `$type` authors write in a field's `rules`, so a registration with `$type: 'postalCode'` handles `{ $type: 'postalCode' }`.
- `schema`: a [Standard Schema](https://standardschema.dev/) for the rule object. The engine build throws if it is not one, and a form config that uses the rule is checked against it, so the options it declares are validated where the form is validated.
- `metadata`: a `name` and an optional `description`.
- `category` and `handler`: the handler returns the Zod Mini schema that checks the value. `dependsOn` and `defaultFor` are optional.

Pass registrations to `createFormEngine({ validations: [...] })`. They are stored in a read-only
registry: a later registration with the same `$type` replaces an earlier one without a warning, and
nothing can be registered or removed after the engine is built. Registrations come after the built-in
rules and after the validations that elements declare, so they can also override a built-in rule.

### Simple Custom Validation

Here's a basic custom validation, passed to the engine, and a field that uses it. The snippet is complete, so it can be copied as it is:

```typescript
import * as z from 'zod/mini';
import { createFormEngine } from '@schema-engine/forms';

type PostalCodeRule = { $type: 'postalCode'; message?: string };

const postalCode = {
	$type: 'postalCode',
	schema: z.object({ $type: z.literal('postalCode'), message: z.optional(z.string()) }),
	metadata: { name: 'Postal code', description: 'A US ZIP or ZIP+4 code.' },
	category: 'string',
	handler: (rule: PostalCodeRule) => {
		const postalCodeRegex = /^\d{5}(?:-\d{4})?$/;
		return z.string().check(z.regex(postalCodeRegex, rule.message || 'Invalid postal code'));
	},
} as const;

export const engine = createFormEngine({ validations: [postalCode] });

export const postalCodeField = {
	$type: 'input',
	id: 'postal-code',
	name: 'postalCode',
	label: 'Postal code',
	rules: [
		{ $type: 'required', message: 'Postal code is required' },
		{ $type: 'postalCode', message: 'Please enter a valid postal code' },
	],
};
```

The patterns below define one registration each. Add each constant to the `validations` list:

```typescript
createFormEngine({ validations: [postalCode, creditCard, lengthRange] });
```

### Use the Rule in a Form

Every element that extends `BaseFieldSchema` accepts a rule of any registered `$type` in its `rules`. When the engine validates a form config (`defineForm`, `validateForm`) it checks each rule against the registry: the `$type` must be registered, the rule must satisfy the registration's `schema`, and its handler must build a schema for it. A registration that replaces a built-in rule decides its options, extra ones included. Nothing in the element needs widening, and the JSON Schema export (`generateFormConfigSchema`) lists each registered rule once, as the `validation-rule` definition that every element's `rules` refers to, so an editor offers custom rules too. A rule is listed with its options when its `schema` is Zod; a schema from another Standard Schema library is listed by its `$type` only.

```typescript
import * as z from 'zod/mini';
import { createFormEngine, defineInput, BaseFieldSchema, type ValidationRegistration } from '@schema-engine/forms';

type PostalCodeRule = { $type: 'postalCode'; country?: 'us' | 'ca'; message?: string };

const postalCode: ValidationRegistration<PostalCodeRule> = {
	$type: 'postalCode',
	schema: z.looseObject({ $type: z.literal('postalCode'), country: z.optional(z.enum(['us', 'ca'])) }),
	metadata: { name: 'Postal code' },
	category: 'string',
	handler: (rule) =>
		z.string().check(z.regex(rule.country === 'ca' ? /^[A-Z]\d[A-Z] ?\d[A-Z]\d$/ : /^\d{5}(?:-\d{4})?$/)),
};

const text = defineInput({
	$type: 'text',
	schema: z.extend(BaseFieldSchema, { $type: z.literal('text') }),
	metadata: { name: 'Text', category: 'input' },
	value: () => z.string(),
	render: () => null,
});

export const engine = createFormEngine({ elements: [text], validations: [postalCode] });

export const form = engine.defineForm({
	id: 'address',
	steps: [
		{
			id: 'main',
			title: 'Address',
			elements: [
				{
					$type: 'text',
					id: 'postal-code',
					name: 'postalCode',
					rules: [{ $type: 'postalCode', country: 'ca', message: 'Enter a Canadian postal code' }],
				},
			],
		},
	],
});
```

A `type` nothing registers is rejected when the form is validated, with the types that are registered: `Unknown validation rule 'postalcode'. Register it with createFormEngine({ validations: [...] }). Registered rules: required, minLength, ...`. The issue is at `steps[0].elements[0].rules[0].type`. An option the registration's `schema` refuses is reported at its key, such as `steps[0].elements[0].rules[0].country`.

### Validation with Parameters

A rule is an object with a `$type` and any parameters you choose. Describe it with a type, and the handler receives it typed. Each snippet below is complete and can be copied as it is.

```typescript
import * as z from 'zod/mini';
import { createFormEngine, type ValidationRegistration } from '@schema-engine/forms';

type LengthRangeRule = { $type: 'lengthRange'; value?: { min?: number; max?: number }; message?: string };

const lengthRange: ValidationRegistration<LengthRangeRule> = {
	$type: 'lengthRange',
	schema: z.looseObject({ $type: z.literal('lengthRange') }),
	metadata: { name: 'Length Range' },
	category: 'string',
	handler: (rule) => {
		const { min, max } = rule.value ?? {};
		const checks = [
			...(min !== undefined ? [z.minLength(min, `Must be at least ${min} characters`)] : []),
			...(max !== undefined ? [z.maxLength(max, `Must be no more than ${max} characters`)] : []),
		];

		return z.string().check(...checks);
	},
};

export const engine = createFormEngine({ validations: [lengthRange] });

export const descriptionField = {
	$type: 'input',
	id: 'description',
	name: 'description',
	label: 'Description',
	rules: [
		{
			$type: 'lengthRange',
			value: { min: 10, max: 500 },
			message: 'Description must be between 10 and 500 characters',
		},
	],
};
```

A credit card rule checks the Luhn sum:

```typescript
import * as z from 'zod/mini';
import { createFormEngine, type ValidationRegistration } from '@schema-engine/forms';

type CreditCardRule = { $type: 'creditCard'; message?: string };

function passesLuhn(value: string): boolean {
	const cleanValue = value.replace(/[\s-]/g, '');

	if (!/^\d+$/.test(cleanValue) || cleanValue.length < 13 || cleanValue.length > 19) {
		return false;
	}

	let sum = 0;
	let isEven = false;

	for (let i = cleanValue.length - 1; i >= 0; i--) {
		let digit = Number(cleanValue[i]);

		if (isEven) {
			digit *= 2;
			if (digit > 9) {
				digit -= 9;
			}
		}

		sum += digit;
		isEven = !isEven;
	}

	return sum % 10 === 0;
}

const creditCard: ValidationRegistration<CreditCardRule> = {
	$type: 'creditCard',
	schema: z.looseObject({ $type: z.literal('creditCard') }),
	metadata: { name: 'Credit Card' },
	category: 'string',
	handler: (rule) => z.string().check(z.refine(passesLuhn, rule.message || 'Invalid credit card number')),
};

export const engine = createFormEngine({ validations: [creditCard] });
```

## Common Custom Validation Patterns

### Business Rule Validations

```typescript
import * as z from 'zod/mini';
import { createFormEngine, type ValidationRegistration } from '@schema-engine/forms';

type CompanyEmailRule = { $type: 'companyEmail'; value?: { domains?: string[] }; message?: string };

const companyEmail: ValidationRegistration<CompanyEmailRule> = {
	$type: 'companyEmail',
	schema: z.looseObject({ $type: z.literal('companyEmail') }),
	metadata: { name: 'Company Email' },
	category: 'string',
	handler: (rule) => {
		const allowedDomains = rule.value?.domains ?? ['company.com'];

		return z
			.email('Invalid email format')
			.check(
				z.refine(
					(email) => allowedDomains.includes(email.split('@')[1] ?? ''),
					rule.message || `Email must be from one of: ${allowedDomains.join(', ')}`,
				),
			);
	},
};

export const engine = createFormEngine({ validations: [companyEmail] });

export const emailField = {
	$type: 'input',
	id: 'work-email',
	name: 'workEmail',
	label: 'Work email',
	rules: [
		{
			$type: 'companyEmail',
			value: { domains: ['mycompany.com', 'subsidiary.com'] },
			message: 'Please use your company email address',
		},
	],
};
```

### Age Validation with Date

```typescript
import * as z from 'zod/mini';
import { createFormEngine, type ValidationRegistration } from '@schema-engine/forms';

type AgeRule = { $type: 'ageFromBirthDate'; value?: { minAge?: number; maxAge?: number }; message?: string };

const ageFromBirthDate: ValidationRegistration<AgeRule> = {
	$type: 'ageFromBirthDate',
	schema: z.looseObject({ $type: z.literal('ageFromBirthDate') }),
	metadata: { name: 'Age From Birth Date' },
	category: 'date',
	handler: (rule) => {
		const { minAge, maxAge } = rule.value ?? {};

		return z.string().check(
			z.refine(
				(dateString) => {
					const birthDate = new Date(dateString);
					const today = new Date();
					const age = today.getFullYear() - birthDate.getFullYear();
					const monthDiff = today.getMonth() - birthDate.getMonth();
					const birthdayPending = monthDiff < 0 || (monthDiff === 0 && today.getDate() < birthDate.getDate());
					const actualAge = birthdayPending ? age - 1 : age;

					if (minAge !== undefined && actualAge < minAge) return false;
					if (maxAge !== undefined && actualAge > maxAge) return false;

					return true;
				},
				rule.message || `Age must be between ${minAge} and ${maxAge}`,
			),
		);
	},
};

export const engine = createFormEngine({ validations: [ageFromBirthDate] });

export const birthDateField = {
	$type: 'input',
	id: 'birth-date',
	inputType: 'date',
	name: 'birthDate',
	rules: [
		{ $type: 'required', message: 'Birth date is required' },
		{
			$type: 'ageFromBirthDate',
			value: { minAge: 18, maxAge: 65 },
			message: 'You must be between 18 and 65 years old',
		},
	],
};
```

### Social Security Number (US)

```typescript
import * as z from 'zod/mini';
import { createFormEngine, type ValidationRegistration } from '@schema-engine/forms';

type SsnRule = { $type: 'ssn'; message?: string };

const ssn: ValidationRegistration<SsnRule> = {
	$type: 'ssn',
	schema: z.looseObject({ $type: z.literal('ssn') }),
	metadata: { name: 'Ssn' },
	category: 'string',
	handler: (rule) =>
		z.string().check(
			z.regex(/^\d{3}-\d{2}-\d{4}$/, 'SSN must be in format XXX-XX-XXXX'),
			z.refine((value) => {
				const [area = '', group = '', serial = ''] = value.split('-');

				if (area === '000' || area === '666' || area.startsWith('9')) return false;
				if (group === '00') return false;
				if (serial === '0000') return false;

				return true;
			}, rule.message || 'Invalid Social Security Number'),
		),
};

export const engine = createFormEngine({ validations: [ssn] });
```

### Password Strength

```typescript
import * as z from 'zod/mini';
import { createFormEngine, type ValidationRegistration } from '@schema-engine/forms';

type PasswordStrengthRule = {
	$type: 'passwordStrength';
	value?: {
		minLength?: number;
		requireUppercase?: boolean;
		requireLowercase?: boolean;
		requireNumbers?: boolean;
		requireSpecialChars?: boolean;
	};
	message?: string;
};

const passwordStrength: ValidationRegistration<PasswordStrengthRule> = {
	$type: 'passwordStrength',
	schema: z.looseObject({ $type: z.literal('passwordStrength') }),
	metadata: { name: 'Password Strength' },
	category: 'string',
	handler: (rule) => {
		const requirements = rule.value ?? {
			minLength: 8,
			requireUppercase: true,
			requireLowercase: true,
			requireNumbers: true,
			requireSpecialChars: true,
		};

		return z.string().check(
			z.refine((password) => {
				if (requirements.minLength && password.length < requirements.minLength) return false;
				if (requirements.requireUppercase && !/[A-Z]/.test(password)) return false;
				if (requirements.requireLowercase && !/[a-z]/.test(password)) return false;
				if (requirements.requireNumbers && !/\d/.test(password)) return false;
				if (requirements.requireSpecialChars && !/[!@#$%^&*(),.?":{}|<>]/.test(password)) return false;

				return true;
			}, rule.message || 'Password does not meet strength requirements'),
		);
	},
};

export const engine = createFormEngine({ validations: [passwordStrength] });

export const passwordField = {
	$type: 'input',
	id: 'password',
	name: 'password',
	inputType: 'password',
	rules: [
		{
			$type: 'passwordStrength',
			value: {
				minLength: 12,
				requireUppercase: true,
				requireLowercase: true,
				requireNumbers: true,
				requireSpecialChars: false,
			},
			message: 'Password must be at least 12 characters with uppercase, lowercase, and numbers',
		},
	],
};
```

## Cross-Field Validations

Every handler receives a `ValidationContext` as its second argument. Read other
fields through `context.resolve`, which resolves a reference relative to the
field being validated: a bare name is a sibling, a dotted name is absolute from
the form root.

```typescript
import * as z from 'zod/mini';
import { createFormEngine, type ValidationRegistration } from '@schema-engine/forms';

type ConfirmPasswordRule = { $type: 'confirmPassword'; message?: string };
type ConditionalRequiredRule = {
	$type: 'conditionalRequired';
	value: { dependsOn: string; when: unknown };
	message?: string;
};

const confirmPassword: ValidationRegistration<ConfirmPasswordRule> = {
	$type: 'confirmPassword',
	schema: z.looseObject({ $type: z.literal('confirmPassword') }),
	metadata: { name: 'Confirm Password' },
	category: 'cross-field',
	dependsOn: () => ['password'],
	handler: (rule, context) =>
		z
			.string()
			.check(
				z.refine(
					(confirmation) => context.resolve('password') === confirmation,
					rule.message || 'Passwords do not match',
				),
			),
};

const conditionalRequired: ValidationRegistration<ConditionalRequiredRule> = {
	$type: 'conditionalRequired',
	schema: z.looseObject({ $type: z.literal('conditionalRequired') }),
	metadata: { name: 'Conditional Required' },
	category: 'cross-field',
	dependsOn: (rule) => [rule.value.dependsOn],
	handler: (rule, context) =>
		z.optional(z.string()).check(
			z.refine((value) => {
				const dependentField = context.resolve(rule.value.dependsOn);

				return !(rule.value.when === dependentField && !value);
			}, rule.message || 'This field is required'),
		),
};

export const engine = createFormEngine({ validations: [confirmPassword, conditionalRequired] });
```

Because the reference is relative, a rule authored once on a field inside an
array reads its own row. A `confirmPassword` rule on `accounts.1.confirm`
resolves `password` to `accounts.1.password`, not `accounts.0.password`.
`context.values` holds the whole form as a nested tree when a rule genuinely
needs more than one reference.

`dependsOn` is what tells a renderer when to re-run the rule. Without it the rule
still validates correctly, but only when its own field is validated — changing a
field it reads will not re-run it.

A cross-field rule that declares `dependsOn` re-runs when a field it reads
changes, so correcting a password clears the "passwords must match" error on the
confirmation. The error surfaces only once the dependent field has been touched,
or once the form has been submitted, so typing a password does not light up a
confirmation nobody has reached.

Authoring the field is unchanged:

```typescript
export const companyNameField = {
	$type: 'input',
	id: 'company-name',
	name: 'companyName',
	label: 'Company Name',
	rules: [
		{
			$type: 'conditionalRequired',
			value: { dependsOn: 'userType', when: 'business' },
			message: 'Company name is required for business accounts',
		},
	],
};
```

## The built-in async rule

For a check that needs a server, use the built-in `async` rule. It sends the value, caches the answer, waits for the user to stop typing and re-validates when the fields it depends on change.

```ts title="async-rule.ts"
import type { AsyncRule } from '@schema-engine/forms';

export const usernameRule = {
	$type: 'async',
	url: '/api/check-username',
	method: 'POST',
	extraPayload: { validationType: 'premium' },
	expectedResponse: { valid: true },
	debounce: 500,
	cacheTTL: 300000,
	message: 'Username is already taken',
} satisfies AsyncRule;
```

| Property           | Type       | Description                                                           |
| ------------------ | ---------- | --------------------------------------------------------------------- |
| `url`              | `string`   | API endpoint for validation                                           |
| `method`           | `string`   | `GET`, `POST`, `PUT`, `PATCH` or `DELETE`                             |
| `headers`          | `object`   | Optional HTTP headers                                                 |
| `extraPayload`     | `object`   | Extra request fields. `value` and `dependsOn` are added automatically |
| `expectedResponse` | `object`   | The response body that means the value is valid                       |
| `dependencies`     | `string[]` | Fields that trigger re-validation when they change                    |
| `debounce`         | `number`   | Delay in ms before the request is made                                |
| `cacheTTL`         | `number`   | Cache time-to-live in milliseconds (default: 5 minutes)               |
| `disableCache`     | `boolean`  | Turn the cache off (default: false)                                   |
| `message`          | `string`   | The text to show when the server says the value is not valid          |

With `debounce`, a newer validation of the same field replaces a pending one and only the latest request is sent. A replaced validation of the same value shares that request's result. One of a different value has no result, neither a pass nor an issue, so a submit-time check superseded by a later edit never passes. Nothing is shown for it while the user types: each renderer shows the result for the latest value.

### Dependencies

`dependencies` are field references and resolve exactly like `relate`'s `fields`: a bare name is a sibling, including a sibling inside the declaring array row, and a dotted name is absolute from the form root. The request body carries a `dependsOn` object keyed by the reference as authored:

```json
{
	"value": "userInputValue",
	"dependsOn": {
		"username": "actualUsernameValue",
		"email": "actual@email.com"
	}
}
```

### Caching and outages

- Successful answers are cached for five minutes by default. The key is the URL and the request payload. Expired entries are evicted on cache reads and writes.
- A non-ok response or a network failure is not an answer about the value. The rule throws `ValidationUnavailable`, which is reported as a failure to run (`validate()` rejects), and it is never cached.

## A custom async rule

Use a registration when the check is not a request and a response the built-in rule can describe. Answer "taken" only when the server says so. A request that fails is not an answer, so throw `ValidationUnavailable`, as the built-in rule does, and the form reports that the check could not run:

```ts title="unique-username.ts"
import * as z from 'zod/mini';
import { createFormEngine, ValidationUnavailable, type ValidationRegistration } from '@schema-engine/forms';

type UniqueUsernameRule = { $type: 'uniqueUsername'; message?: string };

const uniqueUsername: ValidationRegistration<UniqueUsernameRule> = {
	$type: 'uniqueUsername',
	schema: z.looseObject({ $type: z.literal('uniqueUsername') }),
	metadata: { name: 'Unique username' },
	category: 'generic',
	handler: (rule, { fetch }) =>
		z.string().check(
			z.refine(async (username) => {
				let response: Response;
				try {
					response = await fetch('/api/check-username', {
						method: 'POST',
						headers: { 'Content-Type': 'application/json' },
						body: JSON.stringify({ username }),
					});
				} catch (cause) {
					throw new ValidationUnavailable({ cause });
				}
				if (!response.ok) throw new ValidationUnavailable();
				const { available } = (await response.json()) as { available: boolean };
				return available;
			}, rule.message ?? 'Username is already taken'),
		),
};

export const engine = createFormEngine({ validations: [uniqueUsername] });
```

The handler's second argument is the validation context. Its `fetch` is the engine's, so a CSRF policy and a test double apply to this request too.

## Several Validations at Once

Pass several custom validations at once. A later entry replaces an earlier one with the same `$type`:

```typescript
import * as z from 'zod/mini';
import { createFormEngine, type ValidationRegistration } from '@schema-engine/forms';

type PostalCodeRule = { $type: 'postalCode'; country?: 'US' | 'CA' | 'UK'; message?: string };
type WorkingHoursRule = { $type: 'workingHours'; message?: string };
type FileSizeRule = { $type: 'fileSize'; maxSize?: number; message?: string };

const postalCode: ValidationRegistration<PostalCodeRule> = {
	$type: 'postalCode',
	schema: z.looseObject({ $type: z.literal('postalCode') }),
	metadata: { name: 'Postal code' },
	category: 'string',
	handler: (rule) => {
		const country = rule.country ?? 'US';
		const patterns = {
			US: /^\d{5}(-\d{4})?$/,
			CA: /^[A-Za-z]\d[A-Za-z] \d[A-Za-z]\d$/,
			UK: /^[A-Za-z]{1,2}\d[A-Za-z\d]? \d[A-Za-z]{2}$/,
		};

		return z.string().check(z.regex(patterns[country], rule.message || `Invalid ${country} postal code`));
	},
};

const workingHours: ValidationRegistration<WorkingHoursRule> = {
	$type: 'workingHours',
	schema: z.looseObject({ $type: z.literal('workingHours') }),
	metadata: { name: 'Working hours' },
	category: 'date',
	handler: (rule) =>
		z.string().check(
			z.refine((time) => {
				const [hours, minutes] = time.split(':').map(Number);
				const totalMinutes = hours * 60 + minutes;

				return totalMinutes >= 540 && totalMinutes <= 1020;
			}, rule.message || 'Time must be during working hours (9 AM - 5 PM)'),
		),
};

const fileSize: ValidationRegistration<FileSizeRule> = {
	$type: 'fileSize',
	schema: z.looseObject({ $type: z.literal('fileSize') }),
	metadata: { name: 'File size' },
	category: 'generic',
	handler: (rule) => {
		const maxSize = rule.maxSize ?? 1024 * 1024;

		return z
			.instanceof(File)
			.check(
				z.refine(
					(file) => file.size <= maxSize,
					rule.message || `File size must be less than ${maxSize / 1024 / 1024}MB`,
				),
			);
	},
};

export const engine = createFormEngine({ validations: [postalCode, workingHours, fileSize] });
```

## Testing Custom Validations

Always test your custom validations thoroughly. Build an engine with the rule and read the schema from its registry:

```typescript
import * as z from 'zod/mini';
import { describe, it, expect } from 'vitest';
import { createFormEngine, createValidationContext } from '@schema-engine/forms';

const postalCode = {
	$type: 'postalCode',
	schema: z.object({ $type: z.literal('postalCode'), message: z.optional(z.string()) }),
	metadata: { name: 'Postal code' },
	category: 'string',
	handler: (rule: { $type: 'postalCode'; message?: string }) =>
		z.string().check(z.regex(/^\d{5}(?:-\d{4})?$/, rule.message || 'Invalid postal code')),
} as const;

const registry = createFormEngine({ validations: [postalCode] }).getValidationRegistry();

function schemaFor(message: string) {
	const schema = registry.createSchema({ $type: 'postalCode', message }, createValidationContext());
	if (!schema) throw new Error('postalCode is not registered');
	return schema;
}

describe('Custom postal code validation', () => {
	it('should validate correct postal codes', () => {
		const schema = schemaFor('Invalid postal code');

		expect(schema.safeParse('12345').success).toBe(true);
		expect(schema.safeParse('12345-6789').success).toBe(true);
	});

	it('should reject invalid postal codes', () => {
		const schema = schemaFor('Invalid postal code');

		expect(schema.safeParse('1234').success).toBe(false);
		expect(schema.safeParse('abcde').success).toBe(false);
		expect(schema.safeParse('').success).toBe(false);
	});

	it('should use custom error message', () => {
		const result = schemaFor('Please enter a valid postal code').safeParse('invalid');

		expect(result.success).toBe(false);
		if (!result.success) {
			expect(result.error.issues[0].message).toBe('Please enter a valid postal code');
		}
	});
});
```

## Performance Considerations

### Expensive Operations

Place expensive validations last in the rule chain:

```typescript
{
	rules: [{ $type: 'required' }, { $type: 'minLength', value: 3 }, { $type: 'email' }, { $type: 'uniqueEmail' }];
}

{
	rules: [{ $type: 'uniqueEmail' }, { $type: 'required' }, { $type: 'email' }];
}
```

### Debouncing Async Validations

Use the built-in async rule to debounce server-side validation. A pending check
replaced by a different value has no result (it throws `ValidationSuperseded`, which is no issue); a check replaced
by the same value shares the latest result. Checks for separate fields do not
cancel one another. See [The built-in async rule](#the-built-in-async-rule)
for the request and response contract.

```typescript
import type { AsyncRule } from '@schema-engine/forms';

const usernameRule = {
	$type: 'async',
	url: '/api/check-username',
	method: 'POST',
	expectedResponse: { valid: true },
	debounce: 500,
	message: 'Username is unavailable',
} satisfies AsyncRule;
```

Debouncing replaces pending timers; it does not cancel a request that has
already started. If custom validation needs request cancellation or ordering,
its implementation must handle those separately.

## Best Practices

### 1. Use Clear Type Names

Choose descriptive type names that clearly indicate what the validation does:

```typescript
{ $type: 'socialSecurityNumber', ... }
{ $type: 'businessEmailDomain', ... }

{ $type: 'ssn', ... }
{ $type: 'customVal1', ... }
```

### 2. Provide Helpful Default Messages

Always include meaningful default error messages:

```typescript
handler: (rule) => {
	return z
		.string()
		.check(z.regex(pattern, rule.message || 'Please enter a valid phone number in format: +1234567890'));
};

handler: (rule) => {
	return z.string().check(z.regex(pattern, rule.message || 'Invalid format'));
};
```

### 3. Handle Edge Cases

Consider edge cases and provide graceful error handling:

```typescript
import * as z from 'zod/mini';
import { createFormEngine, type ValidationRegistration } from '@schema-engine/forms';

type CardNumberRule = { $type: 'cardNumber'; message?: string };

const cardNumber: ValidationRegistration<CardNumberRule> = {
	$type: 'cardNumber',
	schema: z.looseObject({ $type: z.literal('cardNumber') }),
	metadata: { name: 'Card Number' },
	category: 'string',
	handler: (rule) =>
		z.string().check(
			z.refine((value) => {
				if (!value) return false;

				const cleanValue = value.replace(/[\s-]/g, '');

				return /^\d+$/.test(cleanValue);
			}, rule.message || 'Please enter a valid credit card number'),
		),
};

export const engine = createFormEngine({ validations: [cardNumber] });
```

### 4. Check with a real algorithm

A rule is a good place for a checksum the built-in rules do not have. This rule validates an IBAN with the ISO 7064 mod-97 check, so a typo is caught before the request:

```ts title="iban.ts"
import * as z from 'zod/mini';
import { createFormEngine, type ValidationRegistration } from '@schema-engine/forms';

type IbanRule = { $type: 'iban'; message?: string };

export function isValidIban(value: string): boolean {
	const iban = value.replaceAll(' ', '').toUpperCase();
	if (!/^[A-Z]{2}\d{2}[A-Z0-9]{11,30}$/.test(iban)) return false;
	const rearranged = `${iban.slice(4)}${iban.slice(0, 4)}`;
	const digits = [...rearranged].map((char) => (/\d/.test(char) ? char : String(char.charCodeAt(0) - 55))).join('');
	let remainder = 0;
	for (const digit of digits) remainder = (remainder * 10 + Number(digit)) % 97;
	return remainder === 1;
}

const iban: ValidationRegistration<IbanRule> = {
	$type: 'iban',
	schema: z.looseObject({ $type: z.literal('iban') }),
	metadata: { name: 'IBAN', description: 'An IBAN with a valid mod-97 check.' },
	category: 'string',
	handler: (rule) => z.string().check(z.refine(isValidIban, rule.message ?? 'Enter a valid IBAN')),
};

export const engine = createFormEngine({ validations: [iban] });
```

## Registry Management

The engine's validation registry is read-only. It lists what is registered but has no `register`, `unregister` or `clear`.

### Checking Registration Status

```typescript
const validationRegistry = engine.getValidationRegistry();

if (validationRegistry.has('postalCode')) {
	console.log('Postal code validation is available');
}

const types = validationRegistry.keys();
console.log('Available validations:', types);

const stringValidations = validationRegistry.getByCategory('string');
```

### Replacing and Removing Validations

A registration cannot be removed from an engine that is built. To replace one, register another with the same `$type` later in the list, or extend the engine. To drop one, build the engine without it.

```typescript
const withStrictPostalCodes = engine.extend({ validations: [strictPostalCode] });
```

Here `strictPostalCode` is another registration with `$type: 'postalCode'`.

`extend` returns a new engine and keeps the validations the source engine was created with.

### Creating Separate Registries

For different contexts or testing, build a registry from a list. `createDefaultValidationRegistry` adds the built-in rules first:

```typescript
import { createValidationRegistry } from '@schema-engine/forms';

const testOnly = {
	$type: 'testOnly',
	schema: z.object({ $type: z.literal('testOnly') }),
	metadata: { name: 'Test only' },
	category: 'string',
	handler: () => z.string().check(z.minLength(1)),
} as const;

const testRegistry = createValidationRegistry([testOnly]);

const schema = testRegistry.createSchema({ $type: 'testOnly' }, createValidationContext());
```

## The endpoint

The endpoint of the built-in rule receives `value`, `dependsOn` when the rule has `dependencies`, and every key of `extraPayload`. It answers with the `expectedResponse` body when the value is valid, and `message` can carry the text to show when it is not:

```ts title="check-username-endpoint.ts"
const unavailable = new Set(['admin', 'root']);

export async function POST(request: Request): Promise<Response> {
	const { value } = (await request.json()) as { value: string };
	if (unavailable.has(value.toLowerCase())) {
		return Response.json({ valid: false, message: `Username "${value}" is not available` });
	}
	return Response.json({ valid: true });
}
```
