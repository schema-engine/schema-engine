# Forms

Forms is the first domain of Schema Engine. It uses the [registry](/docs/registry/overview) for its elements, recipes and validation rules, [actions](/docs/actions/overview) for submit, reset and the work around them, and [layout](/docs/layout/overview) for the grid and named appearance. On top of those it adds what a form needs: fields and their values, validation rules, constraints between fields, steps, form state and the submit lifecycle. A form is a [document](/docs/schema-engine/core-concepts#document): a JSON config that names registered elements by `$type`.

`@schema-engine/forms` is the framework-agnostic package. It has no renderer: [Forms React](/docs/forms-react/overview) and [Forms Radiant](/docs/forms-radiant/overview) draw the same config.

With it you can:

- Author form configs in TypeScript with `engine.defineForm()`, typed from your registrations, or load them as JSON and check them with `engine.validateForm()`.
- Register your own elements, view recipes, actions and validation rules.
- Validate values with the 27 validation rules the engine registers, and with rules of your own.
- Run a form without a renderer, with `createFormRuntime`, to test it or to write a renderer.
- Generate JSON Schema from what the engine has registered, for editors and tools.

## What a form can do

A form's behavior is independent of the element that collects a value and the recipe that lays out the form. Both the React and Radiant adapters implement the same form configuration contracts.

| Capability       | Use it for                                                               | Start here                                                                        |
| ---------------- | ------------------------------------------------------------------------ | --------------------------------------------------------------------------------- |
| Constraints      | Show, hide, enable, disable, or require a field from another value       | [Contact form example](/docs/examples/contact-form)                               |
| Validation       | Required values, formats, ranges, and custom rules                       | [Validation](/docs/forms/validation)                                              |
| Actions          | Submit, reset, notifications, and ordered side effects                   | [Actions overview](/docs/actions/overview)                                        |
| Async validation | Debounced remote checks, dependency values, and failure handling         | [Async validation](/docs/forms/validation-how-it-works#enhanced-async-validation) |
| Async actions    | Pending, success, and failure states around a remote operation           | [Sequential actions example](/docs/examples/sequential-actions)                   |
| Dynamic fields   | Repeatable groups and nested field scopes                                | [Components](/docs/forms-react/components)                                        |
| Form state       | Values, field state, validity and submission, the same in both renderers | [Form state](/docs/forms/form-state)                                              |
| Wizard steps     | Next, back and jump, with steps skipped from earlier answers             | [Wizard and runtime](/docs/forms/wizard)                                          |
| Server errors    | Show a server's validation response on the fields it names               | [Server errors](/docs/forms/server-errors)                                        |
| Issue text       | Word every error and warning in your language                            | [Issue text](/docs/forms/issue-text)                                              |
| CSRF             | Send a token with the engine's requests and native posts                 | [CSRF](/docs/forms/csrf)                                                          |

## Installation and quick start

```bash
pnpm add @schema-engine/forms zod
```

[Installation and quick start](/docs/forms/getting-started) registers two elements, checks a form loaded as JSON and submits it with no renderer. The `zod` package provides the `zod/mini` entry point that first-party schemas use. Registrations may use any Standard Schema validator.
