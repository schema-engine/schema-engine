# Builder Pattern

`FormComposer` is the assembly point for a form engine. Register the runtime
capabilities your application uses, then call `build()` to create an immutable
`FormEngine`.

## Register capabilities

The core composer has three independent registries:

- **Elements** render fields and static content inside a step.
- **Recipes** compose the form shell and optional header, progress, and action
  blocks.
- **Actions** respond to form and step lifecycle triggers.

```ts
const engine = new FormComposer()
	.addElements(elementRegistrations)
	.addRecipes(recipeRegistrations)
	.addActions(actionRegistrations)
	.build();
```

`addElement`, `addRecipe`, and `addAction` are the single-registration forms;
the plural methods register a collection. Registration IDs are the `$type`
values used in serialized configuration.

## React composer

The React adapter provides a headless convenience factory. It does not own
application field components or visual recipes: install Schema Engine registry
items and pass their generated registrations explicitly.

```ts
import { createReactFormComposer } from '@schema-engine/forms-react';
import { schemaFormRegistrations } from '@/components/schema-engine/forms/registrations';
import { schemaFormRecipeRegistrations } from '@/components/schema-engine/forms/recipes/registrations';

const engine = createReactFormComposer()
	.addElements(schemaFormRegistrations)
	.addRecipes(schemaFormRecipeRegistrations)
	.build();
```

Radiant uses the same composition model for elements: register them explicitly.
`createRadiantFormComposer()` already binds the canonical view recipes because
Radiant has no shadcn registry. Specs still come from `@schema-engine/forms/recipes`.

## Author form configuration

When configuration is authored in TypeScript rather than loaded as JSON, pass a
typed object to `engine.defineForm()`:

```ts
const form = engine.defineForm({
	id: 'contact',
	title: 'Contact',
	view: { $type: 'card', shell: { maxWidth: 'md' } },
	steps: [
		{
			id: 'details',
			title: 'Contact details',
			elements: [
				{
					$type: 'input',
					id: 'email',
					name: 'email',
					label: 'Email',
					inputType: 'email',
				},
			],
		},
	],
});
```

`defineForm` validates against the engine's registered elements, recipes, and
actions. It applies schema defaults and transforms. Use `engine.validateForm()`
for untyped or external JSON. Use a plain `FormConfig` when configuration must
remain portable or editable by another system.

## Composition rules

There is one view recipe per form. The recipe is selected at the form level:

```ts
const config: FormConfig = {
	id: 'contact',
	steps: [{ id: 'details', title: 'Contact details', elements: [] }],
	view: {
		$type: 'card',
		shell: { padding: 'md' },
	},
};
```

Do not place shell, header, progress, or action configuration on individual
steps. Wizard recipes are for multi-step forms; single-step recipes cannot
declare progress or actions slots. See [View recipes](/docs/forms-react/layouts)
for the available compositions and custom recipe API.
