# @schema-engine/actions

## Overview

`@schema-engine/actions` is the generic action core used across Schema Engine packages.

It provides:

- action registrations
- a registry for resolving action types
- a dispatcher with sequential and parallel execution and metadata merging

The package is reusable across domains. It is not form-specific.

## Action flow

These playgrounds dispatch through `ActionDispatcher`. Run an action, or run the whole sequence. Interrupt or reset from the same control.

<ActionFlow />

## Execution Model

The dispatcher separates the caller-provided base context from the runtime context seen by action handlers.

When an action runs, the dispatcher enriches the base context with the current action config, trigger and cancellation signal before calling `execute()`.

```typescript
execute({
	...context,
	config: action,
	trigger,
	signal,
});
```

At the call site you pass only the base context. The merged runtime shape is constructed internally.

## Dependencies

The package has no schema-library runtime dependency. Its `schema` values use
the provider-neutral Standard Schema contract; applications may choose Zod Mini,
Zod, Valibot, Effect Schema, or another compatible provider.

## Quick Example

```typescript
import * as z from 'zod/mini';

type Trigger = 'submit' | 'change';

type BaseContext = {
	userId: string;
	metadata?: Record<string, unknown>;
};

type LogConfig = {
	id: string;
	$type: 'log';
	message: string;
	enabled?: boolean;
	triggers?: readonly string[];
};

const logAction: ActionRegistration<LogConfig, BaseContext, Trigger> = {
	$type: 'log',
	schema: z.strictObject({
		id: z.string(),
		$type: z.literal('log'),
		message: z.string(),
	}),
	metadata: {
		name: 'Log Message',
		description: 'Logs a message',
		defaultTriggers: ['submit'],
	},
	execute: (context) => {
		console.log(context.userId, context.trigger, context.config.message);
		return { success: true };
	},
};

const registry = new ActionRegistry<BaseContext, Trigger>([logAction]);

const dispatcher = new ActionDispatcher(registry);

const baseContext: BaseContext = {
	userId: 'user_123',
};

const parsed = parseActions(registry, [{ id: '1', $type: 'log', message: 'Hello' }]);
if (!parsed.success) throw new Error(parsed.issues.map((issue) => issue.message).join(', '));

await dispatcher.dispatch({
	actions: parsed.data,
	trigger: 'submit',
	context: baseContext,
});
```

`parseActions` checks each entry against its registration's schema, and `dispatch` takes only what it returned, so an action that did not pass its schema never reaches a handler.

The handler still receives `BaseContext & { config: LogConfig; trigger: Trigger }`, but that runtime shape is injected by the dispatcher.
