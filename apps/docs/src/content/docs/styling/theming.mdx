# Theming

Theming is CSS: you set custom properties, and the grid, the appearance axes and the recipes read them. The vocabulary (which names exist) belongs to the [layout theme](/docs/styling/layout-themes); the values belong to your stylesheet.

## The properties you override

| Group              | Properties                                                                                                                           | Read by                                                                                                    |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------- |
| **Gap tokens**     | `--se-grid-gap-none`, `--se-grid-gap-compact`, `--se-grid-gap-default`, `--se-grid-gap-loose`, `--se-grid-gap-wide`                  | Every grid: step grids, fieldsets, array rows                                                              |
| **Size hooks**     | `--se-space-compact`, `--se-space-comfortable`, `--se-control-height-compact`, `--se-control-height-comfortable`                     | The built-in `size` axis, for `compact` and `comfortable`                                                  |
| **Axis tokens**    | `--se-space`, `--se-font-size`, `--se-measure`, `--se-control-height`, `--se-border-width`, `--se-shadow`, `--se-surface-background` | Card shells and controls; set by the built-in axes                                                         |
| **Colour roles**   | `--primary`, `--on-primary`, `--border`, `--surface`, and the rest of your design system                                             | Radiant UI and shadcn components, and the card shells                                                      |
| **Item placement** | `--se-item-*`, `--se-item-display-mode`                                                                                              | Field hosts; see [Layout themes](/docs/styling/layout-themes#custom-properties-of-a-container-and-an-item) |

A card shell keeps the look of an unstyled card as the fallback of each token it reads (`var(--se-space, 1.5rem)`), so with no token set it looks as it does without a theme.

## Where to set a token

Custom properties inherit, so most tokens can be set on any element above the one that reads them. Three rules decide where yours takes effect.

| Token                                                                   | Set it on                                                                                                       | Why                                                                                                                                                                                                                                           |
| ----------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Gap tokens** `--se-grid-gap-*`                                        | `:root`, a wrapper, or the form's `className`                                                                   | The theme never declares them on an element, so an inherited value always reaches the grid.                                                                                                                                                   |
| **Size hooks** in React                                                 | Any ancestor of the element that carries the pick                                                               | The axis rule reads the hook where the pick sits.                                                                                                                                                                                             |
| **Size hooks** in Radiant                                               | The form's own `className`, or a grid or item                                                                   | Radiant declares the hooks on every element that carries `data-se-theme` to map them to its theme, so a value set on `:root` or a wrapper is replaced at the form. The declaration has zero specificity, so a class on the same element wins. |
| **Axis tokens** with a literal value (`--se-font-size`, `--se-measure`) | A rule with class specificity on the element that carries the pick: `.my-form [data-se-size='compact'] { ... }` | The axis rule declares them on that element, and it is closer than anything above. With **no** pick they are not declared, so the form's `className` works.                                                                                   |
| **Colour roles**                                                        | `:root`, or a class on the form                                                                                 | They are your design system's variables; a host axis can set them per value.                                                                                                                                                                  |

Every theme rule sits inside `:where()`, so a class of yours wins over it when it targets the same element, with no `!important`.

A host override of a gap token replaces it at every width, including a width the theme ramps through `grid.responsive`: the public token is the first `var()` argument and a ramp only changes the fallback. A host that wants its own rhythm per width declares its own media queries.

### Radiant: the spacing tokens of its own theme

Radiant UI computes `--size-control-sm`, `--size-control-md` and `--size-control-lg` on `:root` in its default spacing pack, for example `--size-control-md: calc(2rem * var(--rui-density))`. A custom property that holds a `var()` is resolved where it is declared and inherited as the resolved value, so setting `--rui-density` on a wrapper does **not** resize the controls below it: they keep the size computed from the `:root` density.

To make a region denser, set the tokens on the wrapper too:

```css
.dense-region {
	--rui-density: 0.8;
	--size-control-sm: calc(1.75rem * var(--rui-density));
	--size-control-md: calc(2rem * var(--rui-density));
	--size-control-lg: calc(2.25rem * var(--rui-density));
}
```

`size: compact` and `size: comfortable` map onto `--size-control-sm` and `--size-control-lg`, so this is also what a scoped `size` needs. Prefer the size hooks above for form controls, and Radiant UI's token packs (`@ecopages/radiant-ui/tokens/spacing/compact`) when the whole app should change density.

### React: the registry controls

The recipe styles and the controls styles are two imports with different jobs:

- `recipes.css` is imported into the `components` layer, so your Tailwind utilities and classes sit above it. Its rules are `:where()`, so any class beats them.
- `controls.css` is imported **unlayered**, after `recipes.css`, because a shadcn control sets its height with a Tailwind utility that outranks every layered rule. It lets `--se-control-height` set the height of controls that carry `data-se-control`. While a size is picked, a Tailwind height utility you pass to a control loses to it; an unlayered class of yours still wins.

See [View recipes](/docs/forms-react/layouts#default-registry-recipes) for the import lines.
