# Radiant layouts

The Radiant adapter ships its own shells and wizard blocks. These live
previews use the same `FormConfig` JSON as the React adapter while rendering
with Ecopages and Radiant UI elements.

## Appearance in Radiant

The shells take the same named `appearance` as the React recipes: set `view.shell.appearance` (for example `{ size: 'comfortable', surface: 'elevated' }` on the card shell) or a form-level `appearance`, and the shell reads the layout theme's semantic tokens (`--se-space`, `--se-measure`, `--se-border-width`, `--se-shadow`, `--se-surface-background`). Radiant elements emit the picked values as `data-se-<axis>` attributes, so a host axis is styled with CSS keyed on those attributes. The built-in `card` and `card-wizard` shells declare `size` and `surface`; the hero, split-screen and sidebar shells (and their wizard variants) declare `size` alone and read `--se-space` for their padding and gaps. The stack shell declares no axes, so an `appearance` on its `shell` slot is rejected, but it reads `--se-space` from the form's `appearance` (a step's pick does not reach a shell, which sits above the steps).

`size` also sets the height of inputs, selects, number fields and buttons: `compact` uses the `--se-control-height-compact` hook, which falls back to Radiant's `--size-control-sm`, and `comfortable` uses `--se-control-height-comfortable`, which falls back to `--size-control-lg`. No pick or `default` keeps the theme's `--size-control-md`. A field's font size follows `--se-font-size`, as it does in the React registry fields.

Two Radiant details matter when you tune it:

- The size hooks (`--se-space-compact`, `--se-control-height-compact` and their `comfortable` twins) work from `:root`, any ancestor of the form or the form's own `className`, as in React; the nearest setting wins and it reaches a pick on the card shell, a step or a field. Each hook falls back to a `--se-renderer-*` property that Radiant sets on each form from its theme (set by renderers, not by apps), so a form with no hook follows its theme, also one scoped to a wrapper, and an app-wide hook outranks it.
- Radiant UI computes `--size-control-*` on `:root`, so a scoped `--rui-density` does not resize controls below it. [Theming](/docs/layout/theming#radiant-the-spacing-tokens-of-its-own-theme) has the wrapper rule.

Each form carries an identical copy of the layout stylesheet by design; see [Layout stylesheet per form](/docs/forms-radiant/server-rendering#layout-stylesheet-per-form). [Styling and layout](/docs/layout/overview) lists which tool fits which job, and [Recipes](/docs/layout/recipes) has copy-paste configs with their CSS, rendered with these shells.
