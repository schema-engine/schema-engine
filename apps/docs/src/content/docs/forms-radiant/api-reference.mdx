# API reference

## Entry points

| Import                                       | Holds                                                                                                                                                                                                                                                                                                                                             |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `@schema-engine/forms-radiant`               | `createRadiantFormEngine`, `FormRenderer`, `schemaFormRegistrations`, the recipes, `FormController` and `FormEngineController`, and the hosts                                                                                                                                                                                                     |
| `@schema-engine/forms-radiant/primitives`    | What you build elements and recipes from: `FormElement`, `FormElements`, `FormField`, `FormFieldElement`, `ChildGrid` (its `subgrid` prop lays a container's children on the tracks of the grid around it), `defineRecipe`, the shell and recipe types, `formInstanceContext` and `formEngineContext`, `combineHandlers` and `mergeFieldGridHost` |
| `@schema-engine/forms-radiant/registrations` | Each element registration by name, such as `InputElementRegistration`, each loadable alone                                                                                                                                                                                                                                                        |
| `@schema-engine/forms-radiant/index.css`     | The renderer's stylesheet                                                                                                                                                                                                                                                                                                                         |
| `@schema-engine/forms-radiant/debugger`      | `FormDebugger` and `FormDebuggerElement`, a development panel                                                                                                                                                                                                                                                                                     |
| `@schema-engine/forms-radiant/debugger.css`  | The debugger's styles                                                                                                                                                                                                                                                                                                                             |

`.`, `/primitives`, `/debugger` and `/debugger.css` mean the same in [Forms React](/docs/forms-react/api-reference). A renderer adds `/hooks`, `/registrations` or `/index.css` only when it has that kind of content. Importing `/primitives` loads none of the built-in recipes, and an app that never imports `/debugger` ships no debugger. `formInstanceContext` is what the hosts publish to the blocks and recipes of a renderer; an app reads the form with `FormController`.

## createRadiantFormEngine

```ts
import { createRadiantFormEngine, schemaFormRegistrations } from '@schema-engine/forms-radiant';

export const engine = createRadiantFormEngine({ elements: schemaFormRegistrations });
```

It takes the options of `createFormEngine` and returns the same engine type. It prepends the canonical Radiant recipes (`radiantRecipes`) to the `recipes` you pass, so a recipe of yours with the same `$type` replaces a built-in one. It registers no element: pass `schemaFormRegistrations`, a subset or your own. [Engine and registrations](/docs/forms/engine) covers the options.

## FormRenderer

A view that renders a form with Radiant elements. It validates the config with the engine, so a plain config object or a normalized one both work.

| Prop               | Meaning                                                                                                                                               |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `engine`           | The form engine. A form that only renders on the client passes it here. See [Server rendering](/docs/forms-radiant/server-rendering) for the rest     |
| `config`           | A form config, or the result of `engine.defineForm` or `engine.validateForm`                                                                          |
| `defaultValues`    | Values the form starts from, typed from the config                                                                                                    |
| `onSubmit`         | Called with the values that passed validation, and `{ setServerErrors, fetch }`. Typed from the config                                                |
| `onChange`         | Called with the form's values when they change, never for a touch or an error                                                                         |
| `onAction`         | Called with each submit action that succeeded. Typed by the engine's actions                                                                          |
| `onActionResults`  | Called with the results of every trigger that ran actions, as in React. The same results reach the `se-action-results` event                          |
| `navigate`         | Takes the page to the `redirectUrl` a submit action set, once the whole submission succeeded. `location.assign` by default; it replaces a native post |
| `formatIssue`      | Words an issue for this renderer's forms. It wins over the engine's                                                                                   |
| `action`, `method` | A native post target. A form with them and no `onSubmit` posts natively after validation passes                                                       |
| `class`, `style`   | Styling for the host element                                                                                                                          |

### Events

A form announces what its actions and its submission did as bubbling, composed events on its `rui-form`, so a page with no `FormRenderer` callback, such as a form rendered on the server, can listen to them.

| Event                       | `detail`                                                        |
| --------------------------- | --------------------------------------------------------------- |
| `se-action-results`         | `{ trigger, results }` of every trigger that ran actions        |
| `se-action-submit-start`    | none: validation passed and the submit actions are about to run |
| `se-action-submit-invalid`  | `{ failures }`: empty when the fields have errors               |
| `se-action-submit-complete` | `{ succeeded, results, failures }` of the submit actions        |

`FormRendererElement` is the `se-form-renderer` custom element behind it. Assign `engine` to it, as a property, to bind a server-rendered form. `FormElement` from `@schema-engine/forms-radiant/primitives` is the view of one field.

## Registrations

`schemaFormRegistrations` lists the 18 element registrations of the package, in registration order: the one value for every element. Each is also exported by name from `@schema-engine/forms-radiant/registrations`: `InputElementRegistration`, `TextareaElementRegistration`, `NumberElementRegistration`, `SelectElementRegistration`, `CheckboxElementRegistration`, `CheckboxGroupElementRegistration`, `SwitchElementRegistration`, `RadioElementRegistration`, `SliderElementRegistration`, `ComboboxElementRegistration`, `DropZoneElementRegistration`, `FieldSetRegistration`, `InputOTPElementRegistration`, `PhoneInputElementRegistration`, `MaskedInputElementRegistration`, `ArrayElementRegistration`, `SubmitButtonElementRegistration` and `SubmissionAlertElementRegistration`. [Overview](/docs/forms-radiant/overview#what-ships) maps them to their `$type`.

Each registration loads only its own element. An engine built from a few of them bundles only those widgets, so naming `InputElementRegistration` alone leaves out the phone, masked and drop-zone inputs and the `libphonenumber-js` and `imask` libraries behind them. `schemaFormRegistrations` loads all 18. The built-in recipes always load, because `createRadiantFormEngine` registers them. [Register only some elements](/docs/forms-radiant/getting-started#register-only-some-elements) shows the import.

The schemas, metadata and value declarations of these elements are the default element contracts of [`@schema-engine/forms/default-elements`](/docs/forms/api-reference#default-element-contracts). Each registration spreads its contract into `defineInput` (`defineStatic` for the submit button and the submission alert) beside its Radiant component, as the registry items of Forms React do, so each shares the contract's `schema` by identity. The package adds only the Radiant component and, for the phone input, its own validation.

`createRadiantPhoneValidationRegistration()` takes no arguments and builds the `phone` rule registration, the default rule of `phone-input`. Its check loads `libphonenumber-js` the first time it runs and accepts an empty value or a valid phone number in international format (`+` and the country code). `PhoneInputElementRegistration` already carries it, so call it only for an engine that registers `phone-input` some other way.

## Recipes

`radiantRecipes` lists the canonical view recipes that `createRadiantFormEngine` binds: `CardRecipe`, `SplitScreenRecipe`, `HeroBackgroundRecipe`, `BareControlsRecipe`, `WizardRecipe`, `SidebarWizardRecipe`, `CardWizardRecipe`, `HeroWizardRecipe` and `SplitScreenWizardRecipe`. `defineRecipe` from `@schema-engine/forms-radiant/primitives` binds your own shell and slots to a recipe spec made with `defineRecipeSpec` from `@schema-engine/forms/recipes`; importing it loads none of the built-in recipes. The recipe a multi-step form without a `view` falls back to is `DEFAULT_WIZARD_RECIPE` from `@schema-engine/forms`. See [Layouts](/docs/forms-radiant/layouts).

## Controllers

`FormController` and `FormEngineController` give a custom element access to the form it sits in. [Overview](/docs/forms-radiant/overview#programmatic-form-access) describes them, and [Form controls](/docs/forms-radiant/form-controls) shows a custom control that uses the native events.

## Debugging

`FormDebugger` and `FormDebuggerElement` from `@schema-engine/forms-radiant/debugger` render a panel with the form's meta and state, for development. Render `FormDebugger` inside a `FormRenderer`, and load its styles with `@import '@schema-engine/forms-radiant/debugger.css';` after `index.css`. The root and `index.css` carry neither, so an app that does not debug ships no debugger.
