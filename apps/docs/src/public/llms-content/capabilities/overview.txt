# Capabilities

Capabilities describe what a form does. They are independent of the element
that collects a value and the recipe that lays out the form. Both the React and
Radiant adapters implement the same form configuration contracts.

| Capability       | Use it for                                                               | Start here                                                                        |
| ---------------- | ------------------------------------------------------------------------ | --------------------------------------------------------------------------------- |
| Constraints      | Show, hide, enable, disable, or require a field from another value       | [Contact form example](/docs/examples/contact-form)                               |
| Validation       | Required values, formats, ranges, and custom rules                       | [Validation](/docs/forms/validation)                                              |
| Actions          | Submit, reset, notifications, and ordered side effects                   | [Actions overview](/docs/actions/overview)                                        |
| Async validation | Debounced remote checks, dependency values, and failure handling         | [Async validation](/docs/forms/validation-how-it-works#enhanced-async-validation) |
| Async actions    | Pending, success, and failure states around a remote operation           | [Sequential actions example](/docs/examples/sequential-actions)                   |
| Dynamic fields   | Repeatable groups and nested field scopes                                | [Components](/docs/forms-react/components)                                        |
| Form state       | Values, field state, validity and submission, the same in both renderers | [Form state](/docs/forms/form-state)                                              |
| Wizard steps     | Next, back and jump, with steps skipped from earlier answers             | [Wizard and runtime](/docs/forms/wizard)                                          |
| Server errors    | Show a server's validation response on the fields it names               | [Server errors](/docs/forms/server-errors)                                        |
| Issue text       | Word every error and warning in your language                            | [Issue text](/docs/forms/issue-text)                                              |
| CSRF             | Send a token with the engine's requests and native posts                 | [CSRF](/docs/forms/csrf)                                                          |

## Constraints

Constraints are evaluated from the current form value. The support-ticket field
below is rendered by the server but initially hidden; selecting Technical
support reveals it without rebuilding the form tree.

```json
{
	"$type": "input",
	"name": "ticket",
	"label": "Support ticket number",
	"constraints": [{ "field": "subject", "operator": "equals", "value": "support", "action": "show" }]
}
```

Use `contains` for multi-value controls. A single selection is treated as its
selected scalar when evaluating `equals`.

## Adapter coverage

Storybook keeps cross-adapter behavior examples under `Capabilities/*`:
Radiant and React each include built-in Validation, Async Username
Availability, Constraints, and Actions stories. The Actions story includes the
asynchronous submit lifecycle. `Recipes/*` is reserved for layout shells.
