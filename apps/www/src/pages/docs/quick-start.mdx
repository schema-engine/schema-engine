# Quick Start

Build your first form with Form Engine in just a few steps. This guide assumes you have already [installed Form Engine](/docs/installation).

## Understanding the Builder Pattern

Form Engine uses a **Builder Pattern** to configure and instantiate the form engine. This approach provides:

- **Type Safety**: Full TypeScript support with autocomplete
- **Explicit Configuration**: See exactly what's registered
- **Tree-Shaking**: Only bundle what you use
- **Flexibility**: Easy to add custom components

Learn more about the [Builder Pattern](/docs/builder).

## Your First Form

Let's create a simple contact form to demonstrate the core concepts.

### 1. Create Your Form Engine

First, create a form engine instance with the components you need:

```typescript
// lib/form-engine.ts
import { createReactFormEngine } from '@schema-engine/forms-react/registries/builder-registry';
import {
	InputElement,
	TextareaElement,
	SelectElement,
	CardLayoutRegistration,
} from '@schema-engine/forms-react/registrations';

export const formEngine = createReactFormEngine()
	.addElement(InputElement)
	.addElement(TextareaElement)
	.addElement(SelectElement)
	.addLayout(CardLayoutRegistration)
	.build();
```

### 2. Create the Form Configuration

Define your form structure using a JSON configuration:

```typescript
// components/contact-form.tsx

import { formEngine } from './lib/form-engine';

const contactFormConfig: FormConfig = {
	id: 'contact-form',
	title: 'Get In Touch',
	description: 'We would love to hear from you. Send us a message',
	mode: 'free',
	steps: [
		{
			id: 'contact-details',
			title: 'Contact Information',
			elements: [
				{
					id: 'input',
					inputType: 'text',
					id: 'firstName',
					name: 'firstName',
					label: 'First Name',
					placeholder: 'Enter your first name',
					rules: [{ type: 'required', message: 'First name is required' }],
				},
				{
					id: 'input',
					inputType: 'text',
					id: 'lastName',
					name: 'lastName',
					label: 'Last Name',
					placeholder: 'Enter your last name',
					rules: [{ type: 'required', message: 'Last name is required' }],
				},
				{
					id: 'input',
					inputType: 'email',
					id: 'email',
					name: 'email',
					label: 'Email Address',
					placeholder: 'your.email@example.com',
					rules: [
						{ type: 'required', message: 'Email is required' },
						{ type: 'email', message: 'Please enter a valid email address' },
					],
				},
				{
					id: 'select',
					id: 'subject',
					name: 'subject',
					label: 'Subject',
					placeholder: 'Choose a subject',
					options: [
						{ value: 'general', label: 'General Inquiry' },
						{ value: 'support', label: 'Technical Support' },
						{ value: 'billing', label: 'Billing Question' },
						{ value: 'feature', label: 'Feature Request' },
					],
					rules: [{ type: 'required', message: 'Please select a subject' }],
				},
				{
					id: 'select',
					id: 'priority',
					name: 'priority',
					label: 'Priority Level',
					options: [
						{ value: 'low', label: 'Low' },
						{ value: 'medium', label: 'Medium' },
						{ value: 'high', label: 'High' },
					],
					constraints: [
						{
							field: 'subject',
							operator: 'equals',
							value: 'support',
							action: 'show',
						},
					],
				},
				{
					id: 'textarea',
					id: 'message',
					name: 'message',
					label: 'Message',
					placeholder: 'Tell us more about your inquiry...',
					rows: 4,
					rules: [
						{ type: 'required', message: 'Message is required' },
						{ type: 'minLength', value: 10, message: 'Message must be at least 10 characters' },
					],
				},
			],
		},
	],
};
```

## Understanding the Architecture

Form Engine uses a **clean, simple API** with a powerful adapter system under the hood:

- **Single Component**: Use `FormRenderer` for all your forms
- **Adapter Architecture**: Currently uses React Hook Form, designed to support TanStack Form, Formik, and others
- **Constraint Logic**: Dynamic field behavior through JSON configuration, optimized for each form library
- **Type Safety**: Full TypeScript support with automatic type inference
- **Future-Proof**: Add new form library support without changing your form configurations
- **Tree-Shakable**: Import only the components you need

## Understanding Constraint Logic

Notice the `priority` field in our example includes a `constraints` array:

```json
{
	"id": "priority",
	"name": "priority",
	"id": "select",
	"label": "Priority Level",
	"constraints": [
		{
			"field": "subject",
			"operator": "equals",
			"value": "support",
			"action": "show"
		}
	]
}
```

This creates **conditional logic** where:

- The priority field is only **shown** when the subject field equals "support"
- Users only see priority options for technical support requests
- The field automatically hides/shows as users change the subject

Available constraint operators: `equals`, `not_equals`, `contains`, `not_contains`, `greater_than`, `less_than`, `is_empty`, `is_not_empty`

Available constraint actions: `show`, `hide`, `enable`, `disable`, `require`

## Understanding the Structure

Let's break down the key parts of the form configuration:

### Form Config Structure

```typescript
interface FormConfig {
	id: string; // Unique identifier
	title?: string; // Form title
	description?: string; // Form description
	steps: StepConfig[]; // Form steps (even single-step forms need this)
}
```

### Step Configuration

```typescript
interface StepConfig {
	id: string; // Step identifier
	title?: string; // Step title
	elements: FieldConfig[]; // Fields in this step
}
```

### Field Configuration

```typescript
interface FieldConfig {
	type: string; // Field type (input, select, textarea, etc.)
	id: string; // DOM element ID
	name: string; // Form field name
	label?: string; // Field label
	placeholder?: string; // Placeholder text
	validation?: ValidationRule[]; // Validation rules
	// ... type-specific properties
}
```

## Adding Validation

Form Engine uses a declarative validation system. Here are common validation rules:

```typescript
// Required field
rules: [{ type: 'required', message: 'This field is required' }];

// Email validation
rules: [
	{ type: 'required', message: 'Email is required' },
	{ type: 'email', message: 'Please enter a valid email' },
];

// Length validation
rules: [
	{ type: 'minLength', value: 3, message: 'Must be at least 3 characters' },
	{ type: 'maxLength', value: 100, message: 'Must be less than 100 characters' },
];

// Pattern validation
rules: [
	{
		type: 'pattern',
		value: /^[A-Za-z\s]+$/,
		message: 'Only letters and spaces allowed',
	},
];
```

## Custom Field Registration

You can register your own custom field components:

```typescript
import { defaultFormRegistry } from '@/lib/form-engine';

// Create a custom component
const CustomRatingField = ({ config, value, onChange, error }) => {
  return (
    <div>
      <label>{config.label}</label>
      <div className="flex gap-1">
        {[1, 2, 3, 4, 5].map(rating => (
          <button
            key={rating}
            type="button"
            onClick={() => onChange(rating)}
            className={value >= rating ? "text-yellow-500" : "text-gray-300"}
          >
            ★
          </button>
        ))}
      </div>
      {error && <span className="text-red-500 text-sm">{error}</span>}
    </div>
  );
};

// Register the custom field
defaultFormRegistry.register({
  name: 'rating',
  component: CustomRatingField,
  category: 'input',
  description: 'Star rating field'
});

// Use in your form config
{
  type: 'rating',
  id: 'satisfaction',
  name: 'satisfaction',
  label: 'Rate your experience',
  rules: [
    { type: 'required', message: 'Please provide a rating' }
  ]
}
```
