# How Components Work

Form Engine's component system is built around a simple but powerful idea: **bring your own components**. Instead of forcing you to use our components or rebuild your UI, Form Engine provides a registration system that wraps your existing components with form-aware functionality.

The **adapter architecture** ensures your registered components work seamlessly with any form library we support, starting with React Hook Form and designed for TanStack Form, Formik, and others.

## The Registration System

At its core, the registration system does three things:

1. **Takes your existing components** (inputs, selects, checkboxes, etc.)
2. **Wraps them with form logic** (validation, state management, constraint evaluation)
3. **Makes them available** to the FormRenderer through a type-safe registry that works with any form library adapter

## Adapter-Aware Component Wrapping

With the adapter system, components are automatically wrapped with the appropriate form library hooks:

## The Adapter Integration

The adapter system provides automatic integration with different form libraries:

### Current Implementation (React Hook Form)
- **`useAdapterControlledFormElement`** - Uses React Hook Form's `useController` for optimal performance
- **`useConstraintLogic`** - Leverages React Hook Form's `useWatch` for efficient constraint evaluation
- **`combineHandlers`** - Utility to combine your event handlers with Form Engine's

### Future Form Library Support
The architecture is designed to easily support:
- **TanStack Form** - Modern form library with excellent TypeScript support
- **Formik** - Popular form library with wide ecosystem
- **Custom Libraries** - Easy to add adapters for any form library
- **`FieldGroup`** - Wrapper component that handles labels, errors, and accessibility
- **Grid positioning** - Automatic layout within the responsive grid system

### Real Implementation Pattern

Here's how the actual `TextareaField` component works:

```typescript
import { Textarea } from '@/components/ui/textarea';
import { FieldGroup } from '@/lib/form-engine/components/form/field-group';
import { useControlledFormElement, combineHandlers } from '@/lib/form-engine/hooks';
import type { TextareaFieldConfig } from '@/lib/form-engine/types/form';

interface TextareaFieldProps {
  config: TextareaFieldConfig;
  onChange?: (value: string) => void;
  onBlur?: () => void;
}

export function TextareaField({ config, onChange: propsOnChange, onBlur: propsOnBlur }: TextareaFieldProps) {
  // This hook provides everything you need
  const { value, error, onChange, onBlur, fieldProps, isRequired, containerStyles } =
    useControlledFormElement(config);

  return (
    <div style={containerStyles}>
      <FieldGroup
        label={config.label || config.name}
        htmlFor={config.id}
        hiddenLabel={!config.label}
        required={isRequired}
        error={error}
      >
        {config.description && (
          <p className="text-sm text-muted-foreground mb-2">
            {config.description}
          </p>
        )}
        <Textarea
          {...fieldProps}
          value={value || ''}
          onChange={(e) => combineHandlers(onChange, propsOnChange)(e.target.value)}
          onBlur={combineHandlers(onBlur, propsOnBlur)}
          placeholder={config.placeholder}
          rows={config.rows}
          maxLength={config.maxLength}
          minLength={config.minLength}
          className={`${config.className || ''} resize-${config.resize || 'both'}`}
          style={config.style}
        />
      </FieldGroup>
    </div>
  );
}
```

## Component Interface

The `useControlledFormElement` hook provides everything your component needs:

```typescript
// What the hook returns
interface ControlledFormElementReturn {
  // Current field value
  value: any;
  // Validation error message
  error?: string;
  // Change handler for the field
  onChange: (value: any) => void;
  // Blur handler for the field
  onBlur: () => void;
  // Standard field props (id, name, etc.)
  fieldProps: {
    id: string;
    name: string;
  };
  // Whether field is required
  isRequired: boolean;
  // Grid positioning styles
  containerStyles: React.CSSProperties;
}

// Your component props interface
interface YourFieldProps {
  config: FieldConfig; // The field configuration
  onChange?: (value: any) => void; // Optional external handler
  onBlur?: () => void; // Optional external handler
}
```

The `FieldGroup` component handles the common UI patterns:
- Label display and accessibility
- Required field indicators
- Error message display  
- Proper form semantics

## Integration with React Hook Form

Under the hood, Form Engine uses React Hook Form for state management. Your components automatically get:

- **Optimized re-renders** - Only update when necessary
- **Uncontrolled inputs** - Better performance with large forms
- **Built-in validation** - Integrated with Zod schemas
- **Form submission** - Automatic data collection and validation

```typescript
// This happens automatically when you register a component
function FieldWrapper({ component: Component, config, ...props }) {
  const { 
    field,           // { value, onChange, onBlur, name }
    fieldState,      // { error, invalid, isDirty, isTouched }
    formState        // { isSubmitting, isValid, errors }
  } = useController({
    name: config.name,
    control: formContext.control,
    rules: convertZodToRules(config.rules)
  });

  return (
    <Component
      {...props}
      {...field}
      error={fieldState.error?.message}
      isInvalid={fieldState.invalid}
      config={config}
      formContext={formContext}
    />
  );
}
```

## Responsive Grid Integration

Every component automatically participates in Form Engine's responsive grid system:

```typescript
const responsiveField = {
  componentId: 'input',
  id: 'description',
  label: 'Description',
  
  // Responsive grid positioning
  grid: {
    column: { xs: 12, md: 8 },    // Full width on mobile, 8/12 on desktop
    row: { xs: 2, md: 1 }         // Row 2 on mobile, row 1 on desktop
  }
};
```

The grid system handles:
- **Responsive breakpoints** (xs, sm, md, lg, xl)
- **Automatic column calculation** based on content
- **Row and column spanning**
- **Gap management** and spacing

## Type Safety

The registration system is fully type-safe. When you register a component, TypeScript knows:

```typescript
// TypeScript knows about your registered components
type RegisteredFieldTypes = 'input' | 'textarea' | 'select' | 'checkbox';

// Field configurations are typed based on the component
interface InputFieldConfig extends BaseFieldConfig {
  type: 'input';
  inputType: 'text' | 'email' | 'password' | 'number';
  placeholder?: string;
  maxLength?: number;
}

// Form configurations get full type checking
const typedForm: FormConfig = {
  elements: [
    {
      componentId: 'input',           // Valid
      inputType: 'email',      // Valid  
      placeholder: 'Enter...' // Valid
      // invalid: 'property'   // TypeScript error
    }
  ]
};
```
