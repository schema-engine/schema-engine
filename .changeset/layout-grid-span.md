An element can size itself in tracks with `grid: { span: n }` (`ElementGridConfig.span`, also in `responsive`), and a grid can pack its items with `autoFlow: 'row' | 'dense'` (`GridLayoutConfig.autoFlow`, top level only). A span compiles to `span min(n, var(--se-grid-track-count, 1))`, so it never passes the tracks the grid has and never makes an implicit column. The grid publishes its track count beside its template as `--se-grid-tracks[-slot]` (`columns: n` gives `n`, named widths 12, `areas` the row length, `columns: 'auto'` one), the stylesheet resolves it through the same gated cascade as the template, so the clamp changes at the width the tracks do in a media theme and in a container theme, and a subgrid inherits its parent's resolved count. `columns: 'auto'` cannot clamp a span in CSS (its track count is not computable), so a span there is one track; give the grid `columns` per breakpoint, with a container theme, instead. The stylesheet grows by about 620 bytes (80 gzipped) in every theme, one more row in the grid rule's property table plus `grid-auto-flow`; existing layouts render the same. New exports `spanPlacementIssue` (a span beside `width`, `offset`, `column` or `area` in one slot) and `gridSpanIssues` (a span under `columns: 'auto'`); a subgrid now also rejects `span`.

`subgridPlacementIssue` now names `responsive.default` when the conflicting key is written there, instead of the top-level key.
