'@schema-engine/forms': patch

Add the `@schema-engine/forms/default-elements` entry, which holds the contract of each of the 18 default elements: `input`, `textarea`, `number`, `select`, `checkbox`, `checkbox-group`, `switch`, `radio`, `slider`, `combobox`, `drop-zone`, `fieldSet`, `input-otp`, `phone-input`, `masked-input`, `arrayElements`, `submit` and `submission-alert`. A contract (`CheckboxElementContract`) is an element registration without `render` and `validations`: its `$type`, schema, metadata, value declaration, container kind and appearance axes, so every renderer of an element agrees on them. The entry also exports each element's schema, types and `xFieldValue` declaration (`CheckboxFieldConfigSchema`, `CheckboxFieldConfig`, `checkboxFieldValue`, and so on, the same names the renderers exported until now), `defaultElementContracts` (a registry of all of them, built with `createRegistry` and `duplicates: 'error'`), and the types `ElementBindings`, `ElementBinding`, `InputContract` and `StaticContract`. A renderer binds `render` to a contract with `defineInput({ ...CheckboxElementContract, render })`, or binds every contract at once with `bindRegistry(defaultElementContracts, bindings)` from `@schema-engine/registry`, with `bindings satisfies ElementBindings<typeof defaultElementContracts>` checking each `render` against its own schema.

Where the two renderers had drifted, the contract is the one both now share: the `masked-input` value accepts text, a number or a date with `unmask: 'typed'` (it was text only in Radiant), the `input-otp` completeness rule is `^.{length}$` (the pattern rule skips an empty value, so an empty optional code stays valid), the `arrayElements` `initialValues` record holds `unknown` (the shadcn copy held `any`), the slider value falls back to the bounds 0 and 100, and each element has one `metadata` name and description (`OTP Input`, `Masked Input`, `Phone Input`, and the longer descriptions of the shadcn copies).
