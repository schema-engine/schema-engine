# Conditional Logic

Form Engine provides a powerful constraint system that enables dynamic, interactive forms where fields can show, hide, enable, disable, or become required based on user input. This creates intelligent forms that adapt to user responses and guide them through complex workflows.

## Constraint System Overview

The constraint system uses a declarative approach where you define rules that watch other fields and take actions based on their values:

```typescript
interface ConstraintLogic {
  field: string;                    // Field to watch
  operator: ConstraintOperator;     // Comparison operator
  value?: any;                      // Value to compare against (optional for some operators)
  action: ConstraintAction;         // Action to take when condition is met
}
```

### Basic Constraint Example

```typescript
{
  type: "input",
  name: "businessName",
  label: "Business Name",
  constraints: [
    {
      field: "accountType",         // Watch the accountType field
      operator: "equals",           // When accountType equals
      value: "business",            // the value "business"
      action: "show"                // show this field
    }
  ]
}
```

## Constraint Operators

Form Engine supports a comprehensive set of operators for different data types:

### Equality Operators

```typescript
// Exact match
{
  field: "userType",
  operator: "equals",
  value: "admin",
  action: "show"
}

// Not equal
{
  field: "status",
  operator: "not_equals", 
  value: "inactive",
  action: "enable"
}
```

### Content Operators

```typescript
// Contains substring
{
  field: "email",
  operator: "contains",
  value: "@company.com",
  action: "show"
}

// Does not contain
{
  field: "username",
  operator: "not_contains",
  value: "admin",
  action: "enable"
}
```

### Comparison Operators

```typescript
// Numeric comparisons
{
  field: "age",
  operator: "greater_than",
  value: 18,
  action: "show"
}

{
  field: "score",
  operator: "less_than",
  value: 50,
  action: "require"
}

{
  field: "quantity",
  operator: "greater_than_or_equal",
  value: 10,
  action: "show"
}

// Date comparisons
{
  field: "startDate",
  operator: "less_than",
  value: "today",
  action: "hide"
}
```

### Existence Operators

```typescript
// Field has value
{
  field: "firstName",
  operator: "is_not_empty",
  action: "show"
}

// Field is empty
{
  field: "middleName",
  operator: "is_empty",
  action: "hide"
}
```

### Array Operators

```typescript
// Array contains item
{
  field: "skills",
  operator: "includes",
  value: "JavaScript",
  action: "show"
}

// Array length
{
  field: "contacts",
  operator: "length_greater_than",
  value: 0,
  action: "enable"
}
```

## Constraint Actions

Define what happens when a constraint condition is met:

### Visibility Actions

```typescript
// Show field when condition is met
{
  field: "accountType",
  operator: "equals",
  value: "business",
  action: "show"
}

// Hide field when condition is met
{
  field: "personalInfo",
  operator: "equals", 
  value: "business",
  action: "hide"
}
```

### Interaction Actions

```typescript
// Enable field interaction
{
  field: "hasExperience",
  operator: "equals",
  value: true,
  action: "enable"
}

// Disable field interaction
{
  field: "autoMode",
  operator: "equals",
  value: true,
  action: "disable"
}
```

### Validation Actions

```typescript
// Make field required
{
  field: "accountType",
  operator: "equals",
  value: "business",
  action: "require"
}

// Make field optional (remove required validation)

  operator: "equals",

  action: "optional"
}
```

## Multiple Constraints

Fields can have multiple constraints that work together using AND logic:

```typescript
{
  type: "input",
  name: "businessTaxId",
  label: "Business Tax ID",
  constraints: [
    {
      field: "accountType",
      operator: "equals",
      value: "business",
      action: "show"
    },
    {
      field: "country",
      operator: "equals",
      value: "US",
      action: "show"
    },
    {
      field: "revenue",
      operator: "greater_than",
      value: 100000,
      action: "require"
    }
  ]
  // Field is shown only when accountType is "business" AND country is "US"
  // Field is required only when revenue > 100000 (in addition to show conditions)
}
```

## Conditional Validation

Create validation rules that depend on form state:

```typescript
// Password confirmation that's only required when password is provided
{
  type: "input",
  name: "confirmPassword",
  label: "Confirm Password",
  inputType: "password",
  constraints: [
    {
      field: "password",
      operator: "is_not_empty",
      action: "show"
    },
    {
      field: "password",
      operator: "is_not_empty", 
      action: "require"
    }
  ],
  validation: [
    {
      type: "custom",
      message: "Passwords must match",
      validator: (value, formData) => {
        return !formData.password || value === formData.password;
      }
    }
  ]
}

// Business fields required only for business accounts
{
  type: "input",
  name: "companyName",
  label: "Company Name",
  constraints: [
    {
      field: "accountType",
      operator: "equals",
      value: "business",
      action: "show"
    },
    {
      field: "accountType",
      operator: "equals",
      value: "business",
      action: "require"
    }
  ]
}
```

## Dynamic Field Options

Update field options based on other field values:

```typescript
// This requires custom implementation, but here's the pattern:
{
  type: "select",
  name: "state",
  label: "State",
  options: [], // Will be populated dynamically
  constraints: [
    {
      field: "country",
      operator: "is_not_empty",
      action: "show"
    }
  ]
}

// In your component:
function DynamicOptionsForm() {
  const [stateOptions, setStateOptions] = useState([]);
  
  const handleFormChange = (formData) => {
    if (formData.country) {
      // Update state options based on selected country
      const newStateOptions = getStatesForCountry(formData.country);
      setStateOptions(newStateOptions);
    }
  };
  
  const formConfigWithDynamicOptions = {
    ...baseFormConfig,
    steps: baseFormConfig.steps.map(step => ({
      ...step,
      fields: step.fields.map(field => 
        field.name === 'state' 
          ? { ...field, options: stateOptions }
          : field
      )
    }))
  };
  
  return (
    <FormRenderer
      config={formConfigWithDynamicOptions}
      onChange={handleFormChange}
      onSubmit={handleSubmit}
    />
  );
}
```

## Performance Optimization

Optimize constraint evaluation for large forms:

```typescript
// Group constraints by watched field to minimize re-evaluations
const optimizedConstraints = useMemo(() => {
  const grouped = {};
  allConstraints.forEach(constraint => {
    if (!grouped[constraint.field]) {
      grouped[constraint.field] = [];
    }
    grouped[constraint.field].push(constraint);
  });
  return grouped;
}, [allConstraints]);

// Only watch fields that have constraints
const watchedFields = Object.keys(optimizedConstraints);
const watchedValues = useWatch({ name: watchedFields });
```

## Testing Conditional Logic

Test your constraint logic thoroughly:

```typescript
// Test constraint evaluation
import { evaluateConstraints } from "@/lib/form-engine";

describe('Form Constraints', () => {
  it('shows business fields for business account type', () => {
    const constraints = [
      {
        field: "accountType",
        operator: "equals",
        value: "business",
        action: "show"
      }
    ];
    
    const formData = { accountType: "business" };
    const result = evaluateConstraints(constraints, formData);
    
    expect(result.isVisible).toBe(true);
  });

  it('hides business fields for personal account type', () => {
    const constraints = [
      {
        field: "accountType",
        operator: "equals",
        value: "business",
        action: "show"
      }
    ];
    
    const formData = { accountType: "personal" };
    const result = evaluateConstraints(constraints, formData);
    
    expect(result.isVisible).toBe(false);
  });
});
```
