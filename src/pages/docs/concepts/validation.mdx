# Validation

Form Engine provides a powerful, declarative validation system that automatically generates Zod schemas from your validation rules. This approach ensures type safety while eliminating the need to write validation schemas manually.

## Validation Philosophy

### Single Source of Truth

Define validation rules once in your field configuration - Zod schemas are automatically generated:

```typescript
// Define validation rules in configuration
{
  type: "input",
  name: "email",
  label: "Email Address",
  validation: [
    { type: "required", message: "Email is required" },
    { type: "email", message: "Please enter a valid email" },
    { type: "minLength", value: 5, message: "Email too short" }
  ]
}

// Automatically becomes this Zod schema:
z.string()
  .min(1, "Email is required")
  .email("Please enter a valid email")
  .min(5, "Email too short")
```

### Runtime Safety

All validation happens at runtime with proper error handling and type inference.

## Custom Validation

Create custom validation logic for complex requirements:

### Simple Custom Validation

```typescript
{
  type: "custom",
  message: "Password must contain at least one number",
  validator: (value) => {
    return /\d/.test(value);
  }
}
```

### Advanced Custom Validation

```typescript
{
  type: "custom",
  message: "Passwords must match",
  validator: (value, formData) => {
    return value === formData.password;
  }
}

// Async validation
{
  type: "custom",
  message: "Username is already taken",
  validator: async (value) => {
    const response = await fetch(`/api/check-username?username=${value}`);
    const { available } = await response.json();
    return available;
  }
}

// Complex validation with context
{
  type: "custom",
  message: "End date must be after start date",
  validator: (value, formData, fieldConfig) => {
    if (!formData.startDate || !value) return true;
    
    const startDate = new Date(formData.startDate);
    const endDate = new Date(value);
    
    return endDate > startDate;
  }
}
```

### Conditional Validation

Validation rules that depend on other fields:

```typescript
{
  type: "custom",
  message: "This field is required when account type is business",
  validator: (value, formData) => {
    if (formData.accountType === "business") {
      return value && value.trim().length > 0;
    }
    return true; // Not required for other account types
  }
}
```

## Schema Generation

Form Engine automatically generates Zod schemas from your validation rules:

### Automatic Generation

```typescript
const formConfig = {
  id: "example-form",
  autoGenerateSchema: true,  // Enable automatic schema generation
  steps: [
    {
      title: "User Info",
      fields: [
        {
          type: "input",
          name: "email",
          validation: [
            { type: "required" },
            { type: "email" }
          ]
        },
        {
          type: "number",
          name: "age",
          validation: [
            { type: "required" },
            { type: "min", value: 18 },
            { type: "max", value: 120 }
          ]
        }
      ]
    }
  ]
};

// Automatically generates:
const schema = z.object({
  email: z.string().min(1).email(),
  age: z.number().min(18).max(120)
});
```

### Manual Schema Override

For complex cases, provide your own schema:

```typescript
import { z } from 'zod';

const customSchema = z.object({
  email: z.string().email(),
  age: z.number().min(18),
  // Complex nested validation
  address: z.object({
    street: z.string().min(5),
    city: z.string().min(2),
    zipCode: z.string().regex(/^\d{5}(-\d{4})?$/)
  })
});

const formConfig = {
  id: "custom-schema-form",
  validationSchema: customSchema,  // Use custom schema
  steps: [/* ... */]
};
```

## Error Handling

Comprehensive error handling and display:

### Error Messages

```typescript
// Custom error messages
{
  type: "email",
  message: "Oops! That doesn't look like a valid email address."
}

// Dynamic error messages
{
  type: "custom",
  message: (value, formData) => {
    return `Password must be at least 8 characters, got ${value?.length || 0}`;
  },
  validator: (value) => value && value.length >= 8
}

// Internationalized messages
{
  type: "required",
  message: {
    en: "This field is required",
    es: "Este campo es obligatorio",
    fr: "Ce champ est requis"
  }
}
```

### Error Display

```typescript

  name: "email",
  validation: [{ type: "email" }],
  errorDisplay: {
    position: "bottom",      // "bottom" | "top" | "inline"
    style: "tooltip",        // "tooltip" | "text" | "icon"
    showIcon: true,          // Show error icon
    animate: true            // Animate error appearance
  }
```

## Validation Examples

### Registration Form Validation

```typescript
const registrationFormConfig = {
  id: "registration",
  autoGenerateSchema: true,
  steps: [
    {
      title: "Account Information",
      fields: [
        {
          type: "input",
          name: "username",
          label: "Username",
          validation: [
            { type: "required", message: "Username is required" },
            { type: "minLength", value: 3, message: "Username must be at least 3 characters" },
            { type: "maxLength", value: 20, message: "Username cannot exceed 20 characters" },
            { 
              type: "pattern", 
              value: "^[a-zA-Z0-9_]+$",
              message: "Username can only contain letters, numbers, and underscores"
            },
            {
              type: "custom",
              message: "This username is already taken",
              validator: async (value) => {
                if (!value || value.length < 3) return true;
                const response = await fetch(`/api/check-username?username=${value}`);
                const { available } = await response.json();
                return available;
              }
            }
          ]
        },
        {
          type: "input",
          name: "email",
          label: "Email Address",
          inputType: "email",
          validation: [
            { type: "required", message: "Email is required" },
            { type: "email", message: "Please enter a valid email address" },
            {
              type: "custom",
              message: "This email is already registered",
              validator: async (value) => {
                if (!value || !value.includes('@')) return true;
                const response = await fetch(`/api/check-email?email=${value}`);
                const { available } = await response.json();
                return available;
              }
            }
          ]
        },
        {
          type: "input",
          name: "password",
          label: "Password",
          inputType: "password",
          validation: [
            { type: "required", message: "Password is required" },
            { type: "minLength", value: 8, message: "Password must be at least 8 characters" },
            {
              type: "custom",
              message: "Password must contain uppercase, lowercase, number, and special character",
              validator: (value) => {
                if (!value) return false;
                const hasUpper = /[A-Z]/.test(value);
                const hasLower = /[a-z]/.test(value);
                const hasNumber = /\d/.test(value);
                const hasSpecial = /[!@#$%^&*(),.?":{}|<>]/.test(value);
                return hasUpper && hasLower && hasNumber && hasSpecial;
              }
            }
          ]
        },
        {
          type: "input",
          name: "confirmPassword",
          label: "Confirm Password",
          inputType: "password",
          validation: [
            { type: "required", message: "Please confirm your password" },
            {
              type: "custom",
              message: "Passwords must match",
              validator: (value, formData) => {
                return value === formData.password;
              }
            }
          ]
        }
      ]
    }
  ]
};
```

## Best Practices

### 1. Use Appropriate Validation Levels

```typescript
// ✅ Start with basic validation
{ type: "required" }
{ type: "email" }

// ✅ Add format validation
{ type: "minLength", value: 8 }
{ type: "pattern", value: "^[A-Z]" }

// ✅ Use custom validation for complex rules
{
  type: "custom",
  validator: (value, formData) => complexBusinessLogic(value, formData)
}
```

### 2. Provide Clear Error Messages

```typescript
// ❌ Generic error
{ type: "minLength", value: 8, message: "Invalid input" }

// ✅ Specific, helpful error
{ type: "minLength", value: 8, message: "Password must be at least 8 characters long" }
```

### 3. Consider User Experience

```typescript
// ✅ Don't validate on every keystroke for expensive operations
{
  type: "custom",
  validator: expensiveAsyncValidator,
  timing: "onBlur"  // Only validate when user leaves field
}

// ✅ Provide immediate feedback for format issues
{
  type: "email",
  timing: "onChange"  // Immediate feedback for email format
}
```

### 4. Handle Edge Cases

```typescript
// ✅ Graceful handling of null/undefined
{
  type: "custom",
  validator: (value) => {
    if (!value) return true; // Allow empty (handle with required separately)
    return value.length >= 3;
  }
}
```

Form Engine's validation system provides the flexibility to handle simple format validation to complex business rules while maintaining type safety and excellent user experience.
