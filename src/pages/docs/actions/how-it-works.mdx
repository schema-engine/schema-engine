# How Actions Work

Actions handle what happens when users interact with your forms - submissions, resets, notifications, and more. The system uses plugins that you register when needed.

## Basic Setup

Actions work through a registry system. You register plugins, then define actions in your form config:

```typescript
import { registerAction } from '@/lib/form-engine/actions/action-registry';
import { submitPlugin, notificationPlugin } from '@/lib/form-engine/actions/plugins';
import type { FormConfig } from '@/lib/form-engine/types';

// Register the plugins you need
registerAction(submitPlugin({
  onSuccess: (data, context) => {
    console.log('Form submitted:', data);
  },
  onError: (error, context) => {
    console.error('Submit failed:', error);
  }
}));

registerAction(notificationPlugin({
  onSuccess: (message) => alert(message),
  onError: (message) => alert(message)
}));

// Define actions in your form config
const contactForm: FormConfig = {
  id: 'contact-form',
  title: 'Contact Us',
  steps: [
    {
      id: 'contact-step',
      title: 'Your Details',
      elements: [
        {
          componentId: 'input',
          inputType: 'email',
          id: 'email',
          name: 'email',
          label: 'Email'
        }
      ]
    }
  ],
  actions: [
    {
      id: 'submit-form',
      type: 'submit',
      endpoint: '/api/contact',
      method: 'POST'
    },
    {
      id: 'success-notification',
      type: 'show_notification',
      message: 'Thanks for contacting us!',
      variant: 'success',
      triggers: ['submit_success'] // Only show after successful submit
    }
  ]
};
```

## Available Triggers

Actions respond to specific events. Here are the actual triggers you can use:

### Form Events
- **`form_start`** - Form initialization  
- **`form_change`** - Any field changes
- **`form_submit`** - Form submission starts

### Submit Events  
- **`submit_start`** - Submit begins (internal)
- **`submit_success`** - Submit succeeded (internal)
- **`submit_error`** - Submit failed (internal)
- **`submit_complete`** - Submit finished (internal)

### Multi-step Events
- **`step_change`** - Navigation between steps
- **`step_submit`** - Step submission
- **`step_enter`** - Entering a step
- **`step_leave`** - Leaving a step  
- **`step_view`** - Step becomes visible

### Manual Events
- **`manual_save`** - User clicks save
- **`manual_reset`** - User clicks reset

## Plugin Configuration

Plugins accept configuration to customize behavior:

```typescript
import { registerAction } from '@/lib/form-engine/actions/action-registry';
import { submitPlugin, notificationPlugin } from '@/lib/form-engine/actions/plugins';

// Configure submit behavior
registerAction(submitPlugin({
  // Custom request handling
  request: async (url, options) => {
    return fetch(url, {
      ...options,
      headers: {
        ...options.headers,
        'Authorization': 'Bearer ' + getAuthToken()
      }
    });
  },
  
  // Transform data before sending
  transformData: (data, context) => ({
    ...data,
    timestamp: new Date().toISOString(),
    formId: context.formId
  }),
  
  // Success callback
  onSuccess: (data, context) => {
    console.log('Form submitted:', data);
    gtag('event', 'form_submit', { form_id: context.formId });
  },
  
  // Error callback  
  onError: (error, context) => {
    console.error('Submit failed:', error);
    // Could send to error tracking service
  }
}));

// Configure notifications
registerAction(notificationPlugin({
  onSuccess: (message) => toast.success(message),
  onError: (message) => toast.error(message),
  onWarning: (message) => toast.warning(message)
}));
```

## How It Works Internally

When a form event occurs (like submission), the FormEngine:

1. **Finds matching actions** - Looks for actions with matching triggers
2. **Validates configuration** - Uses Zod schemas to validate action config  
3. **Executes sequentially** - Runs actions one after another
4. **Handles results** - Processes success/error outcomes
5. **Triggers follow-up** - May trigger additional actions (like `submit_success`)

```typescript
// Example: Form submission flow
// 1. User clicks submit
// 2. FormEngine finds actions with 'form_submit' trigger  
// 3. Executes submit action
// 4. On success, triggers 'submit_success' actions
// 5. Notification and reset actions run

const executionFlow = {
  'form_submit': ['submit-form'],           // Submit to API
  'submit_success': ['show-notification', 'reset-form'], // Follow-up actions
  'submit_error': ['show-error']            // Error handling
};
```

## Creating Custom Actions

You can create your own action types by registering custom handlers:

```typescript
import { registerAction } from '@/lib/form-engine/actions/action-registry';
import { z } from 'zod';

// Define your action schema
const MyActionSchema = z.object({
  id: z.string(),
  type: z.literal('my_action'),
  customProperty: z.string(),
  enabled: z.boolean().default(true)
});

// Register the action handler
registerAction({
  type: 'my_action',
  schema: MyActionSchema,
  defaultTriggers: ['form_submit'],
  handler: async (action, context) => {
    console.log('Custom action executed!', {
      action: action.customProperty,
      formId: context.formId,
      formData: context.formData
    });
    
    // Do your custom logic here
    
    return {
      success: true,
      message: 'Custom action completed'
    };
  }
});

// Use in form config
const formWithCustomAction: FormConfig = {
  actions: [
    {
      id: 'my-custom-action',
      type: 'my_action',
      customProperty: 'Hello World'
    }
  ]
};
```

## Execution Order

Actions execute sequentially in the order they're defined. This prevents race conditions and ensures predictable behavior:

```typescript
// Actions run in order
const formConfig: FormConfig = {
  actions: [
    { id: 'submit-form', type: 'submit', endpoint: '/api/submit' },
    { id: 'show-success', type: 'show_notification', triggers: ['submit_success'] },
    { id: 'reset-form', type: 'reset', triggers: ['submit_success'] }
  ]
};

// Execution flow:
// 1. Submit action runs first
// 2. If successful, triggers 'submit_success' 
// 3. Success notification shows
// 4. Form resets
// All happen sequentially, not in parallel
```
