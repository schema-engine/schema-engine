# Why Form Engine?

Modern web development requires sophisticated form handling capabilities, yet existing solutions often present significant limitations. Each project brings unique requirements for validation, design integration, user experience patterns, and data flow management. Traditional form libraries typically impose rigid architectural constraints that can conflict with project-specific needs.

## Common Challenges

Development teams frequently encounter several recurring issues when implementing form solutions:

- **Limited Validation Flexibility** - Existing validation systems may not accommodate custom business logic or complex validation rules
- **UI Library Integration** - Form libraries often conflict with established design systems or preferred component libraries
- **Advanced Feature Requirements** - Implementing conditional logic, multi-step workflows, or auto-save functionality typically requires extensive custom development
- **Responsive Design Complexity** - Creating forms that work seamlessly across different screen sizes and input methods presents ongoing challenges

These limitations motivated the development of Form Engine as a more adaptable solution.

## The Approach

Form Engine was born from this frustration and refined through real-world use. It's not just another form library—it's a **JSON-driven UI system** that adapts to your needs, not the other way around.

## What Makes It Different?

### Complete Customization
Bring your existing component library. Wrap it with our tools, and it instantly adapts to form schemas while getting all the React Hook Form goodness.

```typescript
// Your existing input component
const MyCustomInput = ({ label, error, ...props }) => (
  <div className="my-custom-style">
    <label>{label}</label>
    <input {...props} />
    {error && <span className="error">{error}</span>}
  </div>
);

// Register with the actual Form Engine registry
import { defaultFormRegistry } from '@/lib/form-engine';

defaultFormRegistry.register({
  name: 'input',
  component: MyCustomInput,
  category: 'input',
  description: 'Custom input field'
});
```

### JSON-Driven Everything
Define complex forms with simple JSON schemas. No more writing repetitive JSX for similar forms.

```json
{
  "id": "contact",
  "title": "Get In Touch",
  "autoGenerateSchema": true,
  "steps": [{
    "id": "details",
    "title": "Contact Details",
    "elements": [
      {
        "type": "input",
        "inputType": "text",
        "id": "name",
        "name": "name", 
        "label": "Full Name",
        "validation": [
          { "type": "required", "message": "Name is required" }
        ]
      },
      {
        "type": "input",
        "inputType": "email", 
        "id": "email",
        "name": "email",
        "label": "Email",
        "validation": [
          { "type": "required", "message": "Email is required" },
          { "type": "email", "message": "Please enter a valid email" }
        ]
      }
    ]
  }],
  "actions": [
    {
      "id": "submit-contact",
      "type": "submit",
      "endpoint": "/api/contact",
      "method": "POST",
      "successMessage": "Thank you for contacting us!"
    }
  ]
}
```

### Registrable Everything
Not just components—actions, validations, layouts. Build your own plugins and solutions that fit your exact needs.

### Zod Integration That Just Works
Type-safe validation that just works. Define your schema once, get validation everywhere.

### Powerful Action System
Perform complex operations at any point in your form lifecycle. Auto-save, analytics tracking, multi-step navigation—all through a pluggable action system.

## Philosophy

Form Engine believes in a few core principles:

**Configuration over Code**: Define what you want, not how to build it. Let the library handle the complexity.

**Composition over Inheritance**: Build complex forms by combining simple, focused components.

**Flexibility over Opinions**: The library should adapt to your patterns, not force you into ours.

**Developer Experience**: If it's frustrating to use, it's wrong. Every API decision prioritizes clarity and ease of use.
