# Configuration

Form Engine uses a declarative, JSON-based configuration system that defines the complete structure, behavior, and appearance of your forms. This approach eliminates imperative form building and ensures consistency across your application.

## Configuration Structure

Every form configuration follows this top-level structure:

```typescript
interface FormConfig {
  id: string;                           // Unique form identifier
  title?: string;                       // Form title
  description?: string;                 // Form description
  steps: FormStep[];                    // Form steps (required)
  actions?: FormActionConfig[];         // Form actions
  grid?: ResponsiveGridConfig;          // Layout configuration
  stepper?: StepperConfig;              // Multi-step configuration
  autoGenerateSchema?: boolean;         // Auto Zod schema generation
  metadata?: FormMetadata;              // Additional metadata
}
```

## Basic Form Example

Here's a minimal form configuration:

```typescript
const basicFormConfig = {
  id: "contact-form",
  title: "Contact Us",
  steps: [
    {
      title: "Contact Information",
      elements: [
        {
          type: "input",
          name: "name",
          label: "Full Name",
          rules: [{ type: "required" }]
        },
        {
          type: "input",
          name: "email",
          label: "Email Address",
          rules:
            { type: "required" },
            { type: "email" }
          ]
        },
        {
          type: "textarea",
          name: "message",
          label: "Message",
          rows: 4,
          rules:
            { type: "required" },
            { type: "minLength", value: 10 }
          ]
        }
      ]
    }
  ]
};
```

## Form Steps

Every form must have at least one step, even for single-page forms:

```typescript
interface FormStep {
  title: string;                        // Step title
  description?: string;                 // Step description
  elements: FieldConfig[];                // Step fields
  grid?: ResponsiveGridConfig;          // Step-specific grid
  constraints?: ConstraintLogic[];      // Step-level constraints
}
```

### Single-Step Forms

For simple forms, use a single step:

```typescript
const simpleForm = {
  id: "newsletter",
  steps: [
    {
      title: "Subscribe",
      elements: [
        {
          type: "input",
          name: "email",
          label: "Email Address",
          rules:ype: "email" }]
        }
      ]
    }
  ]
};
```

### Multi-Step Forms

For complex workflows, use multiple steps:

```typescript
const registrationForm = {
  id: "user-registration",
  title: "Create Account",
  steps: [
    {
      title: "Personal Information",
      elements: [
        { type: "input", name: "firstName", label: "First Name" },
        { type: "input", name: "lastName", label: "Last Name" },
        { type: "date", name: "birthDate", label: "Date of Birth" }
      ]
    },
    {
      title: "Account Details",
      elements: [
        { type: "input", name: "email", label: "Email" },
        { type: "input", name: "password", label: "Password", inputType: "password" },
        { type: "input", name: "confirmPassword", label: "Confirm Password", inputType: "password" }
      ]
    },
    {
      title: "Preferences",
      elements: [
        { type: "checkbox", name: "newsletter", label: "Subscribe to newsletter" },
        { type: "select", name: "theme", label: "Preferred Theme", options: [...] }
      ]
    }
  ]
};
```

## Field Configuration

Each field is configured using a discriminated union based on the field type:

```typescript
type FieldConfig = 
  | InputFieldConfig      // type: "input"
  | SelectFieldConfig     // type: "select"
  | CheckboxFieldConfig   // type: "checkbox"
  | NumberFieldConfig     // type: "number"
  | TextareaFieldConfig   // type: "textarea"
  | RadioFieldConfig      // type: "radio"
  | SwitchFieldConfig     // type: "switch"
  | DateFieldConfig       // type: "date"
  | FileFieldConfig       // type: "file"
  | ArrayFieldConfig;     // type: "array"
```

### Common Field Properties

All field types share these common properties:

```typescript
interface BaseFieldConfig {
  type: string;                         // Field type discriminator
  name: string;                         // Field name (form key)
  label?: string;                       // Field label
  description?: string;                 // Help text
  placeholder?: string;                 // Placeholder text
  defaultValue?: any;                   // Default value
  validation?: ValidationRule[];        // Validation rules
  constraints?: ConstraintLogic[];      // Conditional logic
  grid?: FieldGridConfig;               // Field-specific grid
  className?: string;                   // Custom CSS class
  disabled?: boolean;                   // Disabled state
  readOnly?: boolean;                   // Read-only state
}
```

### Type-Specific Properties

Each field type has additional properties:

```typescript
// Input field
interface InputFieldConfig extends BaseFieldConfig {
  type: "input";
  inputType: "text" | "email" | "password" | "url" | "tel" | "search";
  maxLength?: number;
  minLength?: number;
}

// Select field
interface SelectFieldConfig extends BaseFieldConfig {
  type: "select";
  options: SelectOption[];
  multiple?: boolean;
  searchable?: boolean;
}

// Number field
interface NumberFieldConfig extends BaseFieldConfig {
  type: "number";
  min?: number;
  max?: number;
  step?: number;
  precision?: number;
}
```

## Responsive Grid Configuration

Form Engine provides a powerful CSS Grid-based layout system:

```typescript
interface ResponsiveGridConfig {
  columns?: number | "auto";            // Default columns
  gap?: number | string;                // Grid gap
  responsive?: {                        // Responsive overrides
    sm?: GridBreakpointConfig;
    md?: GridBreakpointConfig;
    lg?: GridBreakpointConfig;
    xl?: GridBreakpointConfig;
    "2xl"?: GridBreakpointConfig;
  };
}
```

### Grid Examples

**Two-column desktop, single column mobile:**

```typescript
const formConfig = {
  id: "responsive-form",
  grid: {
    columns: 1,
    gap: 24,
    responsive: {
      md: {
        columns: 2
      }
    }
  },
  steps: [...]
};
```

**Field-specific grid spans:**

```typescript
const fields = [
  {
    type: "input",
    name: "firstName",
    label: "First Name",
    grid: { colSpan: 1 }
  },
  {
    type: "input",
    name: "lastName", 
    label: "Last Name",
    grid: { colSpan: 1 }
  },
  {
    type: "textarea",
    name: "bio",
    label: "Biography",
    grid: { 
      colSpan: 2,                       // Span full width
      responsive: {
        sm: { colSpan: 1 }              // Single column on mobile
      }
    }
  }
];
```

## Form Actions

Actions define behaviors that occur during form interactions:

```typescript
interface FormActionConfig {
  id: string;                           // Action identifier
  type: string;                         // Action type
  triggers?: ActionTrigger[];           // When to execute
  [key: string]: any;                   // Action-specific config
}
```

### Common Actions

**Form submission:**

```typescript
const submitAction = {
  id: "submit-form",
  type: "submit",
  endpoint: "/api/contact",
  method: "POST",
  successMessage: "Thank you for your message!",
  triggers: ["form_submit"]
};
```

**Auto-save drafts:**

```typescript
const autoSaveAction = {
  id: "auto-save",
  type: "auto_save_draft",

  showNotification: true,
  triggers: ["form_change"]
};
```

**Analytics tracking:**

```typescript
const analyticsAction = {

```

## Validation Configuration

Define validation rules declaratively:

```typescript
interface ValidationRule {
  type: "required" | "email" | "minLength" | "maxLength" | 
        "min" | "max" | "pattern" | "custom";
  value?: any;                          // Rule value (for min, max, etc.)
  message?: string;                     // Custom error message
  validator?: (value: any) => boolean;  // Custom validator function
}
```

### Validation Examples

```typescript
const validationExamples = [
  // Required field
  { type: "required", message: "This field is required" },
  
  // Email validation
  { type: "email", message: "Please enter a valid email" },
  
  // String length
  { type: "minLength", value: 8, message: "Minimum 8 characters" },
  { type: "maxLength", value: 100, message: "Maximum 100 characters" },
  
  // Numeric range
  { type: "min", value: 0, message: "Must be positive" },
  { type: "max", value: 100, message: "Maximum value is 100" },
  
  // Pattern matching
  { 
    type: "pattern", 
    value: "^[A-Z][a-z]+$", 
    message: "Must start with uppercase letter" 
  },
  
  // Custom validation
  {
    type: "custom",
    message: "Password must contain at least one number",
    validator: (value) => /\d/.test(value)
  }
];
```

## Conditional Logic

Show, hide, or modify fields based on form state:

```typescript
interface ConstraintLogic {
  field: string;                        // Field to watch
  operator: ConstraintOperator;         // Comparison operator
  value?: any;                          // Comparison value
  action: ConstraintAction;             // Action to take
}

type ConstraintOperator = 
  | "equals" | "not_equals"
  | "contains" | "not_contains"
  | "greater_than" | "less_than"
  | "is_empty" | "is_not_empty";

type ConstraintAction = 
  | "show" | "hide"
  | "enable" | "disable"
  | "require";
```

### Constraint Examples

```typescript
const conditionalFields = [
  {
    type: "select",
    name: "accountType",
    label: "Account Type",
    options: [
      { value: "personal", label: "Personal" },
      { value: "business", label: "Business" }
    ]
  },
  {
    type: "input",
    name: "businessName",
    label: "Business Name",
    constraints: [
      {
        field: "accountType",
        operator: "equals",
        value: "business",
        action: "show"
      }
    ]
  },
  {
    type: "input",
    name: "taxId",
    label: "Tax ID",
    constraints: [
      {
        field: "accountType",
        operator: "equals",
        value: "business",
        action: "show"
      },
      {
        field: "businessName",
        operator: "is_not_empty",
        action: "require"
      }
    ]
  }
];
```

## TypeScript Integration

Form Engine provides full TypeScript support with automatic type inference:

```typescript
// Type-safe configuration
const typedConfig: FormConfig = {
  id: "typed-form",
  steps: [
    {
      title: "Step 1",
      elements: [
        {
          type: "input",           // TypeScript knows this is InputFieldConfig
          name: "email",
          label: "Email",
          inputType: "email"       // Only valid input types allowed
        }
      ]
    }
  ]
};

// Type-safe form data
interface FormData {
  email: string;
  name: string;
  age: number;
}

const handleSubmit = (data: FormData) => {
  // data is fully typed
  console.log(data.email); // ✅ TypeScript knows this is a string
};
```

## Configuration Best Practices

### 1. Use Descriptive IDs

```typescript
// ❌ Poor
{ id: "form1" }

// ✅ Good  
{ id: "user-registration-form" }
```

### 2. Group Related Fields

```typescript
// ✅ Group related fields in logical steps
const steps = [
  {
    title: "Personal Information",
    elements: [/* personal fields */]
  },
  {
    title: "Contact Details", 
    elements: [/* contact fields */]
  }
];
```

### 3. Provide Clear Labels and Help Text

```typescript
// ✅ Clear, helpful labels
{
  type: "input",
  name: "taxId",
  label: "Tax Identification Number",
  description: "Enter your business tax ID (e.g., 12-3456789)",
  placeholder: "12-3456789"
}
```

### 4. Use Appropriate Validation

```typescript
// ✅ Comprehensive but not excessive validation
{
  type: "input", 
  name: "password",
  rules:
    { type: "required" },
    { type: "minLength", value: 8 },
    { 
      type: "custom",
      message: "Password must contain uppercase, lowercase, and number",
      validator: (value) => /^(?=.*[a-z])(?=.*[A-Z])(?=.*\d)/.test(value)
    }
  ]
}
```

### 5. Organize Configuration Files

```typescript
// src/configs/forms/contact-forms.ts
export const contactFormConfig = { /* ... */ };
export const feedbackFormConfig = { /* ... */ };

// src/configs/forms/registration-forms.ts  
export const userRegistrationConfig = { /* ... */ };
export const vendorRegistrationConfig = { /* ... */ };
```
