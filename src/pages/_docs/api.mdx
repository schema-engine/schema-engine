# API Reference

Complete reference for all Form Engine components, hooks, and types currently implemented.

## Core Components

### FormRenderer

The main component for rendering forms from configuration objects.

```typescript
import { FormRenderer } from "@/lib/form-engine";
import type { FormConfig } from "@/lib/form-engine/types";

interface FormRendererProps {
  config: FormConfig;
  onSubmit?: (data: any) => void | Promise<void>;
  onChange?: (data: any) => void;
  initialValues?: Record<string, any>;
  className?: string;
}

// Basic usage
<FormRenderer
  config={formConfig}
  onSubmit={handleSubmit}
  onChange={handleChange}
  className="my-form"
/>
```

#### Props

| Property | Type | Required | Description |
|----------|------|----------|-------------|
| `config` | `FormConfig` | Yes | Form configuration object defining structure and behavior |
| `onSubmit` | `(data: any) => void \| Promise<void>` | No | Called when form is submitted successfully |
| `onChange` | `(data: any) => void` | No | Called whenever form values change |
| `initialValues` | `Record<string, any>` | No | Default values for form fields |
| `className` | `string` | No | CSS class applied to form container |

## Validation

### ValidationPresets

Pre-built validation rules using Zod schemas.

```typescript
import { ValidationPresets } from "@/lib/form-engine/validation";

// Available presets
ValidationPresets.required(message?: string)
ValidationPresets.email(message?: string)
ValidationPresets.url(message?: string)
ValidationPresets.minLength(length: number, message?: string)
ValidationPresets.maxLength(length: number, message?: string)
ValidationPresets.min(value: number, message?: string)
ValidationPresets.max(value: number, message?: string)
ValidationPresets.regex(pattern: RegExp, message?: string)

// Usage in field config
{
  type: "input",
  name: "email",
  validation: [
    ValidationPresets.required("Email is required"),
    ValidationPresets.email("Please enter a valid email")
  ]

```

## Actions System

### Action Types

Currently implemented action types for form behavior:

#### Submit Action

Handles form submissions to API endpoints.

```typescript
{
  id: "form-submit",
  type: "submit",
  description: "Submit form data",
  endpoint: "/api/submit",
  method: "POST" | "PUT" | "PATCH",
  headers?: Record<string, string>,
  successMessage?: string,
  errorMessage?: string,
  enabled: boolean,
  triggers?: ActionTrigger[]
}
```

#### Reset Action

Resets form to initial or default values.

```typescript
{
  id: "form-reset",
  type: "reset", 
  description: "Reset form",
  enabled: boolean,
  triggers?: ActionTrigger[],
  resetToDefaults?: boolean
}
```

#### Auto Save Action

Automatically saves form progress as draft.

```typescript
{
  id: "auto-save",
  type: "auto_save_draft",
  description: "Auto save form progress",
  mode: "debounced" | "interval",
  debounceMs?: number,
  intervalMs?: number,
  formId: string,
  enabled: boolean,
  showNotification?: boolean
}
```

#### GTM Event Action

Sends events to Google Tag Manager for analytics.

```typescript
{
  id: "analytics-event",
  type: "gtm_event",
  description: "Track form event",
  eventName: string,
  eventData?: Record<string, any>,
  includeFormData?: boolean | string[],
  includeMetadata?: boolean,
  enabled: boolean
}
```

#### Notification Action

Displays user notifications and messages.

```typescript
{
  id: "show-notification",
  type: "notification",
  description: "Show user notification",
  message: string,
  variant: "success" | "error" | "warning" | "info",
  duration?: number,
  enabled: boolean
}
```

### Action Triggers

Events that can trigger action execution:

```typescript
type ActionTrigger =
  | "form_start"      // When form initializes
  | "form_change"     // When any field value changes
  | "form_submit"     // When form submission starts
  | "submit_start"    // When submit process begins
  | "submit_success"  // When submit completes successfully
  | "submit_error"    // When submit fails
  | "submit_complete" // When submit process finishes
  | "step_change"     // When navigating between steps
  | "step_submit"     // When submitting a specific step
  | "step_enter"      // When entering a step
  | "step_leave"      // When leaving a step
  | "step_view"       // When step becomes visible
  | "manual_save"     // When user saves manually
  | "manual_reset";   // When user resets manually
```

## Hooks

### useFormActions

Hook for managing form actions and triggers.

```typescript
import { useFormActions } from "@/lib/form-engine";

const { executeAction, actionHistory } = useFormActions(
  formConfig,
  form,
  currentStep
);
```

#### Parameters

- **config** (`FormConfig`) - Form configuration
- **form** (`UseFormReturn`) - React Hook Form instance
- **currentStep** (`number`) - Current step index

#### Returns

- **executeAction** (`(action: FormAction) => Promise<void>`) - Execute an action
- **actionHistory** (`ActionExecutionResult[]`) - History of executed actions

### useConstraintLogic

Hook for evaluating conditional field logic.

```typescript
import { useConstraintLogic } from "@/lib/form-engine";

const { isVisible, isEnabled, isRequired } = useConstraintLogic(
  constraints,
  formWatch
);
```

#### Parameters

- **constraints** (`ConstraintLogic[]`) - Array of constraint rules
- **formWatch** (`any`) - Form watch function or values

#### Returns

- **isVisible** (`boolean`) - Whether field should be visible
- **isEnabled** (`boolean`) - Whether field should be enabled
- **isRequired** (`boolean`) - Whether field should be required

### useGridLayout

Hook for responsive grid layout management.

```typescript
import { useGridLayout } from "@/lib/form-engine";

const { gridStyles, breakpoint } = useGridLayout(layoutConfig);
```

#### Parameters

- **config** (`GridLayoutConfig`) - Grid layout configuration

#### Returns

- **gridStyles** (`CSSProperties`) - CSS styles for grid container
- **breakpoint** (`Breakpoint`) - Current responsive breakpoint
