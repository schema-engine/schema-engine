# Triggers & Lifecycle

Actions in Form Engine execute based on triggers - events that occur during the form's lifecycle. Understanding triggers is essential for creating coordinated action workflows.

## Action Triggers

### Form Lifecycle
These triggers occur during the basic form lifecycle:

- **`form_start`** - Triggered when the form is initialized
- **`form_change`** - Triggered when any form field value changes
- **`form_submit`** - Triggered when the form submission is initiated

### Submit Lifecycle
The submit process has its own lifecycle with automatic trigger progression:

- **`submit_start`** - Triggered when the submit process begins
- **`submit_success`** - Triggered after a successful submission
- **`submit_error`** - Triggered if the submission fails
- **`submit_complete`** - Triggered after the submission process finishes (success or error)

### Multi-Step Forms
For multi-step forms, additional triggers are available:

- **`step_change`** - Triggered when navigating between steps
- **`step_submit`** - Triggered when submitting a specific step
- **`step_enter`** - Triggered when entering a specific step
- **`step_leave`** - Triggered when leaving a specific step
- **`step_view`** - Triggered when a step becomes visible (useful for analytics)

### Manual Actions
These triggers are fired by explicit user actions:

- **`manual_save`** - Triggered when the user manually saves a draft
- **`manual_reset`** - Triggered when the user manually resets the form

## Execution Flow

### Basic Form Submission Flow

```
User clicks submit
       ↓
  form_submit (triggers submit action)
       ↓
  submit_start (automatic)
       ↓
   [Submit process]
       ↓
submit_success/submit_error (automatic)
       ↓
  submit_complete (automatic)
```

### Multi-Step Form Flow

```
User navigates to step 2
       ↓
   step_leave (step 1)
       ↓
   step_change
       ↓
   step_enter (step 2)
       ↓
   step_view (step 2)
```

## Default Triggers by Plugin

Each plugin has default triggers that determine when it executes:

| Plugin | Default Triggers | Purpose |
|--------|------------------|---------|
| Submit | `form_submit`, `step_submit` | Submit form or step data |
| Notification | `form_submit` | Show immediate feedback |
| Reset | `manual_reset` | Only reset when explicitly requested |
| Auto-Save | `form_change` | Save on every change |
| GTM | `form_submit` | Track submission events |

## Custom Triggers

You can override default triggers for any action:

```typescript
const actions = [
  {
    id: "success-notification",
    type: "show_notification",
    message: "Form submitted successfully!",
    variant: "success",
    triggers: ["submit_success"] // Override default trigger
  },
  {
    id: "auto-save-on-step-change",
    type: "auto_save",
    triggers: ["step_change", "form_change"] // Multiple triggers
  },
  {
    id: "track-form-start",
    type: "gtm_event",
    eventName: "form_interaction_start",
    triggers: ["form_start"] // Track when form loads
  }
];
```

## Sequential Execution

Actions with the same trigger execute sequentially in the order they're defined:

```typescript
const actions = [
  {
    id: "submit-form",
    type: "submit",
    endpoint: "/api/submit"
    // Default trigger: form_submit
  },
  {
    id: "track-success",
    type: "gtm_event",
    eventName: "form_submit_success",
    triggers: ["submit_success"] // Runs AFTER submit succeeds
  },
  {
    id: "show-notification", 
    type: "show_notification",
    message: "Thank you!",
    variant: "success",
    triggers: ["submit_success"] // Runs AFTER tracking
  },
  {
    id: "reset-form",
    type: "reset",
    triggers: ["submit_success"] // Runs AFTER notification
  }
];
```

## Error Handling and Flow Control

If an action returns `shouldContinue: false`, subsequent actions in the same trigger group will not execute:

```typescript
registerAction(submitPlugin({
  validate: (context) => {
    if (!context.isValid) {
      return "Form validation failed";
    }
    return true;
  }
}));

// This notification won't show if submit validation fails
const actions = [
  {
    id: "submit-form",
    type: "submit",
    endpoint: "/api/submit"
  },
  {
    id: "success-notification",
    type: "show_notification", 
    message: "Success!",
    triggers: ["submit_success"]
  }
];
```

## Practical Examples

### Complete Form Workflow

```typescript
const actions = [
  // Track form start
  {
    id: "track-form-start",
    type: "gtm_event",
    eventName: "form_interaction_start",
    triggers: ["form_start"]
  },
  
  // Auto-save as user types
  {
    id: "auto-save",
    type: "auto_save",
    interval: 30000,
    triggers: ["form_change"]
  },
  
  // Submit form
  {
    id: "submit-form",
    type: "submit",
    endpoint: "/api/submit"
  },
  
  // Success flow
  {
    id: "track-success",
    type: "gtm_event", 
    eventName: "form_submit_success",
    triggers: ["submit_success"]
  },
  {
    id: "success-notification",
    type: "show_notification",
    message: "Thank you for your submission!",
    variant: "success", 
    triggers: ["submit_success"]
  },
  {
    id: "reset-form",
    type: "reset",
    triggers: ["submit_success"]
  },
  
  // Error flow
  {
    id: "error-notification",
    type: "show_notification",
    message: "Failed to submit. Please try again.",
    variant: "error",
    triggers: ["submit_error"]
  }
];
```

### Multi-Step Analytics

```typescript
const actions = [
  // Track step views
  {
    id: "track-step-view",
    type: "gtm_event",
    eventName: "form_step_viewed",
    eventData: { step: "{{currentStep}}" },
    triggers: ["step_view"]
  },
  
  // Track step completion
  {
    id: "track-step-complete",
    type: "gtm_event", 
    eventName: "form_step_completed",
    triggers: ["step_submit"]
  },
  
  // Save progress on step change
  {
    id: "save-progress",
    type: "auto_save",
    triggers: ["step_change"]
  }
];
```

## Best Practices

1. **Use specific triggers** - Prefer `submit_success` over `form_submit` for post-submission actions
2. **Order matters** - Place critical actions first in the sequence
3. **Handle errors** - Always provide actions for `submit_error` scenarios
4. **Avoid trigger conflicts** - Don't use conflicting triggers that might cause race conditions
5. **Test sequences** - Verify that your action chains work as expected
