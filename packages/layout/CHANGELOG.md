# @schema-engine/layout

## 0.5.2

### Patch Changes

- [#425](https://github.com/schema-engine/schema-engine/pull/425) [`61750ae`](https://github.com/schema-engine/schema-engine/commit/61750ae1c1739331d93590d4b745cff7847fdbcc) Thanks [@andeeplus](https://github.com/andeeplus)! - A layout theme can measure its breakpoints against the grid's own wrapper instead of the window: `createLayoutTheme({ grid: { query: 'container' } })`. The breakpoint tokens, gap ramps and cascade are the same, so a document is unchanged by it; the stylesheet emits `@container se-grid (min-width: ...)` where it emitted `@media`, and one rule for the new `GRID_CONTAINER_CLASS` (`se-grid-container`), a block with inline-size containment that must wrap each grid, nested grids included. `query` defaults to `'media'`, and a theme without it keeps the stylesheet and the id it had. The two modes are different themes: their ids differ. `NormalizedGridTheme` gains `query`, and `GridQueryMode` is exported. In container mode each grid and item resets its private breakpoint gates in its base rule, so a nested grid below a breakpoint keeps its own layout when the grid around it is above it.

- [#432](https://github.com/schema-engine/schema-engine/pull/432) [`81147d5`](https://github.com/schema-engine/schema-engine/commit/81147d5b685f74ea6aecff1ec9cc803808ec284f) Thanks [@andeeplus](https://github.com/andeeplus)! - An element can size itself in tracks with `grid: { span: n }` (`ElementGridConfig.span`, also in `responsive`), and a grid can pack its items with `autoFlow: 'row' | 'dense'` (`GridLayoutConfig.autoFlow`, top level only). A span compiles to `span min(n, var(--se-grid-track-count, 1))`, so it never passes the tracks the grid has and never makes an implicit column. The grid publishes its track count beside its template as `--se-grid-tracks[-slot]` (`columns: n` gives `n`, named widths 12, `areas` the row length, `columns: 'auto'` one), the stylesheet resolves it through the same gated cascade as the template, so the clamp changes at the width the tracks do in a media theme and in a container theme, and a subgrid inherits its parent's resolved count. `columns: 'auto'` cannot clamp a span in CSS (its track count is not computable), so a span there is one track; give the grid `columns` per breakpoint, with a container theme, instead. The stylesheet grows by about 620 bytes (80 gzipped) in every theme, one more row in the grid rule's property table plus `grid-auto-flow`; existing layouts render the same. New exports `spanPlacementIssue` (a span beside `width`, `offset`, `column` or `area` in one slot) and `gridSpanIssues` (a span under `columns: 'auto'`); a subgrid now also rejects `span`.

    `subgridPlacementIssue` now names `responsive.default` when the conflicting key is written there, instead of the top-level key.

    `columns` must now be a whole positive number or `auto`. A fractional, zero or negative count used to pass validation and produced an invalid `repeat()` in the stylesheet; it is now an issue at `columns`, since it is also the count a `span` is clamped to.

- [#434](https://github.com/schema-engine/schema-engine/pull/434) [`a2a2fc7`](https://github.com/schema-engine/schema-engine/commit/a2a2fc7360c46c2b25c78ed259173434a5ea8ccf) Thanks [@andeeplus](https://github.com/andeeplus)! - Docs and the shipped skill reference only. The README and the skill now say when to use an appearance axis (a look an author picks among 2 to 5) and when to use identity tokens (a value every entity has for itself, such as a colour per machine: the host's own `data-<domain>` attribute and CSS that sets the tokens), and the skill gains a tested card recipe that is not a form, with the split between what a recipe holds (shell, slot config) and what a document holds (slot content). No API changes.

- [#426](https://github.com/schema-engine/schema-engine/pull/426) [`d021fff`](https://github.com/schema-engine/schema-engine/commit/d021fffd529ad3aeb8c90446de76a0d199dfa375) Thanks [@andeeplus](https://github.com/andeeplus)! - An element can lay its children on its parent grid's column tracks and gap with `grid: { subgrid: true }` (`ElementGridConfig.subgrid`, top level only, never in `responsive`). It spans its parent's full row, so it takes no `width`, `offset`, `column`, `area`, `justifySelf` or `placeSelf`. The stylesheet gains three rules for the new `GRID_SUBGRID_CLASS` (`se-subgrid`) in both query modes, which add about 360 bytes to every theme, since a theme cannot know which documents will use them: a box becomes a column subgrid on the parent's gap, a child that is not an item spans the row, and an inner `se-grid` takes the parent's template, gap and default column. `getGridItemVariables` emits the full-row placement. New exports `GRID_SUBGRID_CLASS`, `elementIsSubgrid` and `subgridPlacementIssue`; a domain passes the children of its subgrids among the items it gives `getGridVariables`.

- [#429](https://github.com/schema-engine/schema-engine/pull/429) [`46a3f34`](https://github.com/schema-engine/schema-engine/commit/46a3f34fc66d99468d776c98e0352274c41bed75) Thanks [@andeeplus](https://github.com/andeeplus)! - The slot schemas of a recipe spec can be any Standard Schema that validates synchronously: Zod Mini, Valibot or one you write with `standardSchema`. `defineProtocolRecipeSpec` and `defineRecipeSpec` build the view schema themselves, so a spec no longer needs `zod/mini`. A recipe registration carries the slot schemas as `slotSchemas`, and `createRecipeRegistry` (so `createFormEngine`) throws when they do not list exactly the recipe's `slots`, or one is not a Standard Schema. `bindRecipe`, `readSlotConfig`, `getSlotConfig`, `defineFormRecipe`, `defineRecipe` (React and Radiant), `useViewConfig` and `RadiantRecipePayload` take any Standard Schema instead of a Zod one. Specs with Zod Mini slot schemas need no change: the same call gives the same types for `view`, `slotDefaults` and `getSlotConfig`, and the same JSON Schema. In the JSON Schema export, a Zod slot is exported in full, a slot that provides Standard JSON Schema (`~standard.jsonSchema`) is exported as what it returns, and any other slot (Valibot, or a hand-written one without `jsonSchema`) is listed as an open object (`additionalProperties: {}`) with the `appearance` values the recipe declares for it. `@schema-engine/forms-react` and `@schema-engine/forms-radiant` now depend on `@standard-schema/spec` for these types.

    Breaking, and shipped as a patch while the packages have no users outside this repository:

    - `spec.schema` and `recipe.schema` are no longer Zod schemas, so `.parse`, `.safeParse`, `.shape` and passing them to `z.toJSONSchema`, `z.extend` or `z.safeExtend` fail. Validate with `safeParseStandardSchema(spec.schema, view)` from `@schema-engine/registry` (or `safeParseNode`), get a JSON Schema from the forms engine (`describeRecipe`, `generateJSONSchemaCollection`), and compose from `spec.slotSchemas`.
    - `RecipeViewSchema<TType, TSlots>` is now a `StandardSchemaV1<Input, Output>`, not a `ZodMiniObject`. Read its types with `StandardSchemaV1.InferInput` and `InferOutput`.
    - `appearanceAxes` on a slot whose schema input has no `appearance` key is a compile error, for every slot schema and not only strict Zod objects. A non-strict `z.object` slot without an `appearance` key used to pass, because it dropped the key instead of rejecting it; it now fails to compile. The runtime check that probed the schema for the key is gone, since Standard Schema reports no issue codes to probe with, and `resolveRecipeView` removes `appearance` before the slot schema parses. A spec cast past the types now fails only at compile time. Migration: add `appearance: z.optional(AppearanceConfigSchema)` (or the library's equivalent) to the slot schema, or use a loose object; a hand-written slot states its input type with `standardSchema<TOutput, TInput>`.
    - Messages changed. A key the recipe does not declare is an issue at that key (`Recipe 'x' does not accept view key 'y'. Allowed: ...`) and not an `unrecognized_keys` issue at the view. A bad `slotDefaults` entry reads `slotDefaults.<slot> is invalid: <path>: <message>`, with the message of the slot library and the offending key in the path (an unknown key a library reports on the object, as Zod does, is named at the key).
